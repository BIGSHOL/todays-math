### 고등의 함정을 어떻게 피했나

고등의 `unit.grade` 는 **학년이 아니라 과목명**이다. 그래서 학년은 **학년 → 허용 과목 집합**으로 풀었다.

- 초N → {초N} · 중N → {중N} (1:1)
- **고1 → {공통수학1, 공통수학2}** (학년만으로는 못 좁힘)
- **고2·고3 → {대수, 미적분1, 미적분2, 확률과 통계, 기하}** (선택과목)

그 위에 과목 표기로 1:1 로 좁힌다(수상·공수1→공통수학1 / 수하·공수2→공통수학2 / 수1→대수 /
수2→미적분1 / 미적분→미적분2 / 확통→확률과 통계 / 기하→기하 / 수학→{중1,중2,중3}).
`고1 ≠ 공통수학1` 로 셌다면 **경로 학년이 고1인 6,128행이 통째로** 거짓 경보가 됐을 것이다
(브리프는 폴더 표기만으로 4,026건 = 16%로 셌다. 파일명 대괄호까지 합치면 6,128행이다).

**`공수` 는 1·2 를 안 적은 표기라 좁히지 않았다**(25건, 편4241). 적재기는 이걸 `공수1` 로 단정해
DB `subject` 에 넣었지만, 우리가 그렇게 단정하면 그 편의 공통수학2 배정이 전부 거짓 경보가 된다.

## 6. 규칙을 견준 기록 — **같은 경고 건수로 맞춰서**

`고1 → {공통수학1, 공통수학2}` 를 더 좁힐 후보가 하나 있었다: **파일명의 학기 토큰**
(`[25-1-기말]` → 1학기 → 공통수학1). 층 A 를 메타만으로 갈라 줄 유일한 규칙이라 유혹적이었다.

같은 행 집합(고1·고2, 학기 토큰 있는 행)에서 견주니:

| | 건수 |
|---|---:|
| 기존 규칙이 못 잡던 것을 **새로 잡음** | 20 |
| **과목 표기가 그 배정을 뒷받침하는데도 경보** | **1,430행 / 82편** |

정밀도 20/1,450 = **1.4%**. 이유는 실물을 보면 바로 나온다 —
`[이서고][1][공수2][25-1-기말]`(1학기에 공통수학2를 가르침, 18행 전량),
`[…][2][확통][25-1-…]`(1학기 확통 669행), `[…][2][수2][…-2-…]`(2학기 미적분1 740행).
**학기와 과목의 대응은 학교마다 다르다.** → **기각.** 스크립트가 이 두 숫자를 매 실행마다 다시 찍는다
(`규칙비교_학기토큰`). 문턱을 옮기는 대신 열쇠를 바꿔 **편 다수결**을 셋째 근거로 썼고,
그 편 다수결이 층 A 의 2건을 실제로 잡았다.

## 7. 손상 입력 시험 (`--self-test`, 25가지 전부 통과)

판정 코드는 **정상 입력만 보면 전부 초록**이다. 그래서 손상부터 넣었다.

빈 문자열 · `null` · `undefined` · 숫자 · 공백만 · 파일명 없는 경로 · 대괄호 없음 · 빈 대괄호 ·
닫히지 않은 대괄호 · **학년 두 자리(`[12]`)** · 학년 `0` · 학년 자리에 과목 · **토큰 한가운데 공백**
(`고 1`, `[ 화원고 ]`, `[ 확 통 ]`) · 슬래시 경로 · 중복 구분자 · 학교급 없는 학교명 ·
**과목이 넷째 칸** · 학년 폴더 중복 · 학교명 중간에 「고」(`고성중`) — 전부 예외 없이 보류/정상 처리.

판정 단계도 따로: 메타 전무 + `manual`(보류) / 메타 전무 + `past_exam`(판정) / `unit` 없음 /
`subject` 컬럼이 쓰레기 문자열.

## 9. 곁다리로 드러난 **별개의 데이터 결함**

1. **`transformed` 4,862건 전량 `originProblemId` = NULL — 이것은 결함이 아니었다.**
   (2026-08-18 정정) `source=transformed` 는 **RPM 교재 이관본**이다(`src/lib/import/convertRpm.ts` 가 그 값을 쓴다). 교재 문항은 **우리 DB 에 원본이 없으므로**
   NULL 이 맞다. 적재가 링크를 빠뜨린 게 아니다 — 그래서 「이관 파이프라인 수정 대상」이라는
   위 진단은 틀렸고, 물려받을 단원 근거도 애초에 존재하지 않는다.
   진짜 문제는 **같은 값에 AI 변형본도 들어온다**는 것이다(`ai/transformer.ts:132`).
   둘을 가르는 유일한 값이 `originProblemId` 다 → **D-51**. 이걸 안 보고 `source` 만 보던
   `composePredictedPaper.ts` 가 RPM 4,862건을 한 등급 밀어내고 있었다(2026-08-18 수정).
2. **`subject` 컬럼이 43행에서 NULL 인데 파일명에는 과목이 적혀 있다.**
   적재기가 셋째 대괄호만 봤는데 `[화원고][2][25-2-기말][확통][미래엔]` 처럼 넷째 칸에 적힌 편이 있다.
   이 감사는 전 대괄호를 훑어 43행을 주워 담았다.
3. **`[공수]`(1·2 미표기) 25행을 적재기가 `공수1` 로 단정**했다. 편4241 은 실제로 전량 공통수학1
   배정이라 결과는 맞았지만, 단정 자체는 근거가 없다.
