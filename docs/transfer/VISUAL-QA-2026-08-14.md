픽셀 검사에서 축/점/선분/접선/각도호·각 라벨/화살표/곡선/원/좌표평면,

한글/수학 라벨을 확인했다. 100%, 좁은 폭, print에서 잘림이나 충돌은 없었다.

OCR 비교는 다음 기존 자산을 사용했다.

- 원본: `corpus\[경원고][2][기하][25-2-중간] (원본)\pages\p3.png`

재호출하지 않았다.

## 발견하고 수정한 결함

1. Windows 원본 경로의 `\[`를 LaTeX 명령으로 세던 허위 양성을 제거했다.
2. `$` 없는 `\bigstar`, `\underbrace`가 raw fallback으로 내려가던 trigger 누락을
   보완했다.
3. 한 줄에 한 수식만 보호해 뒤의 `\subset`, `\notin` 등이 보이던 전처리를
   여러 수식 구간 반복 처리로 바꿨다.
4. `\{...\}`로 시작하는 구간에서 선행 backslash가 남아 `\$...$`가 보이던
   one-character command 경계를 수정했다.
5. Unicode `√` 하나를 인자 없는 `\sqrt`로 바꿔 fallback하던 인벤토리 셀은
   plain `MathText` glyph로 표시하고, 실제 수학 문맥에서 별도 지원을 검증했다.
6. 실제 OCR 텍스트의 `y=x^2+2px+q`, `p+q`, `f^{-1}`가 caret 평문으로 보이던
   문제를 import 정규화와 프로덕션 전처리 양쪽에서 보수적으로 감쌌다.

수정 후 같은 4모드 캡처와 전수 DOM 검사를 다시 실행해 모두 통과했다.

## 사람이 계속 확인해야 할 예외

일부 코퍼스 원문은 이미 OCR 단계에서 분수 괄호가 잘렸거나 토큰이 붙어 있다.
예를 들어 집합 기호가 연속으로 붙고 분수의 분모가 유실된 문자열, 시험지 전체
text layer가 한 필드에 붙은 문자열이 있다. 렌더러는 이를 raw 명령 없이 표시할
수는 있지만 원래 수학 의미를 복원할 수 없다. 이는 미분류 4,618건과 그림 보류
986건을 자동 적재하지 말고 사람이 원본과 대조해야 하는 이유다.

또한 OCR figure의 자연어 설명에서 만든 샘플 SVG는 엔진 경계와 sanitize/render를
검증하는 결정론적 QA 해석이지, 원본 도형의 수학적 좌표를 자동 복원한 결과는
아니다. 좌표 기반 figure reconstruction 계약은 별도 승인이 필요한 후속 범위다.
