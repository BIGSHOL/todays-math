# 시험지변환기 자산 이전 감사 — 2026-08-14

## 결론

OCR 문제 DB는 오늘의수학 대상 DB로 이전되지 않았다. 대상 DB를 `SET
TRANSACTION READ ONLY` 트랜잭션으로 직접 조회한 결과 `problem`은 8건 모두
`manual`이고 `past_exam`은 0건이었다. 현재 변환 규칙으로 적재 가능한 OCR
3,569건과 안정적 내용 지문을 대조한 매칭도 0건이다. 이 감사에서는 DB를 쓰거나
마이그레이션하지 않았다.

## 재현 명령

Prisma client 생성물이 없는 새 worktree에서는 먼저 다음을 실행한다.

```powershell
npm run db:generate
npm run transfer:audit -- `
  --source-dir "F:\시험지변환기\db\ocr_pilot" `
  --db-env-file "C:\Creative\testautocreator\.env" `
  --out "$env:TEMP\todays-math-transfer-audit.json"
```

감사기는 env 파일의 값이나 연결 URL을 출력하지 않는다. DB 조회는 트랜잭션 첫
문장으로 `SET TRANSACTION READ ONLY`를 실행한다. `--db-env-file`도
`DATABASE_URL`도 없으면 DB 부분은 exit 2와 함께 다음 이유로 재현 가능하게
종료한다.

```text
DATABASE_URL이 없고 --db-env-file도 지정되지 않았습니다.
```

초기 worktree에는 `.env`가 없었고 Docker Desktop 엔진도 실행 중이 아니었다.
공유 대상은 위의 별도 env 파일에서 확인했으며 URL/암호는 기록하지 않았다.

현행 `problem` provenance 관련 열은 `source`, `origin_problem_id`뿐이다.
`external_id`, `content_hash`, 원본 파일/문항 메타데이터 열은 없다. 따라서 현재
스키마만으로는 재실행 가능한 멱등 이전이나 원본 단위 추적을 보장할 수 없다.

## 쓰기 전 승인·백업·검증 절차

현재 `scripts/import/load-classified.ts`는 로컬 DB만 허용하며, 공유 Supabase에는
쓰지 않는 것이 정상이다. 또한 이 감사에서 발견한 기존 dry-run 결함 때문에
`ocr-classified.json`이 과거에는 생성되지 않았고, 현행 loader는 external ID와
내용 지문을 저장하지 않는다. 따라서 현재 loader를 운영 DB에 우회 실행하면 안
된다.

운영 쓰기는 다음 별도 변경과 사용자 승인이 모두 있어야 한다.

1. Supabase의 provider snapshot/PITR을 만들고 별도 임시 DB에 복원 시험한다.
   CLI 백업을 쓸 경우 암호를 명령행에 직접 쓰지 말고 `PGSERVICE`/보호된 자격증명
   파일을 사용해 `pg_dump --format=custom --no-owner --no-acl --file <backup>`을
   실행한다.
2. `problem`에 최소 `external_source_id`, `content_hash`, `source_metadata`를
   추가하고 `(source, external_source_id)` 고유 제약을 둔다. 마이그레이션 SQL을
   먼저 검토한다.
3. 명시적 `--apply`와 대상 확인 문자열 없이는 쓰지 않는 멱등 loader를 만든다.
   신규 문항은 `review_status=pending`으로 유지한다.
4. 운영 복제/임시 DB에서 3,569 external ID, 3,568 고유 내용 지문, 0개 미매칭을
   확인한다. 중복 지문 1쌍의 유지/병합 정책을 승인한다.
5. 승인된 maintenance window에 백업 식별자를 기록한 뒤 한 트랜잭션 또는 재개
   가능한 작은 batch로 적재한다.
6. 이 감사 명령을 다시 read-only로 실행해 기대한 매칭 수, 출처별 건수, 샘플
   ID/지문을 대조하고, 실패 시 복원한다.

미분류 4,618건, 그림 포함 986건, 답 파일이 없는 3개 시험지는 이 쓰기 범위에
자동 포함하지 않는다. 별도 분류·검수 승인이 필요하다.
