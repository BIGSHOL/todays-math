# 벡터 SVG 채택 — **눈으로 보는 검수** (워크트리 `그림벡터검수` / 브랜치 `feat/figure-svg-verify`)

> 원장님 지시 2026-08-20: 「설계 이상없으면 벡터 건 승인」.
> 설계 검증은 끝났다. **남은 것은 수치 검사가 구조적으로 못 보는 것 하나뿐이다.**

## 0. 왜 너에게 맡기나

이 저장소는 그림을 눈으로 안 보고 지표만 믿다가 **여러 번 데였다**:

- 겹쳐 보기가 `℃` 를 `¾` 로 바꾼 것을 0.027 로 통과시켰다.
- 앤티앨리어싱을 획 손실로 세어 **멀쩡한 그림 242장을 버렸다.**
- `<use>` 의 stroke-width 가 ×9 로 부푼 것을 0.0250 으로 통과시켰다.
- 오려낸 37장 중 **14장이 결함**이었는데, 커밋 전 표본 12장은 전부 깨끗해 보였다.

**세 번 다 눈으로 봐서만 나왔다.** 그리고 클로드는 이미지를 볼 수 없다.
그래서 이 일은 네 몫이다 (원장님 2026-08-19: 「이미지 처리해야하는건 클로드가
불가능하니까 grok에게 맡겨야해」).

## 1. 지금 상황 — 무엇이 이미 끝났나

`public/figures-svg/` 에 벡터 SVG **2,467장**이 있다(기출 888 · RPM 1,579).
문항의 `figureUrls` 를 이 `.svg` 경로로 **바꿀지** 정하는 중이다.

수치로 이미 확인한 것 (이걸 다시 하지 마라 — 토큰 낭비다):

| 확인한 것 | 결과 |
| --- | --- |
| 전환 가능 문항 (전 그림 SVG + 전 자리 mm + 비율 일치) | **1,415** (출제 가능 1,328) |
| 실릴 SVG | 1,461장 · 62.1MB |
| **비율이 래스터와 어긋나 막힌 자리** | **167** (거의 전부 RPM · 최대 66% 차이) |
| 넘침 판정이 바뀌는 문항 | **0** — 지면이 한 자리도 안 움직인다 |
| 흰 배경 사각형이 있는 SVG | 1장 (나머지는 투명 — 종이색 위에 그대로 앉는다) |

## 2. 🔴 네가 답할 질문 — **딱 하나다**

> **SVG 가 원본 그림을 충실히 담고 있나?**

수치 검사가 **구조적으로 못 보는** 부류를 찾아라:

- 획이 **빠졌다** (선분 하나, 화살표 머리, 눈금, 해칭)
- 글자가 **빠졌거나 깨졌다** (꼭짓점 이름 A·B·C, 치수 `16 cm`, 축 이름, 각도 기호)
- 선 굵기가 **부풀거나 사라졌다** (`<use>` · `stroke-width` 문제 전례)
- **잘렸다** — 테두리 밖으로 나간 부분이 있다
- 채움·해칭이 **까맣게 뭉갰다**
- **전혀 다른 그림**이다

⚠️ **테두리(bbox)가 맞아도 안이 틀릴 수 있다.** 비율 대조는 이미 통과한
1,415문항이 대상이다 — 그러니 「비율이 맞으니 괜찮다」는 **이미 아는 것**이고
네가 답할 것이 아니다.

## 3. 어떻게

1. **전량이 원칙이다** (1,461장). 못 하겠으면 **몇 장 봤는지 반드시 적어라** —
   「N장 확인」은 N 이 전부인지 말해 주지 않는다. 표본이면 **무작위**로 뽑고
   그 사실을 적어라. 「깨끗해 보이는 것부터」 보면 아무것도 못 찾는다.
2. SVG 와 **같은 문항의 래스터**(`public/figures/…`)를 나란히 렌더해서 견줘라.
   래스터가 정본이다(원본 시험지에서 오려 낸 것).
3. 결함을 찾으면 **파일 경로와 무엇이 어떻게 다른지**를 적어라.
   고치려 들지 마라 — **판정만** 한다.
4. **기출(888)과 RPM(1,579)을 갈라 세라.** 앞 트랙이 「기출 벡터는 대부분
   표·상자이지 도형이 아니다」라고 했다. 부류마다 결함률이 다를 수 있다.
5. 🔴 **반대쪽도 봐라** — 비율이 어긋나 **막힌 167자리** 중 20장쯤 열어 보고,
   정말 SVG 가 틀린 것인지 **아니면 래스터 쪽이 틀린 것인지** 말해 달라.
   (그 답에 따라 그 167을 되살릴 수도 있고, 반대로 래스터를 고쳐야 할 수도 있다.)
