# 트랙 A — RPM **본문이 말하는 자리**로 발문과 그림을 가른다 (62건)

작성 2026-08-19 · 원장님 지시 「남은 242건 처리 계획」 → A·B 먼저

## 0. 무엇을 하는가

RPM 그림 유실 **203건** 중, 오려내기가 「**칸에 발문이 N자 들어왔다**」로 버린
**62건**(관문 통과분 37 + 무리 계획 25)을 되찾는다.

## 1. 🔴 앞 트랙의 진단이 틀렸다 — 얽힌 게 아니다

`rpm-figure-rescue.md` §4.2 는 이 부류를 「그림과 발문이 붙어 있어 못 가른다」로 보고
**발문 줄을 흰 사각형으로 덮고 오리기**를 다음 수로 적었다. 그런데 네 건을 지면에서
떠서 눈으로 보니 **깨끗이 갈린다** — 발문·보기가 왼쪽, 그림이 오른쪽이다. 덮을 필요가
없다. (표본: `019fd1d7-783b` p.35 · `7a78` p.36 · `9793` p.49 · `9c9d` p.51.
앞의 셋은 세로로, 마지막 하나는 가로로 갈린다.)

## 2. 열쇠 — **책이 스스로 적어 둔 구조**

발문이 그림의 자리를 말해 준다. 38건(관문 통과분) 전수로 셌다:

| | 건수 |
|---|---:|
| 「**오른쪽** 그림」·「우측 그림」 → 세로로 가른다 | **31** |
| 「아래 그림」·「다음 그림」 → 가로로 가른다 | **7** |
| 못 가르는 것 | **0** |

문턱을 고르는 게 아니라 **본문을 읽는** 것이다. 2026-08-19 에 15건을 되찾은
「오른쪽 그림」 폴백(`--widen-fallback`)과 같은 부류이고, 무리 그림을 되찾은
`[0004~0006]` 표시와도 같은 부류다.

## 3. 반드시 지킬 것

1. **폴백이지 넓힘이 아니다.** 이미 성공한 것에 같은 규칙을 대면 안 된다 —
   실측으로 넓힘을 전체에 걸면 **130건이 망가진다**(좌표 달라짐 94 · 못 찾게 됨 36).
   실패한 것에만 대라. 그리고 오려낸 **전 장의 md5 를 전후 대조**해 실제로 0인 것을
   보여라(2026-08-19 에 1,703장으로 그렇게 확인했다).
2. **전량 육안.** 18건 중 3건이 나빴다 — 옆 문항 통째 삼킴 · 번호 배지만 · 잘림.
   **그중 하나는 눈으로만 잡혔다**(정답 28=C(8,2) 가 공장 8개를 요구하는데 5개뿐).
3. **새 가드는 무엇을 깎는지부터 세라.** 그리고 **망가뜨려 빨개지는 것을 확인**하라.
4. **D-20** — 붙이기 전에 무엇을 잃는지 센다. 붙일 대상만 추린 결과 파일을 쓴다
   (전체를 붙이면 이미 붙은 행의 값을 건드린다).
5. **되돌리기 원장은 커밋되는지 `git check-ignore -q` 로 확인**하고,
   `mergeLedgerRows` 로 **이어 쓴다**(덮어쓰면 앞서 붙인 것을 되돌릴 근거가 사라진다 —
   2026-08-19 에 실제로 149행이 한 번에 날아갈 뻔했다).

## 4. 쓸 것

```bash
# 지금 실패 사유
python scripts/figure/crop-rpm-from-pdf.py \
       --plan scripts/qa/reports/rpm-crop-plan-gated.json \
       --out  scripts/qa/reports/rpm-crop-result.json --widen-fallback
```

`figure_rect` 는 이미 손봐 뒀다 — `clip_images` 가 기본으로 켜져 있어
「겹침이 모자라 후보에서 빠진 이미지」도 «자르지 마라» 검사에 들어간다.

## 5. 안 할 것

- **15개정 교재는 쓰지 않는다** (원장님 지시 2026-08-19). 22개정만.
- `thin_pt` 를 켜지 마라 — 실측으로 **47건 중 0건을 얻고** 이미 회수한 52건의 좌표를
  망친다.
- `directUseAllowed` 는 다른 원장 소관이다. 회수한 것의 잠금 해제는
  `apply-missing-figure-lock.ts --revert --recovered` 하나로만.
