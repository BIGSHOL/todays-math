## 2. 자동 회수 97건 — **맞다**

브리프의 물음은 「짝이 있다」가 아니라 **「짝이 맞다」**였다. 넷으로 물었다.

### 2.1 검수 시트는 **동어반복이 아니다** (판정: 통과)

`shot-choice-figure-pairs.py` 는 **원본 PDF 지면을 그대로 픽셀로 오려** 놓고 그 위에
되찾은 번호를 빨간 상자로 얹는다. 지면에는 **인쇄된 ①②③④⑤ 가 이미 찍혀 있고**,
그 검은 글자는 회수기가 만든 것이 **아니다** — 원본 파일의 내용이다.
즉 채점자(지면)와 피채점자(빨간 번호)의 출처가 다르다. **동어반복이 아니다.**

빨간 라벨은 그림 상자의 **왼쪽 위 안쪽**에 그려지고 인쇄된 마커는 그림 **바깥 왼쪽**에
있어 가리지도 않는다 (실물 확인).

> **다만 시트에 구조적 사각지대가 있다** — `render_one()` 은 `figs[0]["page"]` **한 쪽**만,
> 그것도 **반쪽 폭**만 오려 그린다. 다른 쪽·다른 단의 그림은 **말없이 안 그려진다.**
> 그래서 「전량 육안 확인」이 전량이 아닐 수 있다.
> **세어 봤다: 97건 중 «시트에 안 그려진 DB 그림이 있는 문항» 은 0건이다** (§2.4).
> 오늘 데이터에서는 안 물었다. 코드에는 남아 있으니 앞으로 들어올 문항에는 물 수 있다.

### 2.3 🔑 **다른 알고리즘으로 다시 짝지어 97/97 일치**

시트를 눈으로 보는 것만으로는 「내가 만든 사람과 같은 실수를 하지 않았다」를 못 세운다.
그래서 **회수기의 규칙을 하나도 안 쓰는** 짝짓기를 따로 짰다
(`probe-independent-match.py`):

- 단(column) 개념 **없음** · 읽기 순서 **없음** · 줄 묶기 **없음**
- 「같은 줄이 바로 위를 이긴다」 같은 **등급 없음**
- 마커도 `page_markers()` 를 안 쓰고 쪽을 직접 훑는다
- 대신 **전역 최소비용 배정** — 마커 n개를 그림 n장에 붙이는 **모든 순열** 중 거리 합이
  가장 작은 것 (탐욕 대 전역, 알고리즘 부류가 다르다)

```
전역 최소비용 배정으로 다시 짝지음
  일치        97
  어긋남       0
  못 잼        0
```

### 2.4 「①과 ②가 뒤바뀐 경우를 잡을 수 있는가」 — **잡는다** (실측)

먼저 **구조를 정확히 적는다.** 보고서는 「열쇠 둘(순서·기하)이 어긋나면 사람확인」이라
했는데, `choice_run()` 은 **언제나 `[1,2,…,k]` 를 돌려준다**(1부터 1씩 잇는 가장 긴 연속을
고르므로). 그래서 마지막 대조

```python
[key_geom[f["i"]] for f in choice_figs] != [m["n"] for m in marks]
```

는 사실상 **「기하 배정을 그림 읽기 순서로 늘어놓으면 1,2,3,…,n 인가」** 하나다.
**열쇠가 둘이 아니라 «하나 + 불변식(전단사·단조)»** 이다 — 보고서의 표현은 과장이다.

그러면 그 불변식이 뒤바뀜을 실제로 잡는가. **일부러 뒤바꿔 봤다**
(`probe-swap-detection.py`):

| 변이 | «자동» 이 살아남은 수 | 자동인데 짝이 달라진 수 |
| --- | ---: | ---: |
| 없음 (기준) | 97 / 97 | 0 |
| ㉠ 기하 배정에서 **①↔② 맞바꿈** | **0 / 97** | 0 |
| ㉡ 배정을 **한 칸 돌림**(①→②→…→⑤→①) | **0 / 97** | 0 |
| ㉢ 그림 **읽기 순서 뒤집기** | **0 / 97** | 0 |

**뒤바뀐 짝은 «자동» 으로 살아남지 못한다.** 그리고 「자동인데 짝만 달라진」 경우가
0 이라는 것이 중요하다 — 변이가 **다른 그럴듯한 답**을 만들어 통과하는 일이 없다.

### 2.5 체계적으로 실패하는 지면이 섞였는가 — **안 섞였다**

브리프가 지목한 넷을 97건에 대해 **전량** 셌다 (`probe-page-census.py`, DB 가 실제로
갖고 있는 그림만 대상):

| | 건수 |
| --- | ---: |
| 회전된 쪽 | **0 / 97** |
| 그림이 여러 쪽에 걸침 | **0 / 97** |
| 그림이 두 단에 걸침 | **0 / 97** |
| 그림끼리 겹침 | **0 / 97** |
| 세로로 긴 보기 그림 | 3 / 97 |
| 검수 시트에 안 그려진 그림이 있는 문항 | **0 / 97** |

세로로 긴 3건(`b6378ee9`·`beff02e9`·`e8b52a39`)은 판정이 **실제로 거꾸로 걸렸던** 부류라
따로 봤다 — `b6378ee9` 는 시트로 확인했고 맞다(§2.2), 나머지 둘은 §2.3 의 독립 배정이
일치한다.

### 2.6 본문 밖 열쇠 하나 더 — **기록된 정답**

지면과 무관한 증거로 한 번 더 물었다: 「되찾은 보기 번호의 범위 안에 기록된 정답이
들어가는가」.

```
자동 97건 · 정답이 되찾은 보기 범위 안 : 97
  범위 밖(반증)                        : 0
  정답이 보기 번호가 아님              : 0
```

**97건 전량이 객관식이고 정답이 범위 안이다.** (이 사실은 §3 에서 결정적으로 쓰인다.)

### 2.7 §2 결론

> **자동 회수 97건은 맞다.** 눈(10건) · 독립 알고리즘(97/97) · 뒤바꿈 변이(0/97 생존) ·

## 3. 🔴 43건은 43건이 **아니다** — 29건이다

### 3.1 무엇이 잘못됐나 — **433 사고와 같은 오독이 한 겹 아래 남아 있었다**

첫 판은 무리(`보기그림`/`미분류`/`반대쪽`)를 안 걸러 **43 이 433** 이 됐다. 무리 필터를
넣어 좁혔다. 그런데 **`보기그림` 무리 «자체»가 판정용으로 넓게 잡은 모집단이다.**

그 무리를 잡는 열쇠 중 ㉯ 는 앞 자에서 물려받은 **한 방향 문턱**이다:

```ts
export function keyMissingFive(f: ChoiceFigureFeatures): boolean {
  return f.nFig >= 4 && f.nFilled < 5;          // 그림 4장 이상 + 글자 보기가 다섯이 아님
}
```

이 문턱은 **「그림이 넷 이상 붙은 서술형」을 전부 빨아들인다.** 서술형에는
「어느 그림이 ①인가」라는 물음 **자체가 성립하지 않는다.** 그래서 그런 행의 «불가» 는
「못 쓰는 문항」이 아니라 **「이 경로의 문항이 아니다」**다 — **433 사고와 똑같은 말이
한 겹 아래에서 반복된다.**

## 4. 잠금 방식 — 작동한다. 다만 한계가 있다

### 4.1 출제 풀을 거르는 곳은 **둘**이고, 둘 다 이 값을 본다

브리프가 물었다: `findEligibleProblems` 말고 다른 곳이 있는가. **있다.**

| 어디 | `directUseAllowed: true` 를 보는가 |
| --- | :-: |
| `src/lib/findEligibleProblems.ts:74` | ✅ |
| `src/lib/predictor/generatePredictedPaper.ts:326` (**규칙을 복사해 갖고 있다**) | ✅ |
| `src/lib/generator/selectProblems.ts:101` (`p.directUseAllowed !== false`) | ✅ |
| `/api/problems` (문제은행 목록) | ❌ — **의도한 것**. 잠긴 문항도 은행에는 보인다(영구 삭제가 아니다) |

**잠금은 두 출제 경로 모두에 먹는다.** 다만 예측 시험지 쪽이 **규칙을 복사**해 갖고 있는
것은 이 트랙 밖의 선행 위험이다(둘이 갈라지면 아무도 모른다).

### 4.2 두 잠금은 **오늘은** 안 겹친다

```
discard lock 29 · missing-figure lock 446 · 겹침 0
mitigation-ledger(158) 과도 겹침 0
```

### 4.3 ⚠️ 그러나 공유 boolean 한 칸에 잠금이 **넷**이고, **이미 어긋나 있다**

`direct_use_allowed` 를 쓰는 원장이 넷이다 — 그림 유실 · 단원 감사 완화 ·
단원 감사 보류 종결(이건 **`true` 로 되돌린다**) · 이번 것.

**실측:**

```
그림 유실 원장 446행 · 지금도 잠김 441 · 누가 풀었음 5
DB 전체에서 false 인 행 442
```

**원장과 DB 가 이미 5행 어긋나 있다.** 이건 이 트랙이 만든 문제가 아니지만,
「되돌릴 때는 **지금 값이 우리가 쓴 값(false)일 때만** 되돌린다 — 남의 변경을 안 덮는다」는
주장의 한계를 정확히 보여 준다:

> **`false` 는 «우리가 썼다»는 뜻이 아니다.** 누가 잠갔는지는 그 값에 안 적혀 있다.
> A 가 잠근 뒤 B 가 같은 행을 잠그면(또는 B 의 계획에 들어 있으면), **A 의 되돌리기가
> B 의 잠금을 푼다.**

이 트랙은 (ㄱ) 계획 시점에 상대 원장을 읽어 겹치면 안 잠그고, (ㄴ) 되돌릴 때 값을 확인해
**대부분의 경우를 막는다.** 남는 구멍은 **계획과 쓰기 사이**의 창이었다 — 그건 ⓓ 로 고쳤다.

### 4.4 ⓓ 고침 — 계획과 쓴 행이 다르면 **멈춘다**

전에는 `뺐다: ${count}건` 을 찍고 그냥 끝났다. `updateMany` 는 `directUseAllowed: true`
조건을 걸어 두었으므로, 그 사이 남이 잠근 행은 **안 써지는데 원장에는 남는다** —
그러면 되돌리기가 **남의 잠금을 푼다.** 이제 둘이 다르면 무엇을 확인해야 하는지 찍고
`exitCode = 1` 로 멈춘다. 적재 쪽도 같다.

## 5. 「모른다」가 새는가 — **안 샌다**

### 5.1 규약은 튼튼하다

`checkChoiceFigureIndex` 를 반쪽 입력으로 찔러 봤다. 길이 불일치·범위 밖·정수 아님
(`null`·`NaN`·구멍 난 배열 포함)·0 아닌 번호 중복 — **전부 «모른다»로 떨어진다.**
빈 배열이 «안다»로 미끄러지는 경로는 없다. 발문(0)의 중복은 **일부러** 허용하는데
그게 맞다(발문 그림은 여럿일 수 있다).

### 5.2 ⓒ 🔴 그런데 **변이 21개 중 2개는 돌지도 않았다**

보고서는 「**변이 21개 전부 빨강** (규약 8 · 적재 7 · 제외 6)」이라고 적었다.
그대로 돌려 봤다:

```
🔴 빨강 …(19개)
PATTERN NOT FOUND
SKIP  되돌리기가 남의 변경을 덮는다 (패턴 없음)
PATTERN NOT FOUND
SKIP  이미 빠진 행도 다시 뺀다 (멱등 깨기) (패턴 없음)
원복 완료
exit=0                                   ← **종료 코드가 0 이다**
```

- **21 은 «빨강의 수»가 아니라 «`mutate` 호출의 수»였다.** 둘은 **실행되지 않았다.**
- 원인은 줄바꿈이다 — prettier 가 그 두 자리를 여러 줄로 접어 놓아 한 줄짜리 패턴이 안 맞는다.
  즉 **가드를 고치면서 변이 패턴이 조용히 죽었다.**
- 그리고 harness 가 `SKIP` 을 찍고 **exit 0** 을 낸다 — 「전부 빨강」으로 읽힌다.
  이 저장소가 여러 번 적은 **「세는 쪽이 실패를 셀 수 있는 형태인가」** 그 자리다.

**두 가드 자체는 멀쩡했다.** 패턴을 맞게 고쳐 직접 걸어 보니 **둘 다 빨강**이다.
그러니 이건 **주장이 검증되지 않았던 것**이지 가드가 없던 것은 아니다.

### 5.3 고쳤다

- 못 맞은 패턴 둘을 **실제 소스에 맞게** 고쳤다.
- 못 찾은 변이는 `🟠 못 찾음` 으로 **세고**, 초록도 세서, 하나라도 있으면 **exit 1**.
- 새 가드 셋(§3.4 · 객관식 · 정답 모양 · 그림 있음)을 변이 목록에 넣었다.
- **harness 를 스스로 망가뜨려 확인했다** — 없는 패턴을 하나 넣으니 `exit=1`.

```
🔴 빨강 …(24개 전부)
원복 완료
✅ 변이 전부 빨강        exit=0
```

`mutate-choice-figure-rules.sh`(판정 규칙 14개)도 돌려 봤다 — **14/14 빨강, 문제 없다.**

## 6. 되돌리기 — 🔴 **한 번은 정말 안 됐다**

### 6.1 원장이 «드라이런» 한 번에 지워진다

두 스크립트 다 원장을 **무조건 덮어쓴다**(`writeFileSync(LEDGER, …)`). 그런데
**적용을 마치면 다음 실행의 계획은 비게 된다**:

- 제외: 잠긴 행은 `directUseAllowed=false` 라 멱등 가드(⑥)에 걸린다. 후보를 다시 뽑으면
  **«출제 가능» 이 아니라서 목록에서 아예 빠진다.**
- 적재: 값이 든 행은 멱등 가드(②)에 걸린다.

그래서 **적용 뒤에 드라이런을 한 번만 더 돌려도** 원장이 `[]` 가 되고
**`--revert` 가 0행을 되돌린다.** 「영구 삭제가 아니다」의 근거가 사라진다.
그리고 **드라이런이 기본값이다** — 다음 사람이 「드라이런이니 안전하지」 하고 돌리면 그만이다.

**시연했다** (`qa/adversarial/scripts/demo-ledger-clobber.mjs`, DB 는 안 씀):

```
적용 직후 원장: 이전상태 29행 · 적용됨 true
드라이런 한 번 뒤:  이전상태 0행 · 적용됨 false
🔴 원장이 비었다 — `--revert` 는 이제 0행을 되돌린다.
```

`적용됨` 이 **`true` → `false` 로 꺼지는 것**도 나쁘다 — 다음 사람이 「아직 안 썼구나」로 읽는다.

### 6.2 고쳤다 — 원장은 **덮지 않고 이어 쓴다**

`scripts/qa/revertLedger.ts` 한 곳에 규칙을 뒀고 두 스크립트가 같이 본다.
원장은 「이번에 무엇을 할까」가 아니라 **「우리가 무엇을 바꿨나」의 누적 기록**이다.

- `mergeLedgerRows` — 새 계획을 앞에, **계획에 없는 옛 행은 그대로 남긴다**
  (같은 id 는 새 것이 이긴다 — 방금 읽은 `before` 가 더 정확하다)
- `stillApplied` — 한 번 적용했으면 뒤이은 드라이런이 **`false` 로 되돌리지 못한다**

시연이 이제 🟢 다. 회귀 가드 9개(`src/__tests__/unit/revertLedger.test.ts`).

### 6.3 되돌리기 **왕복**을 로컬 사본에서 돌렸다

공유 DB 의 **지금 값을 읽어** 메모리 사본을 만들고, **제품이 쓰는 순수 함수 그대로**
(`decideDiscard`/`revertDiscard`, `planRow`/`revertRow`) 적용 → 되돌리기를 돌렸다.
규칙을 옮겨 적지 않았다 — 옮겨 적으면 동어반복이다.

```
── ㉮ 출제 제외 잠금 ──
  ✅ 원장 29행이 DB 에 다 있다
  ✅ 잠그기 전 값이 전부 true (원장의 before 와 같다)
  ✅ 적용: 29행을 뺐다
  ✅ 남이 바꾼 1행은 안 건드리고 나머지를 되돌렸다 — 되돌림 28 · 안 건드림 1
  ✅ 되돌린 뒤 원래 값과 **한 글자도** 다르지 않다 — 다른 행 0
  ✅ 되돌리기를 한 번 더 돌려도 아무것도 안 바꾼다 (멱등)

── ㉯ 보기 그림 짝 적재 ──
  ✅ 계획 97행 · 적용 뒤 다시 계획하면 0행 (멱등)
  ✅ 남이 넣은 1행은 안 덮고 나머지를 되돌렸다 — 되돌림 96 · 안 덮음 1
  ✅ 남이 바꾼 그 한 행 말고는 원래 값 그대로다
  ✅ 그림 한 장이 떨어진 뒤에는 짝을 안 쓴다 — 「그림 목록이 바뀌었다 (회수 때 5장 · 지금 4장)」
```

### 6.4 `.gitignore` 함정이 **다른 곳에도** 있는가 — 없다

브리프가 물었다. 되돌리기 원장 **여덟 개 전부**를 `git add --dry-run` 으로 확인했다
(`git check-ignore` 의 종료 코드는 `!` 예외에도 0 을 돌려주므로 못 쓴다):

```
✅ 커밋된다 · scripts/qa/reports/choice-figure-index-apply.json
✅ 커밋된다 · scripts/qa/reports/choice-figure-discard-lock.json
✅ 커밋된다 · scripts/qa/reports/missing-figure-lock.json
✅ 커밋된다 · scripts/classify/reports/{mitigation,hold-resolve,reassign,reassign2,reassign3}-ledger.json
```

**여덟 개 다 커밋된다.** 같은 함정은 남아 있지 않다.

## 12. 교훈 (CLAUDE.md 에 옮길 것)

### 「반증용 모집단 → 처리용 모집단」의 좁히기는 **한 겹으로 안 끝난다**

433 → 43 은 **무리**를 걸러 좁힌 것이다. 그런데 남은 무리(`보기그림` 147건)도
**판정용으로 넓게 잡은 것**이고, 그 열쇠 하나가 **한 방향 문턱**이라 「그림이 넷 이상 붙은
서술형」을 전부 빨아들이고 있었다. 43 중 14 가 그것이었다.

**좁히기는 «어느 무리인가»가 아니라 «이 결함이 이 행에 성립하는가»로 해야 끝난다.**
여기서 성립 여부를 가른 것은 **정답 모양**이었다 — 서술형에는 「어느 그림이 ①인가」가
**물음으로 성립하지 않는다.**

그리고 **D-20 이 이번엔 못 잡았다.** 433 때는 분포가 튀어서 보였지만 14건은
건수도 분포도 그럴듯했다(영향 단원 25 → 15, 정원 아래는 그대로 0).
**잡은 것은 「전량을 눈으로 보라」와 「반대쪽 사실」(자동 97건은 전량 객관식)뿐이다.**

### 원장은 **「무엇을 할까」가 아니라 「무엇을 바꿨나」**다

되돌리기 원장을 매 실행마다 덮어쓰면, **멱등 가드가 계획을 비우는 순간 원장도 빈다.**
「원장을 DB 보다 먼저 쓴다」는 지켰는데도 그렇다 — **순서는 맞고 수명이 틀렸다.**
그리고 그 파괴가 **기본값인 드라이런**에서 일어난다. 원장은 **누적**이어야 한다.

### 변이 시험은 **패턴이 맞았는지**까지 세야 한다

「변이 21개 전부 빨강」의 21 은 **호출 수**였고 둘은 **돌지도 않았다.** 원인은
**가드를 고치면서 prettier 가 줄을 접어 패턴이 죽은 것**이다 — 즉 **고칠수록 변이가
조용히 죽는다.** harness 가 `SKIP` 을 찍고 **exit 0** 을 내면 아무도 모른다.
**세는 쪽이 자기 실패를 셀 수 있는 형태인지부터 보라** — 이 저장소가 이미 여러 번 적은 자리다.

### `false` 는 「우리가 썼다」는 뜻이 아니다

공유 boolean 한 칸을 원장 넷이 잠근다. 「지금 값이 우리가 쓴 값일 때만 되돌린다」는
**대부분을 막지만 attribution 이 아니다.** 실제로 그림 유실 원장 **446행 중 5행이 이미
풀려 있다.** 잠금이 셋을 넘으면 **누가 잠갔는지를 값에 적어야** 한다.
