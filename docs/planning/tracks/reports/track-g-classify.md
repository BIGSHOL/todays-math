## 1. 한 줄 결론

4. **기권** — 확신이 학년별 문턱 미만이면 붙이지 않는다.

### 5.1 본문과 소단원 라벨이 어긋난 행 **56건** (같은 학년 안)

트랙 D 가 문항 번호를 열쇠로 `content` 를 재추출본으로 교체했는데, **번호 정렬이
어긋난 편에서는 본문만 바뀌고 라벨은 옛 본문 기준으로 남았다.** 실물 확인:

| externalId | 현재 DB 본문 | 현재 DB 라벨 |
|---|---|---|
| 4485-6 | 연립부등식 $x^2-2x-3<0$ … | 4. 행렬 / **행렬의 곱셈의 성질** |
| 4485-7 | 공 10개에서 4개를 꺼내는 경우의 수 … | 2. 방정식과 부등식 / **연립이차부등식** |

편별: 4451(15) · 4539(12) · 4485(11) · 4542(9) · 그 외 산발 9건.
**이 행들은 그 단원으로 출제할 때 엉뚱한 문제로 섞여 나간다.** `content` 는 트랙 D 소유라
내가 고치지 않았다. 목록: `scripts/classify/reports/label-content-mismatch.json`.

> 이전 판 보고서에서 "편 7개의 번호가 어긋나 있다" 고 넘긴 건과 같은 뿌리다. 그때는 본문
> 교체 전이라 **본문↔라벨이 서로 맞는 상태**였고, 지금은 교체 후라 **어긋난 상태**다.

### 5.2 시험지 학년과 라벨 학년이 다른 행 **163건** (43편)

| 유형 | 건수 |
|---|---|
| 중2 시험지 → **공통수학2** 단원 | 71 |
| 중3 시험지 → **공통수학2** 단원 | 65 |
| 중2 → 중1 | 11 |
| 그 외 | 16 |

확인해 보니 성광중·사동중·강북중 등 **중학교 2학년 시험지**인데 붙은 단원이 고등
공통수학2 다(`[성광중][2][25-1-기말][천재이] (완료).PDF`). 전체의 0.46% 지만
**중등 문항이 고등 출제 풀에 들어가 있다.** 나는 이 행들을 학습셋에서 뺐다.

**원인은 학년 힌트가 숫자로 넘어가는 것이다** (⚠️ 앞선 보고 정정 — §11).
163건 중 **135건(83%)이 같은 단원 하나**로 갔다 — `공통수학2 / 3. 함수와 그래프 / 함수`.
적재기는 `gradeHint = paper.meta?.grade ?? paper.meta?.subject` 를 넘기는데 중2 시험지
메타가 `{ level: "중", grade: 2 }` 라 **맨숫자 2** 가 가고, `normalizeGrade(2)` 는 그것을
**공통수학2** 로 읽는다. `level` 은 안 넘어간다. 그 다음 공통수학2 안에 이름이 그냥
`함수` 인 소단원이 있어 `일차함수와 그래프`(71건)가 부분문자열로 붙는다.
중3 무리(62건)는 `grade: 3` → `normalizeGrade(3) = null` 이라 경로가 다르다(pool 이 전체).
**같은 자리로 가는 길이 둘이다.** 자세한 것과 정정 경위는 인계문에 있다.

## 6. 시도했지만 효과가 없어서 넣지 않은 것

**G-2(본문 대조로 원본 회수)** — 안 통한다. 최근접 이웃 라벨 일치율이 유사도 ≥0.95 에서
87.5%(16건), ≥0.80 에서 79.9%(누적 0.6%) 다. 방법이 틀려서가 아니라 **같은 문항이 학교를
건너 그대로 반복 출제되는 비율이 0.6% 뿐**이어서다.

**문항 번호 순서(스피어만 0.520)를 쓰는 동적계획 복원** — 소단원 정확도 +0.6%p 로 미미해
복잡도 대비 값어치가 없다고 보고 뺐다.

**실측 중 낸 오류**: 특징 추출 정규식이 `/\\[a-zA-Z]+/` 여야 하는데 `/\[a-zA-Z]+/` 로 들어가
**LaTeX 명령 특징이 통째로 죽어 있었다.** 지표는 초록이었고 "수식 특징을 넣으나 빼나
63.17% 로 같다" 가 유일한 단서였는데 "효과 없음" 으로 읽고 넘어갈 뻔했다.

## 10. 기하 `공간도형-위치관계(1)(2)` 가 0 건인 건 — 조사와 제안 (트랙 F 인계)

**`mapUnit.ts` 는 고치지 않았다. 제안만 낸다**(브리프 §5.1 — 공용 분류 로직).

### 무엇이 안 붙나

시험지가 소단원을 **적어 줬는데도** 매핑이 실패하는 기하 문항 **13건**:

| 시험지 표기 | 건수 | 위치관계(1) 유사도 | 위치관계(2) 유사도 |
|---|---|---|---|
| 두 평면이 이루는 각의 크기 | 5 | 0.000 | 0.000 |
| 두 직선이 이루는 각의 크기 | 4 | 0.000 | 0.000 |
| 직선과 평면의 위치관계 | 1 | 0.353 | 0.353 |
| 직선과 평면의 위치 관계 | 1 | 0.353 | 0.353 |
| 직선과 평면의 수직 | 1 | 0.000 | 0.000 |
| 직선과 평면의 평행과 수직 | 1 | 0.000 | 0.000 |

`SIMILARITY_FLOOR` 는 0.60 이다. **유사도 하한을 낮추는 것으로는 못 고친다** — 13건 중
11건이 공유 bigram 0 이라 하한을 아무리 낮춰도 0 이다. **별칭으로만 붙는다.**

### ⚠️ (1) 인지 (2) 인지 정할 근거가 없다

`normalizeForCompare` 가 괄호를 떼므로 두 소단원 이름이 **완전히 같은 문자열**이 된다:

```
"공간도형-위치관계(1)" → "공간도형-위치관계"
"공간도형-위치관계(2)" → "공간도형-위치관계"   ← 같다
```

그래서 유사도로는 영원히 동점이고 `bestSimilar` 는 앞선 것을 집는다. 교육과정 정본
(`eywa/curriculum.ts` 1271~1272행)에도 차시명 두 줄뿐이라 구분 설명이 없고,
이미 분류된 문항이 **두 단원 모두 0 건**이라 실측으로도 정할 수 없다.

**이건 `mapUnit.ts` 의 별칭 정책이 금지하는 상황이다** — "소단원 여러 개에 걸쳐 있어
하나를 고르면 임의 배정이 되고, 그 소단원으로 출제할 때 결이 다른 문제가 섞인다.
넣으려면 원장님 확인을 받을 것."

### 제안 (원장님 확인 후 적용)

두 묶음으로 갈라 각각 (1)/(2) 중 어디로 갈지 확인받은 뒤 `SECTION_ALIASES.기하` 에 넣는다.

```ts
기하: {
  // 묶음 ㄱ — 직선·평면의 위치 관계 자체 (4건)
  직선과평면의위치관계: "공간도형-위치관계(?)",
  직선과평면의수직: "공간도형-위치관계(?)",
  직선과평면의평행과수직: "공간도형-위치관계(?)",
  // 묶음 ㄴ — 이루는 각 (9건)
  두직선이이루는각의크기: "공간도형-위치관계(?)",
  두평면이이루는각의크기: "공간도형-위치관계(?)",
},
```

`aliasKey()` 가 공백·구두점을 털므로 `직선과 평면의 위치 관계`(띄어쓰기 다른 판)도
같은 키로 들어온다 — 항목을 따로 만들 필요가 없다.

**틀렸을 때의 손해는 작다**: (1)·(2) 는 `orderIndex` 687·688 로 바로 이웃이라
잘못 붙어도 진도 어긋남이 **1칸**이고, §4 에서 정한 ±2 밴드 안이다.
그래도 공용 로직이라 확인 없이 넣지 않았다.

## 11. `mapUnit.ts` 를 고치면 이미 적재된 것이 어떻게 되나 (코디네이터 요청 실측)

**`mapUnit.ts` 는 고치지 않았다.** 고쳤다고 가정하고 판정이 어떻게 달라지는지만 쟀다.
재현: `npx tsx scripts/classify/simulate-mapunit-fix.ts`
(수치 전량 `scripts/classify/reports/mapunit-fix-simulation.json`)

### 11.1 기준선을 재현값이 아니라 **DB 저장값**으로 잡았다 — 처음엔 틀렸다

처음에 "적재기가 넘긴 값을 그대로 재현해 비교" 하려다 **27,975행이 달라진다**는 결과가
나왔다. DB 의 실제 오배정은 163행뿐인데 말이 안 된다. 원인은 트랙 D 재추출본(08-16)의
`meta` 모양이 **적재 당시(08-14~15) 추출본과 다르다**는 것이었다 — 재현이 불충실했다.
그래서 "지금 판정" 을 **DB 에 실제로 저장된 `unitId`** 로 잡고 비교했다.

> 재현이 원본과 같다고 **가정하기 전에 규모부터 대조할 것.** 163 대 27,975 라는 자릿수
> 차이가 아니었으면 그대로 보고할 뻔했다.

옳고 그름의 잣대는 시험지 메타 학년(`gradeKeyOf`)이다 — 35,666행 중 99.54% 일치로 검증돼 있다.
비교 대상은 topic 이 있어 판정을 다시 낼 수 있는 **35,706행**이다.

### 11.2 안1 «부분문자열 단계에 학년 가드» — **손실이 이득보다 크다**

| 묶음 | 행 |
|---|---|
| (가) 지금 틀렸는데 옳아짐 | **0** |
| (가2) 틀린 것이 미분류로 | 70 |
| **(나) 맞던 것이 미분류로** | **6,345** |
| (나2) 맞던 것이 다른 단원으로 | 0 |
| (다) 안 바뀜 | 29,291 |

**옳아지는 행이 0 이고 맞던 6,345행이 출제 풀에서 빠진다.**
이유: `meta.grade` 가 `3` 인 중3·확률과 통계 시험지는 `normalizeGrade(3) = null` 이라
지금은 pool 이 전체지만 소단원 이름이 뚜렷해 **옳게 붙고 있다**. 가드는 그걸 끊는다.
표본 — `4126-6 "이차함수와 그래프" → 중3/이차함수와 그래프`,
`4082-9 "근호를 포함한 식의 계산" → 중3/근호를 포함한 식의 계산`. 전부 지금 맞는 행이다.

그리고 **정작 문제의 중2 무리 71건에는 걸리지도 않는다** — 그쪽은 학년이 *안 풀린* 게
아니라 *틀리게 풀린*(2 → 공통수학2) 것이라 가드가 발동할 자리가 없다.

### 11.3 안2 «적재기가 `level` 을 반영한 학년을 넘김» — 이쪽이 맞다

| 묶음 | 행 |
|---|---|
| **(가) 지금 틀렸는데 옳아짐** | **143** |
| (가2) 틀린 것이 미분류로 | 24 |
| (나) 맞던 것이 미분류로 | **18** |
| (나2) 맞던 것이 다른 단원으로 | 103 |
| (다) 안 바뀜 | 35,418 |

학년별로는 중2 +73 · 중3 +70 이 옳아진다(§5.2 의 그 행들이다).

**(나2) 103건은 손실로 보기 어렵다.** 표본이 전부 `4485`·`4451`·`4539` 로,
§5.1 에서 **번호 정렬이 깨졌다고 이미 지목한 편**이다(공통수학1 91건이 여기 몰려 있다).
그 편들은 본문·라벨·번호가 서로 어긋나 있어 무엇이 옳은지 이 시뮬레이션으로는 못 가린다.
**§5.1 을 먼저 정리한 뒤 다시 재야 한다.**

### 11.4 결론

- 트랙 C 가 짚은 «부분문자열 학년 가드» 는 **이 결함의 원인이 아니고, 넣으면 손해다**
  (옳아짐 0 · 맞던 것 6,345 손실).
- 실제 원인은 **적재기가 `level` 없이 `meta.grade` 맨숫자를 넘기는 것**이고,
  `normalizeGrade` 가 맨숫자를 고등 학년으로 단정하는 것이다.
- 고칠 자리는 `mapUnit.ts` 가 아니라 **적재기(`convertPastExam.ts`)** 일 수 있다.
  그쪽이면 공용 분류 로직을 안 건드린다. `normalizeGrade` 를 고치는 쪽은 공용 로직이라
  원장님 확인이 필요하다.
- 어느 쪽도 트랙 G 가 고치지 않았다. 판단은 코디네이터·원장님 몫이다.
