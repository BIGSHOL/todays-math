# RPM 쪽 장식 제외 — 「그림을 못 찾았다」 36건 중 18건은 **측면 색인 탭**이었다

작성 2026-08-20 · 원장 [`16-figure-recovery-ledger.md`](../../16-figure-recovery-ledger.md) §3.18

## 0. 한 줄

그림 유실 **121 → 103** (RPM 88 → 70). 회수 **18/18**, 전량 육안 확인, 손실 0.

## 1. 무엇이 대상이었나

§3.17(무리 짝짓기) 뒤 남은 RPM 88건은 이렇게 갈렸다.

| | 건수 |
|---|---:|
| 「자기 상자」 경로 잔여 | **52** ← 이 트랙 |
| 무리 표시 없는 지면 | 29 |
| 띠 안에 덩어리 없음 | 3 |
| `externalId` 없음(불가) | 4 |

52건의 실패 사유를 세니 **35건이 「문항 안에서 그림을 못 찾았다」**였다.

## 2. 「없다」를 적기 전에 — **제품 함수를 `trace` 로 불렀다**

이 저장소는 진단기를 따로 썼다가 값을 치른 적이 있다(2026-08-19 `diagnose-no-figure.py`
가 `thin_pt` 를 모른 채 「획이 아예 없다 10행」을 보고했는데 오려내기는 이미 살리고
있었다). 그래서 진단기를 새로 쓰지 않고 **`figure_rect` 가 이미 가진 `trace`** 를 썼다
(`scripts/figure/probe-rpm-nofig.py`).

한 번 돌리자 바로 보였다.

| 왜 못 찾았나 | 건수 |
|---|---:|
| **완비 검사가 버렸다** (무언가 칸 경계를 가로지르는데 삼킬 수 없다) | 29 |
| 후보가 아예 없다 | 7 |

그리고 가로지르는 것이 **17행에서 똑같은 51×28pt 하나**였다. 떠 보니
**측면 색인 탭**(`04 다각형`)이다.

```
     ┌──────────────┐   ┌─────┐
     │   그림       │   │ 04  │ ← 쪽 오른쪽 여백의 색인 탭
     └──────────────┘   │다각형│    상자에 걸치고 bleed 밖까지 뻗는다
                        └─────┘    → 삼킬 수 없다 → 그 문항을 통째로 버린다
```

낱말로는 못 가른다(글자가 아니라 획이다). 가르는 성질은 **되풀이**다 —
`furniture_keys` 가 이미 그 판정을 하고 있었는데 **RPM 경로가 그것을 안 불렀다.**

## 3. 고친 것

| | |
|---|---|
| `--furniture` | 되풀이되는 획을 그림 후보에서도 완비 검사에서도 뺀다. **기본 꺼짐** |
| `furniture_keys` 를 한 곳으로 | `crop-pdf-by-stem.py` 에 있던 정의를 `crop-rpm-from-pdf.py` 로 옮기고, 전자는 그것을 **그대로 쓴다**(`CIRCLED_ANSWER` 와 같은 이유) |
| 반올림 상수 | `figure_rect` 안에 **손으로 적힌 `3`** 이 있었다 → `FURNITURE_ROUND` 를 쓰게 했다. 세는 쪽과 거르는 쪽이 갈라질 자리였다 |
| `"이미있음": true` | 건너뛴 행에 그 사실을 적는다 — 그 파일은 예전 실행이 남긴 **다른 그림**일 수 있다 |
| `apply-rpm-furniture.py` | 붙일 대상을 **지금 유실인 행으로 다시 좁힌다.** 판정 없으면 멈추고, 분모가 안 맞으면 멈춘다 |

## 4. `--thin-pt` 는 **혼자 켜면 안 된다**

§3.14 는 「회수한 RPM 계획에 `--thin-pt` 를 켜지 마라 — 얻는 것 0, 좌표 52건 훼손」으로
막아 뒀다. 그 측정은 **장식 제외가 꺼진 상태**였다. 선을 살리면 단 사이 구분선·머리띠
밑줄도 같이 살아나 띠가 그리로 자란다 — `figure_rect` 의 주석이 이미
「선을 살리면 쪽 장식도 같이 산다」라고 적어 둔 자리다.

**둘을 같이** 켜고 다시 쟀다.

| 계획 | 기준 성공 | 둘 다 켬 | 잃음 | 얻음 | 좌표 달라짐 |
|---|---:|---:|---:|---:|---:|
| 관문(gated) 73행 | 14 | **31** | 1\* | 18 | 3 (≤0.6pt) |
| 무리(group) 48행 | 13 | **16** | 0 | 3 | 0 |
| 짝짓기(pair) 46행 | 46 | 46 | 0 | 0 | **0** |

\* 잃은 1행은 **지금 그림이 붙어 있는 행**이라 이번 회수 대상이 아니다.
(그 행의 붙어 있는 그림이 잘렸을 수 있다 — §7 에 남긴다.)

그리고 그 짝이 실제로 값을 했다. **장식만** 켰을 때 새로 오린 23칸 중
`a7ce23a1` 은 **x축이 양끝에서 잘려** 있었다 — 축이 두께 0인 선이라 완비 검사가
**볼 수 없었다.** `--thin-pt 0.5` 를 같이 켜자 그 칸은 「발문이 들어왔다」로 **제대로
떨어졌다.** 잘린 그림은 지면에서 티가 안 난다.

## 5. 눈으로 본 것

새로 오린 **21칸 전량**을 (ㄱ) 오려낸 그림 격자 한 장 (ㄴ) **지면 맥락**(칸을 빨강으로)
넉 장으로 봤다. 남의 발문·선택지·번호 배지 **0**. 색인 탭 **0**.

곁가지로 둘이 드러났다.

1. **`079c125c`(산점도)**: 지금 오리면 가로축 이름 「달리기(초)」가 칸 밖이다.
   그 낱말이 발문의 「100 m 달리기」와 같아 **지면 글자로 갈리기** 때문이다
   (§3.16 이 이미 겪은 자리). 그런데 이 행은 **이미 그림이 붙어 있었고**,
   붙어 있는 쪽이 축 이름을 담고 있었다 — 그래서 안 건드렸다.
2. **「이미있음」 3건이 지금 오릴 칸과 다른 그림**이었다. 결과에는 「성공」으로만
   적혀 있어, 눈으로 본 것과 붙는 것이 조용히 갈라질 자리였다.

### 변이 하나가 처음에 **거짓 초록**이었다

「거르는 쪽이 반올림을 손으로 적는다」 변이가 초록이었다. 치환 문자열
`k = tuple(int(round(v / FURNITURE_ROUND))` 이 **`furniture_keys` 안에도 똑같이
있어서** 둘 다 바뀌었고, 그래서 세는 쪽과 거르는 쪽이 **여전히 같은 수**를 썼다.
2026-08-18 「가드를 텍스트로 쓸 때는 그 낱말이 파일 안 다른 곳에도 있는지 먼저 보라」와
같은 자리다. 치환 자리를 유일하게 좁히고 `assert s.count(old)==1` 을 붙였다.

시험 픽스처도 두 번 고쳤다 — 합성 지면의 탭을 상자에서 멀리 두면 애초에 후보로도
안 잡혀 완비 검사가 볼 일이 없다. **상자에 걸치고 `bleed` 밖까지 뻗게** 놓아야
실제 지면과 같은 조건이 된다.
