## 1. 왜 자동으로는 안 되나 — 세는 것과 짝짓는 것은 다르다

`plan-rpm-group-figures.py` 는 지면에 인쇄된 무리 표시 `[0014~0017]` 로 띠를 잡고
그 안의 그림 덩어리를 찾는다(§3.13, 149건 회수). 짝은 이렇게 정한다:

- 덩어리 1개 → 무리가 함께 쓰는 그림. 전원 같은 좌표.
- 덩어리 수 == 소문항 수 → 세로(또는 가로) 차례가 맞을 때만.
- 그 밖 → **판정 불가로 버린다.**

버려진 46건의 실제 모습은 이랬다:

| 지면이 실제로 어떤가 | 건수 | 자동이 왜 못 했나 |
|---|---:|---|
| **무리 공용 그림 1장인데 덩어리가 여럿으로 세어졌다** | 24 | 소문항의 **답 넣는 `□` 줄**(`AB=□AM`)이 덩어리로 잡힌다. 「덩어리 4 ≠ 소문항 3」 |
| **격자(2열×2행)로 놓였다** | 22 | 세로·가로가 다 겹쳐 축을 못 정한다. 그중 **14건은 사실 무리 공용 1장**이고, 8건만 진짜 칸별 그림이다 |

즉 46건 중 **37건이 «그림 한 장을 여럿이 나눠 쓰는» 것**이었다(칸별은 9건뿐).
세는 것만으로는 그 사실에 닿을 수 없다 — 지면을 봐야 한다.

## 2. 검수 시트 — 무리마다 한 장

`scripts/figure/sheet-rpm-group-pair.py`

```
python scripts/figure/sheet-rpm-group-pair.py                # 시트 + 띠 그림 18장
python scripts/figure/sheet-rpm-group-pair.py --probe <무리키>  # 좌표 지도
python scripts/figure/sheet-rpm-group-pair.py --emit         # 판정대로 계획
```

띠를 200dpi 로 뜨고 **빨강 `[1][2][3]`** 으로 자동 덩어리를, **파랑 `0014`** 로
소문항 좌표 상자를 얹는다. 옆에 소문항마다 DB 발문 머리를 적는다. 사람은
`덩어리 N` 을 고르거나, 어느 것도 아니면 `--probe` 로 좌표를 보고 **네모를 직접 그린다.**

### 지키는 것 넷 (앞 시트 `sheet-rpm-stem-split.py` 와 같다)

1. **찾는 규칙은 한 곳뿐이다.** 띠·덩어리·소문항 자리는 계획이 잰 것을 그대로 읽는다.
   여기서 다시 찾으면 찾는 눈이 둘이 되고, 둘이면 같이 눈이 먼다.
2. **오려내기·검사는 손대지 않는다.** 이 스크립트는 좌표만 낸다. 발문 침입·문장·
   선택지 번호·완비 검사는 `crop-rpm-from-pdf.py` 가 그대로 한다. `avoid`/`forbid` 도
   계획 쪽 `guard_boxes()` 를 **그대로 부른다**(이번에 한 함수로 뽑았다).
3. **조용히 빼지 않는다.** `--emit` 은 판정이 안 적힌 대상이 하나라도 있으면 멈춘다.
4. **판정은 사유와 함께 커밋된다** (`rpm-pair-decision.json` · `rpm-pair-sheet.json`).
   판정이 «덩어리 3» 처럼 **번호**라서, 그 번호가 무엇인지는 시트에만 있다 —
   시트가 없으면 판정이 뜻을 잃는다. 그래서 둘 다 `.gitignore` 예외에 넣었다.

## 3. 막고 있던 것 넷 — 전부 **자동일 때는 옳은 규칙**이다

처음 돌렸을 때 46건 중 **16건이 떨어졌다.** 사유를 하나씩 지면과 대 보니 넷이 나왔고,
넷 다 「사람이 네모를 그려 준 자리에서 거꾸로」였다. 그래서 **끄지 않고 옵트인**으로 만들었다.

### 3.1 곧은 선은 `is_empty` 다 — **이 저장소에서 세 번째**

`fitz.Rect.is_empty` 는 폭·높이 중 **하나만 0이어도 참**이다. 축에 나란한 곧은 선이
정확히 그 모양이라, 획을 훑는 첫 가드가 선을 전부 버린다.

실측 1-2 p11 `[0030~0033]`(∠AOB 를 분류하는 각 그림):

```
가로 직선  [216.64, 317.55, 301.89, 317.55]   ← 높이 0 → is_empty
세로 직선  [259.26, 274.93, 259.26, 317.55]   ← 폭  0 → is_empty
남은 획    [259.27, 280.63, 280.56, 317.55]   ← 이것만 보인다
```

그래서 **사람이 그린 네모 `[214,272,305,330]` 이 `[222.8,278.6,295.0,330.6]` 으로
줄어들며 선을 양끝에서 잘랐다.** 지면에서는 티가 안 난다 — 직선이 짧아 보일 뿐이다.

→ `crop-rpm-from-pdf.py --thin-pt 0.5` (기본 0 = 예전 그대로).

> ⚠️ **회수한 RPM 계획에는 켜지 마라.** §3.14 가 이미 재 봤다 —
> 얻는 것 **0건**이고 이미 회수한 **52건의 좌표가 왼쪽 글자 열까지 벌어진다.**
> 켤 자리는 **선으로 그린 그림이 든 새 계획**이다.

앞선 두 번: 2026-08-19 기출 획 검출기(`figure_rect`), 같은 날 **그 결함을 잡으라고
만든 `bisected` 가드 안에서** 또 한 번. **`fitz` 로 획을 훑는 코드를 새로 쓸 때는
`is_empty` 를 먼저 의심하라.**

### 3.2 `bleed`(±60pt) 가 울타리를 넘는다

`figure_rect` 는 준 상자를 **찾기 시작할 자리**로 보고 ±`BOX_BLEED`(60pt)까지 자란다.
자동 좌표(`source_coords`)에는 그게 맞다 — 정사각뿔 꼭대기가 28pt 밖이었다.
그런데 **격자 무리에서 사람이 「이 칸이다」라고 그려 주면 그 60pt 가 옆 칸을 끌고 온다.**

- `0198`(2×2 왼위): 칸이 번호 배지에 물려 「지면 글자가 들어왔다」로 버려졌다.
- `0202~0205`: 칸이 **「(단, 점 O는 두 대각선의 교점이다.)」 줄까지** 자라 버려졌다.

→ 계획이 `bound` 를 주면 `bleed` 를 좁히고 **결과도 그 안으로 자른다.**
울타리를 준 22행 중 **7행**의 좌표가 실제로 달라졌다(클램프를 빼고 재 대조해 확인).

### 3.3 「30×20 보다 작으면 잡티」 — **한 줄짜리 그림은 원래 낮다**

1-2 p9 `[0014~0017]` 의 반직선 `A B C` 는 **83×12.6pt** 다. 그 문턱은 「자동으로 고를 때
밑줄 한 토막·점 하나를 거른다」는 뜻이지 「그림이 이보다 크다」는 뜻이 아니다.
→ 부르는 쪽이 문턱을 넘긴다. 울타리를 그은 행만 `(8,8)`.

### 3.4 「글자 블록에 잠긴 획은 수식 부속」 — 글자가 그림을 감싸고 흐르면 거꾸로

2-2 p41 `0201` 은 치수 라벨(`10 cm`·`x cm`·`y cm`)이 **한 글자 블록
`[183.8,713.9,290.7,752.7]`** 으로 묶여 평행사변형을 통째로 덮었다. 획 **12개가 전부**
「글자 속」으로 버려졌다. **면적 비율로는 분수 가로줄과 안 갈린다**(둘 다 «블록 안»이다).
→ 문턱을 옮기는 대신, **사람이 울타리를 그은 자리에서만 끈다.**

### 3.5 곁가지 — 「옆 문항 상자를 덮었다」가 무리 공용에는 거꾸로다

무리 공용 그림은 **형제들의 좌표 상자와 겹치는 것이 정상**이다(3-2 p12 `[0001~0006]`:
직각삼각형 하나를 여섯 소문항이 나눠 쓴다. `cos A` 소문항의 상자가 그림 칸까지 넓다).
이 가드 하나로 **8행**이 떨어지고 있었다.

→ 계획이 `siblings` 를 넘겨 **그 형제만** 빼고 센다. 근거는 짐작이 아니라
**지면에 인쇄된 무리 표시** `[0001~0006]` 다.

## 4. 눈으로 봐야 갈리는 것 — badge 조각 vs 잘린 라벨

`0198` 은 치수 `7`(93.2~97.2pt)이 번호 배지 `0198`(…94.1pt)과 **0.9pt 겹친다.**

| 왼끝 | 무엇이 생기나 |
|---|---|
| 93.2 | `7` 은 온전하지만 배지 `8` 의 **초록 조각**이 그림에 들어온다 |
| 94.3 | 배지는 없고 `7` 의 왼끝 1.1pt 가 잘린다 (여전히 `7` 로 읽힌다) |

**둘 다 600dpi 로 떠서 보고** 배지 조각이 없는 쪽을 골랐다. 자동으로는 못 고르는
자리이므로 판정과 근거를 `rpm-pair-decision.json` 에 남겼다.

## 5. 시험 — **양방향**으로 잰다

`python scripts/qa/test-rpm-group-pair.py` (합성 지면)

네 옵트인을 **켜고/끄고** 둘 다 잰다 — 「켜면 정말 달라지나 · 끄면 정말 그대로인가」.
`--emit` 의 「조용히 빼지 않는다」와 `blob_boxes` 의 겹침 묶기·차례도 잠근다.

⚠️ **픽스처를 두 번 고쳤다.** 처음 지면에서는 `bound` 와 `drop_inside_text` 변이가
**초록**이었다 — 가드가 없어서가 아니라 **지면이 그 가드가 갈라 주는 자리를 안 만들어서**다.

- `bound`: 라벨을 울타리 **밖**에 두면 `bleed & bound` 에서 이미 안 보인다.
  실제 지면(`0198`)처럼 **울타리 경계에 걸치게** 놓아야 갈린다.
- `drop_inside_text`: 글자 블록이 그림을 **가로로만** 덮으면 획 면적의 80%를 못 넘는다.
  실제 지면(`0201`)처럼 **위아래로도 감싸게** 놓아야 갈린다.

`bash scripts/qa/mutate-rpm-group-pair.sh` — **변이 8개 전부 빨강.**
변이마다 「자리를 실제로 찾았는지」 `assert` 를 붙였다(거짓 초록 방지).
