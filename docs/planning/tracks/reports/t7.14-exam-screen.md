새로 **3개 테스트를 추가**했다: 반대편 탭 링크 존재 / `aria-current` 전환 / 날짜·남은 작업 공유.

### 🔴 소유권 — `PredictionRun.userId` 가 없어 우회했다

지시는 "`PredictionRun.userId` 로 거른다"였는데 **그 컬럼이 없다**(§0).
그래서 `학생 → 반 → Class.userId` 로 되짚고, **없는 쪽으로 닫는다(fail closed)**:

> 이 회차가 다루는 학생 중 **하나라도** 내 학생이면 내 회차. 하나도 없으면 안 보인다.

- 남의 회차는 지시대로 **403 이 아니라 404** — 존재 여부 자체를 알리지 않는다.
- 상세 응답의 학생 행은 **내 학생만** 싣는다. 한 회차에 남의 학생이 섞여도 이름이 안 샌다
  (전용 테스트로 잠금).
- 부작용: 학생이 **한 명도 안 걸린 회차는 아무에게도 안 보인다.** 새는 것보다 낫다고 봤다.
- 갈아끼울 자리는 `composeRounds.ts` 의 `isRunVisibleTo()` **함수 하나**다.

### 🔴 지어내지 않고 비운 값 3건 (전부 테스트로 잠금)

| 값 | 왜 못 내나 | 화면이 하는 일 |
|---|---|---|
| `examDate` | 컬럼 없음 | `null` → D-day 자리에 **"일정 미정"** |
| `문제지`·`채점` 단계 | 담을 테이블·컬럼 자체가 없음(T7.9/T7.10 범위) | 항상 미완. **진행한 것처럼 칠하지 않는다** |
| `observedBlueprint` | 실측 청사진 컬럼 없음(T7.10 범위) | `null`. **예측값을 실측인 척 복사하지 않는다** |

Json 컬럼(`predictedScores`·`predictedBlueprint`)은 DB 가 형태를 지켜 주지 않는다.
엔진 버전이 올라가면 과거 행이 옛 모양으로 남으므로 **원소 단위로 검증해 깨진 것만 버리고
나머지는 살린다.** 청사진이 계약을 통과 못 하면 신뢰도를 `null` 로 두어 화면이
"예측 불가"로 그린다 — 검증 안 된 숫자를 원장님께 보내지 않는다.

### ⚠️ 성능 메모 (지금은 문제 없음)

`PredictionRun` 에 `userId` 가 없어 SQL 로 못 좁히고 **전량을 읽어 앱에서 거른다.**
학원 한 곳 규모에서는 문제없지만 컬럼이 생기면 `where: { userId }` 로 바꿔야 한다.
`Student.schoolName` 으로 미리 좁히는 안은 **검토했다가 버렸다** — 그 값이 NULL 인 학생의
회차가 통째로 사라져 **조용한 누락**이 생긴다. 주석에 적어 뒀다.

### 공유 테스트 더블을 건드렸다 (보고 대상)

## 6. 코디네이터가 확인해야 할 것

### 🔴 반드시

1. **§0 의 전제 3건을 다시 확인해 주십시오.** 특히 `PredictionRun.examDate` / `userId` /
   `riskFlags` 가 정말 배포됐다면 **다른 브랜치에 있고 `origin/main` 에 안 올라온 것**이다.
   올라오면 내가 우회한 세 곳을 즉시 정리하겠다:
   - `composeRounds.ts` `isRunVisibleTo()` → `where: { userId }` 로 교체
   - `composeRounds.ts` `toRoundSummary()` 의 `examDate: null` → 실제 컬럼
   - `loadRounds.ts` 의 전량 조회 → SQL 필터 (성능 메모 해소)
2. **내 브랜치가 아직 main 에 없다.** 1차 작업분도 함께 병합되어야 한다.
3. `src/mocks/prismaTestDouble.ts` 추가분을 T7.7/T7.10 과 대조해 주십시오(§2 끝).

### 확정이 필요한 디자인 세부 (1차 보고서에서 이월 — 아직 미확정)

4. **회차 행의 주 버튼**: Hi-fi 시안 3열 그리드에 버튼 칸이 없어 **회차 제목을 링크로**
   두었다. '오늘의 수학'처럼 별도 액션 컬럼을 원하시면 알려 주십시오.
5. **`MIN_EVIDENCE_ROUNDS = 2`**: 11 §8 backtest(근거 1편 MAE 1.362 vs 4편+ 1.079)를 근거로
   내가 정한 값이다. **원장님 확정 사항이 아니다.** "1회차라도 보여 달라"면 상수 하나만 바꾸면 된다.
6. **정렬이 지금은 사실상 무의미하다.** `examDate` 가 전부 `null` 이라 `sortRounds` 의
   D-day 정렬이 작동하지 않고 `createdAt desc` 순으로만 선다. 컬럼이 들어오면 자동 해소된다.

### 남은 범위 (내 태스크 아님 — 후속 태스크 필요)

7. 「+ 새 회차」(회차 생성 API·폼), 배점 보정기 화면(T7.9), 실점수 `[입력]` 폼(T7.10),
   실측 청사진 저장(T7.10).
8. **픽셀 대조는 코디네이터가 하기로 한 부분이다.** 내가 확인한 것은 "실제로 렌더되고
   빈 상태가 제대로 나온다"까지다(§3).
