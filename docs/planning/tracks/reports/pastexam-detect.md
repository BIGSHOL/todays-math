## 1. 브리프의 진단이 틀렸다 — **세는 쪽과 고치는 쪽이 갈라져 있었다**

브리프 §2 는 「상자 안에 획이 없다 11행」의 원인을 `thin_pt`(두께 0인 곧은 선)로 짚었다.
**그 값은 이미 켜져 있었다.** 그런데도 진단기가 그렇게 보고한 이유는,
`diagnose-no-figure.py` 가 「무엇이 버려졌나」를 **옆에서 다시 구현**하고 있었고 그 판이
`thin_pt` 를 몰랐기 때문이다. 두께 0인 획을 전부 「버려졌다」로 세고 있었다.

실제로는 이랬다 — `figure_rect` 에게 **자기가 버린 자리를 적게 해서** 다시 세니:

| 옛 진단기 | 제품이 실제로 버린 자리 |
|---|---|
| 상자 안에 획이 아예 없다 **10** | 완비 검사(칸이 경계를 가로지름) **13** · 후보가 없다 **3** |

`5350-13` 은 획 257개가 **전부 살아** 후보 144개가 됐고, 버린 것은 완비 검사였다.
그리고 그 13행 중 **11행이 옆 단(또는 단 구분선) 때문**이었다.

> 진단기는 이제 **세지 않는다.** `figure_rect(..., trace=…)` 가 적어 준 것을 모으기만 한다.
> (CLAUDE.md 2026-08-18 「목록을 손으로 쓰면 세는 쪽과 고치는 쪽이 같이 눈이 먼다」)

## 2. 무엇을 고쳤나 — 전부 **문턱이 아니라 구조**

| 고친 것 | 왜 |
|---|---|
| **단(段)을 안다** (`column_edges`) — 되풀이되는 세로 구분선 + 되풀이 글자줄을 뺀 빈 띠 | `AROUND_PT`(24pt) 가 상자를 옆 단으로 24pt 밀어내고 있었다. 대상 30편 **전부**에서 구분선이 잡혔다(728pt 판 363.4 · 595pt 판 296.7 · 2-up 841pt 판 210·630) |
| 단 경계를 **구분선 바깥쪽**으로 물린다 | 경계를 선 가운데로 잡으면 그 선이 상자에 1pt 걸린다 — 단 클립을 넣고도 5행이 그대로 떨어졌다 |
| **선택지 줄 위에서 끊는다** (`choice_floor`) | 이 시험지들은 숫자가 사유 영역 글꼴이라 `② ` 로 나온다. 열쇠가 비어 「본문에 있다」로 안 걸러지고, 라벨 되찾기가 선택지를 통째로 삼켰다 (28행 중 **9행**) |
| 그 판정을 「원문자가 있나」가 아니라 **「줄이 원문자로 시작하고 발문과 같은 왼쪽 끝에 서나」** | 그림 **안**에 ①~⑤ 가 적힌 문항(`5231-2` 피라미드)에서 끊기면 그림이 통째로 잘린다. 실측 전수: 진짜 선택지 줄은 들여쓰기 **0.0/−0.5pt**, 그림 안 원문자는 **+91.4·+116.3·+141.4pt** — 겹치지 않는다 |
| 선택지 줄의 **띠**를 되풀이해 넓힌다 | 선택지 값이 분수면 분자가 제 줄로 따로 잡혀 ① 줄보다 위로 올라간다. 그 꼭대기가 칸에 남았다(3행) |
| 지면 문법(`[4점]`)을 **줄**로 본다 | `[` · `12` · `점]` 이 서로 다른 span 이라 span 하나씩 물으면 **어느 span 에서도** 안 걸린다 |
| 배점 표기를 넓힌다 (`[…점]` → `[…점…]`) | 서술형은 `[총 6점, 각 2점]`·`[5점, 부분 점수 있음]` 처럼 길고 「점」 뒤에도 말이 붙는다. D-20: 통과분 19행 중 넓혀서 걸리는 것은 **실제로 배점 줄을 담고 있던 1행**뿐 |
| 발문을 **삼키지 말고 피한다** (`avoid_stem`) | 완비 검사가 「가로지르면 넓혀 삼킨다」라 발문 마지막 줄 **0.2pt** 때문에 발문이 통째로 칸에 들어왔다. 물러서다 그림 조각을 자르면 **안 물러선다** |
| **단을 가로지르는 것은 후보가 아니다** (`crosses_column`) | 머리띠는 울타리 밖까지 뻗어 **절대 못 삼킨다**. 스치기만 해도 그 문항이 버려졌다 |
| 문항 번호로 **쪽을 검산**한다 | 본문이 상해 최장 일치가 20자에 못 미쳐도, 번호가 그 쪽에 있으면 두 근거가 맞은 것이다. **번호로 쪽을 «고르지» 않는다** — 해설 쪽에 같은 번호가 또 있다(실측 4편 전부) |
| 조이는 규칙은 **폴백 사다리**로만 (7칸) | 「기본」이 통과하면 그대로 쓴다 — 성공하던 문항의 손실이 구조적으로 0. 실제로 `2384-6`(줄기와 잎)의 표 제목이 `avoid_stem` 에 잘려 나갔다가 이 구조로 되살아났다 |

곁가지로 고친 것 둘:

- `hwp-to-pdf.py` 가 **별도 데스크톱 격리를 안 쓰고 있었다.** 창 숨김만으로는 포커스를
  못 막는다(훔치는 시점이 `Dispatch` 그 순간이다). `hwp_to_hwpx_quiet.isolate_desktop`
  을 **불러 쓰게** 했다 — 트릭은 한 곳에만 둔다. 격리에 실패하면 **멈춘다**(절대 규칙 9).
- `build-pdf-figure-plan.ts` 가 **0바이트 PDF 를 「있다」로 셌다.** 변환이 죽으면 0바이트가
  남는데 `existsSync` 만 보면 계획에 들어가 오려내기가 통째로 멈춘다(`5049.pdf` 실측).

## 3. 검수에서 나온 결함 둘 — **둘 다 그림을 눈으로 봐서** 나왔다

1. **`bisected` 가 곧은 선을 못 봤다.** 「칸이 무언가를 반으로 잘랐나」는 획도 보는데
   `Rect.is_empty` 가 두께 0인 선에 참이라 **첫 줄에서 전부 걸러지고 있었다** — 같은
   함정이, 그것을 잡으라고 만든 가드 **안에서** 다시 났다. `3627-15` 은 상자를 잇는 선이
   칸 밖으로 18.4pt 나갔는데 관문 여섯이 전부 통과시켰다.
2. **그 가드를 넣자 사다리가 남의 그림을 물어 왔다.** 「위까지」 칸은 단 꼭대기까지
   열려 있어 앞 문항 14번의 마방진을 가져왔다 — 살짝 잘린 것보다 나쁘다.
   `foreign_choices` 로 막았다: 그림과 발문 **사이에 선택지 줄이 있으면 남의 것**이다.

## 4. 전량 육안 · 뺀 것

**고유 그림 22장을 전부 봤다.** 21장 정상, 1장(`3627-15`)이 위 ⑴ 결함 — **뺐다.**

확인한 것: 전개도의 칸이 다 들어왔나 · 표의 제목·머리가 붙어 있나 · 선택지·발문·배점
표시가 섞이지 않았나 · 본문이 말하는 것과 그림이 같은가(예 `3284-15` 「8등분된
정사각형」 ↔ 대각선·중선으로 8칸, `4229-24` 「5×5 격자, 아래에서 두 번째 행 왼쪽에서
두 번째 칸 색칠」 ↔ 그 자리가 회색).

**D-20 — 무엇을 잃었나**: 검수에서 넣은 가드 둘로 `3627-15` **1행**을 잃는다.
나머지 **27장은 바이트가 그대로**임을 다시 오려내 md5 로 확인했다(변동 0건).

## 6. 되돌리기

```bash
# 그림 되붙이기 21행  (원장: scripts/qa/reports/figure-attach-ledger.json)
ALLOW_SHARED_IMPORT=1 node scripts/figure/attach-hwp-figures.mjs --revert
# 잠금은 원장(missing-figure-lock.json)대로 다시 잠근다
ALLOW_UNIT_FIX=1 npx tsx scripts/qa/apply-missing-figure-lock.ts
```

원장 둘 다 커밋된다(`git check-ignore -q` 로 확인). 되돌리기는 **지금 값이 자기가 쓴
값일 때만** 되돌린다 — 남의 변경을 덮지 않는다.
