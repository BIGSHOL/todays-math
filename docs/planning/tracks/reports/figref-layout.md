## 1. 지금 왜 이렇게 그려지나 — 코드 경로

### 1.1 짝은 **원본에 있었다.** 이관이 문자열로 눌러 버린다

```
exam_index OCR JSON
  question.contents[]              ← 발문 (그 안에 figure 블록)
  question.choices[] = { number, contents[] }   ← ★ 여기 «③ 은 이 그림» 이 있다
        │
        │  src/lib/import/convertPastExam.ts:73-84
        ▼
  choiceParts = choices.map(c => `${c.number}. ${blocksToLatex(c.contents).content}`)
  content     = [발문, 세부문항, choiceParts].join("\n\n")      ← ★ 여기서 구조가 사라진다
        │
        │  src/lib/import/blocksToLatex.ts:57      figure 블록 → 문자열 `[그림] <설명>`
        │  src/lib/import/flattenStructured.ts:62,83  (RPM/sumaek 경로도 같다.
        │                                              83 줄은 choices 배열까지 편다)
        ▼
  problem.content  : 한 덩어리 문자열
  problem.figureUrls : 그림 파일 **평탄 배열** (figure-manifest 에서 따로 붙는다)
```

**어느 단계에도 「이 그림이 ③ 이다」를 담는 자리가 없다.** `ImportDraft` 는 `content:string`
하나뿐이고, `Problem` 도 `content` + `figureUrls: String[]` 뿐이다.
`prisma/schema.prisma` 의 `figureUrls` 주석이 「순서는 지면에 나온 순서다」라고만 적는다.

`src/lib/import/buildReport.ts:18` 은 이미 이렇게 적고 있었다 —
> 그림 없이 본문만 들어간 문항은 `"[그림] ..."` 만 남아 **학생이 풀 수 없다**.

### 1.2 렌더는 표시를 **보지 않는다** — 그냥 글자다

- `src/lib/problem/parseProblemContent.ts` — **`그림` 이라는 낱말이 한 번도 안 나온다.**
  `[그림]` 은 어떤 정규식에도 안 걸리고 `question`·`choices` 문자열에 **그대로 실려 나간다.**
- `src/components/math/ProblemContent.tsx:63-79` — 그림은 **한 덩어리**로 그린다.
  ```tsx
  <div className="mt-3 flex flex-wrap items-start gap-4 print:break-inside-avoid">
    {figures.map(...)}          // figureUrls 전량. 보기와 잇는 코드가 없다
  </div>
  ```
  그 아래 보기 그리드가 따로 온다. **그림과 보기를 잇는 코드는 저장소에 없다.**
- 그래서 지면에는 「발문 … `[그림] [그림] [그림]`」 뒤에 그림이 통째로 쌓이고,
  보기 자리에는 `① [그림] ② [그림]` 이 찍힌다.
  → `docs/planning/tracks/reports/figref/현행-발문70.png`

### 1.3 고칠 자리는 **한 곳**이다

`ProblemBody`(인쇄) · `ProblemCard`(문제은행) · `ProblemExcerpt`(검수) 가 전부
`PaperProblemView → ProblemContent` 한 경로를 지난다(렌더 경로 분기 금지, 2026-08-17 지시).
**`ProblemContent` 하나를 고치면 지면과 화면이 같이 고쳐진다.**

### 1.4 🔴 분모부터 갈랐다 — **134건 중 11건은 객관식이 아니다**

`report-choice-figures.ts` 의 열쇠 ㉯(「그림 4장 이상인데 번호 붙은 보기 다섯이 없다」)는
**서술형·단답형을 같이 잡는다.** 그림 넷은 발문 그림이거나 해설 그림이지 보기가 아니다.

가르는 열쇠는 **기록된 정답**이다 — 본문과 **독립**이고, `question_type` 은 못 쓴다
(정답이 `①` 인데 `서술형` 이라 적힌 행이 36건이다).

### 1.5 🔴 **본문 규약으로는 못 담는다** — 123건 중 1건

브리프가 물은 것: 「`content` 규약(보기 안에 그림을 적는 표기)으로 될 일인지,
컬럼이 필요한지」. **세어서 답했다** (`scripts/qa/report-figref-layout.ts`).

판정은 «표시 자리에 그림을 놓을 수 있는가»를 묻고, **본문 밖 열쇠 둘**로 반증한다.

- ㉠ **기록된 정답** — 정답이 `⑤` 인데 파서가 본 보기가 셋뿐이면 그 구조는 **틀린 것이 증명된다.**
- ㉡ **보기 칸 수** — 출제 가능 객관식 33,794건 중 **33,489건(99.10%)이 정확히 5칸**이다
  (4칸 46 · 3칸 37 · 2칸 54 · 0칸 109). 문턱이 아니라 **분포**에서 나온 경계다.

| 갈래 | 건수 | 뜻 |
| --- | ---: | --- |
| **규약가능** | **1** | 표시 수 = 그림 수 · 보기 5칸 · 발문 몫도 맞는다 (성광중 11) |
| **규약모순** | **76** | 정답이 보기 수를 넘음 41 · 보기 칸이 4·5가 아님 32 · 표시 수 ≠ 그림 수 1 · 발문 몫 불일치 2 |
| **표시없음** | **45** | 본문에 `[그림]` 이 **한 개도 없다** — 그릴 자리 자체가 없다 |
| 그림부족 | 0 | |
| **미분류** | **1** | 사수중 11 — §1.6 |

> **표시 수가 그림 수와 같아도 짝은 못 믿는다.** 관음중 17(exam 5193)은 그림 6장·표시 6개로
> 「1:1」처럼 보이는데, 파서가 보는 구조는 **발문 3 + 보기 3** 이다. 그런데 **기록된 정답이 ⑤**다 —
> 보기가 셋뿐인 문항에 ⑤ 는 없다. 그림 파일을 열어 보니 `q17.jpeg` 가 그릇(발문),
> `q17_1~q17_5` 가 그래프(보기 다섯)였다. **OCR 이 ①②를 발문 쪽으로 밀어 넣은 것**이고,
> `choice.number` 도 1·2·3 으로 다시 매겨져 있어 **번호조차 못 믿는다.**

**결론: 컬럼(또는 그에 준하는 자리)이 필요하다.** 본문 표시로 되는 것은 1/123 이다.

### 1.6 곁가지 — 변이 시험과 미분류가 잡아 준 것 둘

- **미분류 1건 = 사수중 11번(40cacb18).** 원인은 데이터가 아니라 **제품 코드**다.
  `parseProblemContent` 의 `dedupeRepeatedBlock` 은 「보기 목록이 통째로 2회 반복된 OCR 결함」을
  지우는데, 보기가 **전부 `[그림]` 뿐**이면 앞뒤 절반이 당연히 같아서 **멀쩡한 보기 넷을 둘로
  줄인다.** 출제 가능 풀 전량에서 이 함수가 보기를 절반으로 줄인 문항은 6건이고,
  **눈으로 보니 확실한 오작동은 이 1건**이다(나머지는 진짜 중복이거나 판단 보류).
  → 손상이 심할수록 손상을 정상으로 읽는 그 가드다. 고치는 것은 이 트랙의 일이 아니라 적어만 둔다.
- **판정기에서 죽은 검사 하나를 변이 시험이 잡았다.** 「보기 칸 하나에 표시가 정확히 하나」
  검사는 앞의 셋을 통과하면 「발문 몫이 맞는가」와 **대수적으로 같은 말**이라 아무것도 더
  가르지 못했다. 지웠다. **검사를 늘리는 것과 가르는 힘이 느는 것은 다른 말이다.**
- **덤**: 「정답 번호 > 파서가 본 보기 칸 수」인 문항이 **출제 가능 객관식 전량에서 169건**이다.
  그중 41건만 이 134 안에 있다. **나머지 128건은 그림과 무관하게 본문 구조가 깨진 것**이고
  아무 지표도 세고 있지 않다. 이 트랙 밖이지만 남긴다.

## 2. 배치안 — 안마다 **실측**

### 2.1 무엇을 재고 무엇을 그대로 두었나

- **제품 CSS·컴포넌트는 한 글자도 안 바꿨다.** 시안은 탐침 컴포넌트
  (`scripts/qa/figrefLayout.tsx`)로 그리고, 발문·상자·수식·발문 그림은 **제품 `ProblemContent`
  그대로** 태운다. 그래서 시안 사이의 차이가 **보기 조판 하나**만 남는다.
- **캐시로 채점하지 않았다.** 시안 높이는 전부 그 실행에서 새로 쟀다(Chromium · `media: print` ·
  실제 KaTeX/Tailwind/`TestPrint.module.css`).
- **분모를 검산했다.** 「현행」팔을 전수 실측 캐시(`.measure/cont.json`)와 맞대니
  **123건 중 1px 넘게 다른 것 0건**이다. 세 번의 실행에서 모두 같았다.
  앞 트랙이 스크린샷으로 남긴 값과도 같다(사동중 21번 현행 **1,878px** · 29mm **438px**).

### 2.2 ⚠️ 높이를 재기 위한 **가정** — 짝을 정하는 규칙이 아니다

`figref-source` 가 답을 내기 전이라, 측정에는 가정을 하나 두었다:
**그림이 5장이면 다섯 장 전부가 보기, 6장이면 첫 장이 발문 그림이고 나머지 다섯이 보기.**

표본을 **그림 파일을 열어** 확인했다.

| 문항 | 그림 | 확인한 것 |
| --- | ---: | --- |
| 관음중 17 (5193) | 6 | `q17.jpeg` = 그릇(발문) · `q17_1~5` = 물높이 그래프 → **발문 1 + 보기 5** ✅ |
| 원화중 4 (3868) | 6 | 발문 「아래 그림과 같은 △ABC와 서로 닮음인 삼각형은?」 → **발문 1 + 보기 5** ✅ |
| 대구북중 13 (5427) | 5 | `q13.jpeg` 가 **수직선 그림(=①)** 이다. 발문은 「일차부등식 …의 해를」 → **보기 5, 발문 0** ✅ |
| 범물중 13 (3761) | 5 | 발문에 그림이 필요 없는 문항 → **보기 5, 발문 0** ✅ |

**가정이 틀려도 «보기 칸에 몇 장이 들어가는가»가 같으면 높이는 같다** — 높이는 배정이 아니라
장수와 치수로 갈린다. 다만 **발문 그림 한 장의 자리**는 높이를 바꾸므로 위 넷을 눈으로 봤다.
그림 4장(3건)·7장(2건)은 「마지막 다섯(또는 넷)이 보기」로 뒀다. 전량 확인은 `figref-source` 몫이다.

`mt-4`(16px)·`gap-y-2`(8px)는 **지금 보기 그리드와 같은 값**이고, 열 간격만 새로 정했다.

```css

.figrefChoices.cols2  { grid-template-columns: repeat(2, minmax(0,1fr)); }

.figrefCell img       { max-width:100%; height:auto; width:auto; }

> **열 간격을 32px(`gap-x-8`, 지금 보기 그리드 값)로 두면 3열 칸이 99.8px 로 줄어든다.**
> 16px 이면 110.5px 다. 글자 보기와 달리 그림 보기는 «칸이 넓을수록 그림이 커지는» 쪽이라
> 좁혔다. — **이 값도 원장님 확정 대상이다(§6).**
>
> **그리고 `.figrefFig` 감싸는 칸을 빼면 안 된다.** 처음에 `img{max-width:100%}` 만 줬더니
> 그 100% 가 «칸 전체»로 풀려 3열에서 그래프의 `x` 축 라벨이 **잘려 나갔다.**
> 시안 사진을 눈으로 봐서 찾았다 — 숫자로는 안 보인다.

## 3. 「모른다」를 어떻게 그릴 것인가

브리프의 조건: **원장님이 지면에서 알아차릴 수 있는가. 조용히 틀리는 안은 버려라.**

### 3.1 지금 지면에 남는 «흔적» — 실측

| 지금 무엇이 보이나 | 건수 |
| --- | ---: |
| `[그림]` 날 문자열이 찍힌다 | **78** |
| 보기 번호만 찍히고 내용이 없다 | 2 |
| **아무 흔적도 없다** | **43** ← 지면만 보고는 «정상»과 구별 못 한다 |

**43건은 지금 조용히 틀리고 있다.** 발문 아래 그래프 여섯 장이 쌓여 있을 뿐이라,
지면을 훑어서는 「보기가 없다」는 것을 알아차릴 수가 없다.

### 3.2 후보 다섯 — 값과 함께

| 안 | 지면에 무엇이 보이나 | 높이 중앙(123건) | 원장님이 알아차리나 | 학생이 조용히 틀리나 |
| --- | --- | ---: | :-: | :-: |
| **㉠ 지금처럼 다 쌓기**(현행) | 43건은 **아무 표시도 없다** | 1,211px | ❌ 43건은 못 알아챈다 | 🔴 **그렇다** |
| **㉡ 순서대로 ①~⑤ 를 붙인다** | 정상 문항과 똑같아 보인다 | 346px (ㄴ) | ❌ **전혀 못 알아챈다** | 🔴 **가장 위험하다** |
| **㉢ 번호 없이 격자 + 머리말** | 「보기 그림 · 번호와의 짝을 확인하지 못했다」 | 427px | ⭕ 눈에 띈다 | ⚠️ 학생이 순서를 짐작한다 |

**버려야 하는 것은 ㉡ 이다.** 「모른다」를 「순서대로 붙인다」로 미끄러뜨리면 **틀린 시험지가
정상으로 보인다.** 지금(㉠)보다 나쁘다 — 지금은 적어도 78건에 `[그림]` 이 찍혀 이상하다는 게 보인다.

**㉤ 에는 선례가 있다.** 그림 유실 문항 857건은 이미 `directUseAllowed=false` 로 잠겨 있고

**㉣ 는 학생 시험지에 내부 메모를 인쇄한다.** 절대 규칙 5(문구는 간결·사무적)와 별개로,
학생 손에 「확인 필요」가 가는 것은 제품으로서 이상하다. **㉣ 는 검수 화면 전용**으로 두고
지면은 ㉤ 로 가는 조합이 자연스럽다.

### 3.3 그래서 권하는 짜임 (§5 에서 다시)

```
짝을 안다        → §2 의 조판으로 그린다
짝을 모른다      → 출제 풀에서 뺀다(㉤) + 검수 화면에서 「그림 확인 필요」로 보여 준다(㉣)
                   ↳ 사람이 짝을 지어 주면 그 자리에서 풀로 돌아온다
```

**「모른다」의 크기는 `figref-source` 세션이 정한다.** 이 세션이 말할 수 있는 것은
**본문만으로는 1/123 밖에 못 세운다**는 것뿐이다(§1.5).

## 4. 높이 자를 **같이** 어떻게 고치나

> 조판을 바꾸면 자가 같이 움직여야 한다. 안 그러면 「출제는 골랐는데 인쇄 판정은 경고하는」
> 문항이 생긴다 — 오늘 확정된 **D-52** 가 정확히 그 원칙이고, `fit-select.md` §2 가
> 「한 규칙·한 숫자」로 잠가 둔 자리다.

### 4.1 자에 더할 것은 **한 항**뿐이다

탐침 자 `scripts/qa/figrefRuler.ts` 는 이렇게 생겼다.

```ts
estimateFigrefProblemPx(content, plan, {cols, beside}) =
    estimateProblemPx( stripFigureMarks(content), plan.stem )   // ← 제품 자 그대로 부른다
  + choiceFigureBlockPx( plan.choices, {cols, beside} )         // ← 새로 세는 것은 이것뿐
```

- **발문·상자·세로 수식·«글자가 남은 보기»는 제품 자가 센다.** 옮겨 적으면 두 자가 갈린다.
- `stripFigureMarks` 는 `[그림]` 표시와 **빈 보기 줄**(`1.` 만 남은 줄)을 지운다.
  조판이 안 그리는 것을 자도 안 세게 하려는 것이고, **조판과 자가 같은 함수·같은 문자열**을 쓴다.
- `choiceFigureBlockPx` 는 격자 모형이다 — 한 줄에 정확히 `cols` 장, 줄 높이는 그 줄의 최댓값,
  `번호 옆`은 마커 한 줄(20.3125px) 아래로 안 내려간다.

**상수는 실측에서 온다** (`measure-figref-layout.tsx` 가 지면에서 재서 찍는다):

| 시안 | 보기 칸 폭 | 마커 폭 | 그림칸 폭 | 마커 줄높이 |
| --- | ---: | ---: | ---: | ---: |
| ㄱ-옆2 | 173.77 | 12.50 | 155.27 | 20.31 |
| ㄴ-옆3 | 110.52 | 12.50 | 92.02 | 20.31 |
| ㄷ-아래2 | 173.77 | 12.50 | 173.77 | 20.31 |
| ㄹ-아래3 | 110.52 | 12.50 | 110.52 | 20.31 |

칸 폭은 `(problemColumn − colGap×(cols−1)) / cols` 와 **소수점까지 같다**(2열 173.75 · 3열 110.50).
그래서 자는 유도값을 쓰고, 회귀 가드는 **실측 리터럴**로 못 박는다.

### 4.2 채점 — 「참」은 Chromium 이 잰 값이다

정답은 **제품 상수가 아니라 실측 `neededPx`** 다. 자를 아무리 고쳐도 정답이 안 움직인다
(2026-08-18 의 그 결함을 안 되풀이하려는 것이다).

| 자 / 시안 | \|오차\| 중앙 | 90분위 | 최대 | ≤20px | **20px 넘게 과소(놓침)** |
| --- | ---: | ---: | ---: | ---: | ---: |
| ㄱ-옆2 · ㄴ-옆3 · ㄷ-아래2 · ㄹ-아래3 | **0** | 20 | 28 | **87.0%** | **0.0% (0건)** |
| **제품 자 / 현행 (분모)** | 0 | 20 | 20 | 88.6% | 0.0% (0건) |

네 시안의 성적이 같은 것은 우연이 아니다 — 격자 모형이 **정확**해서 남는 오차가 전부
발문 글자 줄 수(시안과 무관)에서 온다. 격자 자체는 실측과 1px 안에서 같다.

> **놓침 0건이 중요하다.** 과소평가는 겹쳐 찍힌 시험지로 간다. 오차는 전부 «크게 보는» 쪽이다.
>
> 만들다가 실제로 놓침을 낸 적이 있다. **이미 파싱된 발문**을 자에 다시 넣었더니
> `estimateProblemPx` 가 한 번 더 파싱하면서 **상자 구조가 녹아** 4건이 78~229px 과소평가됐다
> (계성중 15·제일중 10·심인중 10·강북중 6 — 전부 `<상자>`/`<보기>` 문항).
> **원문을 넣도록 고쳐서 0건이 됐다.**

### 4.3 자가 바뀌면 **출제와 인쇄 경고가 같이** 바뀐다

`assessSeat` 하나를 출제(⑷)와 인쇄 판정이 같이 쓴다. 그래서 아래 수가 곧
**⑷ 가 후순위로 미는 수**이자 **인쇄가 경고하는 수**다.

| 자 / 시안 | 첫 장 405px | 이어지는 장 484px | 혼자 쓰는 칸 997px |
| --- | ---: | ---: | ---: |
| **제품 자 / 현행 (분모)** | 117 | 113 | **75** |
| ㄱ-옆2 | 103 | 92 | 3 |
| **ㄴ-옆3** | **57** | **51** | **0** |
| ㄷ-아래2 | 110 | 102 | 22 |
| ㄹ-아래3 | 69 | 58 | 0 |

- 실측과 맞는다(ㄴ-옆3 실측 57 / 50 / 0 · 자 57 / 51 / 0).
- **⑷+⑸-c 를 도로 까먹지 않는다.** 이 123건은 지금 «후순위로 밀리는» 쪽인데,
  조판을 바꾸면 대부분이 «칸에 들어가는» 쪽으로 올라온다 — 정책이 약해지는 게 아니라
  **정책이 밀어낼 이유가 없어진다.**
- ⚠️ **다만 시험지 단위 경고율(69.1% → 5.9%)을 다시 재는 것은 이 트랙에서 못 한다.**
  `simulate-overflow-policies.ts` 는 제품 `selectProblems` 를 부르고, 제품 자는 아직 안 바뀌었다
  (D-07). **조판이 확정되고 자가 제품에 들어간 뒤 그 시뮬레이터를 반드시 다시 돌려야 한다.**
  이 123건은 풀의 0.28% 라 시험지 단위 효과는 작을 것으로 보지만, **그건 추측이고 위 표만이 측정이다.**

### 4.4 배선 — 한쪽만 옮기면 그쪽 지표만 좋아진다

「어느 그림이 ①인가」를 담는 자리를 만들면 **자를 부르는 모든 자리가 그것을 받아야 한다.**
자는 브라우저에서 도니 파일을 못 읽는다 — 짝은 **DB 에서 실려 와야** 한다.

경로가 하나라서(§1.3) **같은 결함이 화면에도 그대로 있다.** 화면 매체로 다시 재 봤다:

| | 지면(인쇄) 중앙 | **화면 중앙** |
| --- | ---: | ---: |
| 현행 | 1,211px | **1,363px** |
| ㄴ-옆3 | 346px | 346px |

화면이 더 큰 이유는 그림 상한이 다르기 때문이다 —
`className="… sm:max-w-[360px] print:max-w-[70mm]"`(264.6px). **발문 그림 상한을 정할 때
화면 값(360px)도 같이 정해야 한다.** 보기 격자는 매체와 무관해서 두 값이 같다.

## 7. 두 브리프의 차이 · 확인과 추측

### 7.1 브리프가 둘이었다 — 어긋난 것을 적는다

작업 도중 넘침 조사 세션이 쓴 `brief-choice-figures.md` 를 원장님이 넘겨 주셨다.
**근거는 그쪽을 우선했고**, 어긋난 것은 아래에 남긴다.

| 항목 | 내 `BRIEF.md` | `brief-choice-figures.md` | 이 보고서가 한 것 |
| --- | --- | --- | --- |
| 산출물 | `figref-layout.md` | `choice-figures.md` | **`figref-layout.md`** (세션이 둘로 갈렸다) |
| 범위 | 조판만 (복구는 `figref-source`) | 복구 + 조판 한 세션 | **조판만.** 복구 경로 ㉠~㉣ 은 손대지 않았다 |
| 건수 | 134 | 134 (past_exam 131 · RPM 3) | **재현됐다.** 다만 조판 대상은 **123**(§1.4) |
| 열쇠 ㉮ / ㉯ | — | 64 / 134 | **재현됐다** |
| 그림 장수 4/5/6/7/13/20 | — | 10/68/52/2/1/1 | **전부 재현됐다** |

**숫자 둘은 재현이 안 됐다. 조용히 버리지 않고 적는다.**

- **「본문에 보기 마커가 얼마나 남았나: 없음 53 · 일부만 78 · 다섯 다 3」**
  → 내가 센 값은 **53 · 67 · 14**. 「없음 53」은 같다. 내 규칙은
  「줄머리의 `1.`~`5.` 중 **서로 다른** 번호의 개수」다(`(?:^|\n)\s*([1-5])[.)]\s`).
  중복까지 세면 갈래가 달라진다. **조판 결론을 바꾸지 않는다** — 어느 쪽이든
  「다섯이 다 남은 문항」은 소수다.
- **「보기 자리에 `[그림] <설명>` 이 붙은 것 67건」**
  → 내가 센 값은 **134건 중 1건**(그 1건도 객관식이 아니다). 규칙은
  「`[그림]` 바로 뒤 같은 줄에 글자가 있는가」(`/\[그림\][ \t]*\S/`)이고,
  DB 전량으로는 53건이다. `scripts/figure/strip-figure-text.ts` 가 그 사이에 걷어냈거나
  세는 규칙이 다른 것으로 보인다. **이 차이도 조판 결론을 바꾸지 않는다** —
  ㉠ 경로에 필요한 것은 표시의 **자리**이지 설명이 아니고, 그 자리는 §1.5 에서 이미 무너졌다.

### 7.2 확인한 것 / 추측인 것

**확인한 것 (실측·육안)**

- 조판 경로가 한 곳이라는 것 — 코드로 확인, 화면 매체 측정으로 재확인.
- 시안별 높이 전부 — Chromium 실측. 분모(「현행」팔)는 전수 캐시와 **0건 차이**.
- `[그림]` 표시로 그릴 수 있는 문항이 123건 중 1건 — 판정기 + 반대쪽 모집단 33,794건 분포.
- 관음중 17·원화중 4·대구북중 13·범물중 13 의 발문 그림 유무 — **그림 파일을 열어서**.
- 자의 정확도와 놓침 0건 — 실측 채점.
- 3열에서 그래프 축 라벨이 잘리던 것 — **시안 사진을 눈으로 봐서**.

**추측인 것 (표시해 둔다)**

- 「그림 5장이면 전부 보기, 6장이면 첫 장이 발문」 — 표본 4건만 봤다(§2.2). 전량 확인은
  `figref-source` 몫이고, **높이 표는 이 가정 위에 서 있다**(장수가 같으면 값은 안 변한다).
- 시험지 단위 경고율이 얼마나 내려가는가 — **안 쟀다**(§4.3). 제품 자가 안 바뀌었기 때문이다.
- 그림 4장(3건)·7장(2건)의 짝 — 「마지막 다섯(넷)이 보기」로 뒀을 뿐 확인하지 않았다.

- **분모를 먼저 갈라라.** 「134건」 안에 서술형 11건이 섞여 있었고, 그 열쇠는 본문이 아니라
  **기록된 정답**이었다. 판정 근거를 한 컬럼에서만 찾으면 다른 컬럼에 있는 답이 「없는 것」이 된다.
- **«가능»과 «옳음»은 다른 말이다.** 표시 수가 그림 수와 같아도 짝이 맞는다는 뜻이 아니다.
  관음중 17 은 6:6 으로 딱 맞는데 구조는 발문 3 + 보기 3 이었다. 그것을 반증한 것은
  **본문 밖의 정답 번호**였다.
- **가드는 망가뜨려 봐야 가드인 줄 안다.** 19개 중 3개가 초록이었고 셋 다 픽스처 탓이었으며,
  그중 하나는 **검사 자체가 죽은 코드**였다. 검사를 늘리는 것과 가르는 힘이 느는 것은 다르다.
- **자에 넣는 입력이 조판과 같은지 보라.** 파싱된 발문을 자에 다시 넣었더니 상자 구조가
  녹아 4건이 최대 229px **과소평가**됐다 — 놓침 방향이다. 원문을 넣게 고쳐 0건이 됐다.
- **그리고 숫자가 못 보는 것은 사진에서 나온다.** 3열에서 그래프 축 라벨이 잘리던 것도,
  「43건은 지면에 아무 흔적이 없다」도, 높이 표에는 한 줄도 안 나온다.
