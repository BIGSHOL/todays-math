# 검토 ③ 지면 — 문항번호를 시험지에 어떻게 둘 것인가

작성 2026-08-18 · 트랙 `id-print` · **검토 문서다. 제품 코드는 한 줄도 안 고쳤다.**

원장님 말씀 세 번을 그대로 옮긴다.

1. 「모든 문항에 문항번호를 넣고 쉽게 찾아볼 수 있게 하고 싶다. **무작정 넣는 게 아니라
   일리 있고 합리적으로.**」
2. 「문항번호는 메타데이터로 숨긴다」 — 다만 「**보여줘도 되면 아주 작은 글씨로
   그냥 참고용으로 정도만**」이 열려 있다.
3. 「**문항번호를 키우고, 상단에 문항번호, 하단에 문제시작**을 할 수도 있지 않을까?
   문항번호를 **별개의 서식**으로 두는거지.」

2·3 의 「문항번호」는 서로 다른 것을 가리킨다. 2 는 **내부 식별자**(문제은행에서 그
문항을 집는 값)이고, 3 은 **지면 순번**(문 1, 문 2 …)이다. 이 문서는 둘을 섞지 않고
`식별자` / `순번` 으로 나눠 쓴다.

## 1. 무엇을 재고, 무엇을 안 건드렸나

### 1.1 잰 방법

지면을 **실제로 그려서** 잰다. 추정치는 한 개도 안 썼다.
Chromium · `emulateMedia({media:"print"})` · 제품이 쓰는 KaTeX CSS·Tailwind 산출물·
`TestPrint.module.css` **원문** (`scripts/qa/paperProbe.tsx` 하네스).

문항 하나의 세로를 두 가지로 잰다.

- `neededPx` — 문항번호 위 ~ **정답란 아래**. `measure-print-overflow.tsx` 와 같은
  정의라서 전수 캐시와 같은 자다.
- `usedPx` — 문항번호 위 ~ **문항 열에 그려진 것 중 가장 아래**. 넘침 판정은 이 값으로 한다.

> ⚠️ **`usedPx` 가 없었으면 이 문서의 표가 통째로 거짓이 될 뻔했다.** 처음엔 `neededPx`
> 하나로만 쟀는데, 「정답란 **아래**에 새 줄을 붙이는」 대조군이 **Δ 0.0px** 로 나왔다.
> 한 줄을 새로 먹는 배치인데도 그렇다 — 붙인 자리가 그 구간 **밖**이라 자가 아예 못 본
> 것이다. 「0px 이라 공짜」는 이 검토가 가장 듣고 싶어 하는 답이라, 그대로 실렸으면
> 아무도 의심하지 않았을 것이다. 자를 고치니 같은 대조군이 **+18.0px** 로 나온다.

### 1.2 조용히 거짓이 되는 길을 막은 가드 다섯

배치안의 마크업 주입이 실패하면 그 변형은 **기준선과 똑같이 그려지고**, 결과는
「Δ 0px · 넘침 증가 0건」이 된다. 그래서 매 실행 다음을 확인하고, 어긋나면 **던진다.**

| #   | 무엇을 확인하나                                                               | 왜                                                             |
| --- | ----------------------------------------------------------------------------- | -------------------------------------------------------------- |
| ①   | 주입한 표시(`.idMark`)가 **문항 수만큼** DOM 에 있는가                        | 주입이 새면 「0px」이 공짜로 나온다                            |
| ②   | 번호 서식이 **실제로** 그 글꼴·여백으로 그려졌는가 (브라우저에서 되읽어 대조) | CSS 가 안 먹어도 표는 초록이다                                 |
| ③   | 실측 칸이 제품 상수(484/405px)와 같은가                                       | 다르면 엉뚱한 칸으로 넘침을 센다                               |
| ④   | 기준선에서 `usedPx == neededPx` 인가                                          | 두 자가 다른 것을 재고 있으면 비교가 성립 안 한다              |
| ⑤   | 같은 실행의 기준선이 **전수 캐시와 같은 값**인가                              | 전수 환산이 «다른 두 지면을 이어 붙인 숫자»가 되는 것을 막는다 |

### 1.3 전수 환산을 «정확»이라고 부를 수 있는 조건

변형마다 47,152건을 다시 그리면 한 변형에 90분이다. 그래서 **판정이 뒤집힐 수 있는
문항만** 골라 전수로 잰다 — 여유(`availPx − neededPx`)가 창 안인 문항이다. 창 밖
문항은 **Δ 가 창보다 작은 한** 판정이 바뀔 수 없다.

그 전제를 스스로 확인한다: 잰 Δ 의 최대 절대값이 창보다 크면 도구가
「**있음(주의)**」이라고 말한다. 이 확인이 없으면 **창을 좁게 잡을수록 「증가 0건」이
잘 나온다** — 듣고 싶은 답이 공짜로 나오는 구조다. 창 밖에서도 Δ 가 창을 안 넘는지
보려고 창 밖 문항 600건을 고루 뽑아 같이 잰다.

### 1.4 무엇을 바꾸고 무엇을 그대로 뒀나

|                  |                                                                                                                                                                                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **안 건드린 것** | 제품 코드 전부. `src/lib/printOverflow.ts`·`src/lib/tests/`(다른 세션 작업 중)·`scripts/qa/paperProbe.tsx`·`TestPrint.module.css` 한 글자도 안 고쳤다.                                                                                                   |
| **바꾼 것**      | 없다. 배치안은 **탐침 문서에만** CSS 를 덧입혀 그렸다 — 지면 원문은 그대로 두고 `<style>` 을 뒤에 붙여 덮어썼다.                                                                                                                                         |
| **새로 만든 것** | `scripts/qa/measure-id-mark.tsx`(배치별 자리 값·전수 환산) · `scripts/qa/measure-mark-size-budget.tsx`(자리별 크기 한도) · `scripts/qa/audit-printable-id.ts`(식별자 체계 판정) · `scripts/qa/probe-print-metadata.tsx`(인쇄 경로 생존). 전부 읽기 전용. |

지면 원문을 안 바꿨으므로 **전수 높이 캐시는 이 작업 때문에 낡지 않았다.** 캐시의
지문(`inputsHash`)은 작업 전후가 같다.

### 1.5 캐시 — 실제로 있었던 일

받은 캐시로 채점기를 돌리니 **멈췄다**(문항 본문 지문 불일치). 조사한 결과:

- 어긋난 문항 **37건**, 전부 그림이 있는 RPM 문항이고, 그 그림 파일이 **디스크에서
  사라졌다**(`public/figures/rpm/…` — 다른 트랙이 회수 경로를 옮기는 중이다).
- 즉 **DB 는 안 바뀌었다.** 지문이 그림 **파일 자체**를 보기 때문에 걸린 것이다
  (2026-08-18 에 그 장치를 넣어 둔 덕에 드러났다).
- `--verify … --repair` 로 그 37건과 고루 뽑은 표본 2,000건을 다시 재니
  **「본문이 그대로인데 다른 것 0건 (최대 차 0.00px)」** — 지면은 안 바뀌었다.
  37건만 깁고 지문을 다시 찍었다.

지금 캐시로 채점기가 내는 값은 브리프의 숫자와 정확히 같다:
**이어지는 장 2,917건(6.19%) · 첫 장 6,345건(13.46%).** 이 문서의 전수 환산은 이 캐시를 쓴다.

> 첫 장 캐시는 같은 절차에서 어긋난 문항이 **1건**이었다. 37 → 1 로 줄어든 것은 그
> 사이에 그림 파일이 되돌아왔기 때문이다. **파일이 지금도 움직이고 있다**는 뜻이라,
> 이 문서의 절대 높이는 「2026-08-18 저녁 기준」이다.

## 2. 가 — 번호 줄의 빈 자리는 정말 0px 인가

`.questionNumber` 는 `font-size:18px · line-height:1 · margin-bottom:6px` 인 **독립 블록**이고,
그 오른쪽은 서술형 배지가 없는 문항에서 **비어 있다**. 문항 열은 363.5px 인데
「문 12」는 40px 안팎만 쓴다. 그러니 **가로는 남는다.** 문제는 세로다.

### 2.1 전수 실측 — 표시를 넣으면 넘침이 몇 건 느나

식별자 `5123-7`(6자)을 넣고 47,152건 전수로 환산했다. 창 안 문항은 전부 다시 그렸고,
잰 Δ 의 최대 절대값이 창(5px)보다 작아 **창 밖 문항은 뒤집힐 수 없다 → 아래 숫자는 정확하다.**

| 배치                         |     Δ(문항당) | 이어지는 장 484px | 첫 장 405px     |
| ---------------------------- | ------------: | ----------------- | --------------- |
| (기준선)                     |             — | 2,917건           | 6,345건         |
| **풀이칸 오른쪽 아래** 7pt   |     **0.0px** | **2,917 (+0)**    | **6,345 (+0)**  |
| **정답란 오른쪽 끝** 7pt     |     **0.0px** | **2,917 (+0)**    | **6,345 (+0)**  |
| 번호 옆 인라인 6pt           |         0.0px | 2,917 (+0)        | 6,345 (+0)      |
| 번호 옆 인라인 7pt           |         0.3px | 2,926 (**+9**)    | 6,367 (**+22**) |
| 번호 옆 인라인 8pt           |         0.7px | 2,940 (+23)       | 6,382 (+37)     |
| 번호 줄 오른쪽 끝 7pt (flex) | 0.3~**3.0**px | 2,937 (+20)       | 6,383 (+38)     |

**여기서 배울 것은 「0.3px 이 9건을 넘긴다」이다.** 지면이 그만큼 빡빡하다 — 이어지는
장에서 여유가 5px 안쪽인 문항이 333건, 첫 장은 564건이다. 「작으니까 괜찮겠지」가
성립하지 않는 지면이라는 뜻이다.

> **번호 줄 오른쪽 끝(flex) 안의 3.0px 은 서술형 문항에서만 난다.** Δ>1px 인 146건을
> DB 와 대조하니 **146건 전부 `서술형`** 이었다. 번호 줄을 `display:flex` 로 바꾸면
> 「서술형 n」 배지의 안쪽 여백·테두리가 줄 높이에 **참여하게** 되기 때문이다
> (인라인일 때는 참여하지 않는다). 배지가 없는 문항은 0.3px 그대로다.

### 2.2 왜 어떤 자리는 0 이고 어떤 자리는 아닌가 — 자리마다 «크기 한도»가 다르다

같은 7pt 인데 자리에 따라 0.0 과 0.3 으로 갈린다. 크기 탓이 아니라 **그 자리가 무엇으로
높이를 정하느냐**의 차이다. 크기를 올려 가며 재면 성질이 드러난다.

**① 번호 줄 안** — 버팀목이 18px(`line-height:1`)이고, 표시가 제 줄상자로 그 밖에
삐져나온 만큼만 늘어난다.

| 표시 크기 | `line-height:normal` | `line-height:1` |
| --------- | -------------------: | --------------: |
| 6pt       |              +1.00px |     **+0.00px** |
| 7pt       |              +1.00px |         +0.33px |
| 8pt       |              +2.00px |         +0.67px |
| 9pt       |              +2.00px |     **+0.00px** |
| 10pt      |              +2.00px |         +0.33px |

9pt 가 8pt 보다 **작게** 나오는 것은 오타가 아니다. 실제 값이다 — 줄상자가 버팀목
안에 들어가느냐는 글꼴의 가로줄 위치와 반올림이 정하기 때문에 크기에 **단조롭지 않다.**
그래서 이 자리의 0px 은 **글꼴 반올림에 기댄 우연**이지 견고한 성질이 아니다.
글꼴이 바뀌면(지금 지면은 Pretendard → Malgun Gothic 으로 대체돼 그려진다) 달라질 수 있다.

**② 정답란 안** — 줄 높이를 `.answerLine`·`.checkBox`(각 16px)가 정한다. 표시가 그보다
작으면 **아무 일도 안 일어난다.**

| 표시 크기 |     6 |     7 |     8 |     9 |    10 |    12 |  14pt |
| --------- | ----: | ----: | ----: | ----: | ----: | ----: | ----: |
| 문항 세로 | +0.00 | +0.00 | +0.00 | +0.00 | +1.50 | +4.50 | +8.50 |

→ **9pt 까지 공짜, 10pt 부터 값이 붙는다.** 경계가 분명하다.

> 이 경계는 표시 쪽 `line-height` 에 따라 한 칸 움직인다. 위 표는
> `line-height:normal` 로 잰 값이고, 값을 물려받게 두면 9pt 에서 이미 +1.50px 이 된다.
> **8pt 이하는 어느 쪽이든 0px** 이라 안전한 구간이다.

**③ 풀이칸 안** — `.scratchPad` 는 `position:relative` 이고 그 안의 「SCRATCH PAD」 라벨은
이미 **절대 위치**다. 같은 방식으로 붙이면 흐름 밖이라 문항 세로에 **관여하지 않는다.**

| 표시 크기 | 6   | 7   | 8   | 9   | 10  | 12  | **14pt** |
| --------- | --- | --- | --- | --- | --- | --- | -------- |
| 문항 세로 | +0  | +0  | +0  | +0  | +0  | +0  | **+0**   |

→ **크기와 무관하게 0px.** 14pt 까지 확인했다. 이건 반올림이 아니라 **구조**다.

_(위 세 표: `npx tsx scripts/qa/measure-mark-size-budget.tsx`)_

### 2.3 §2 의 답

> **「자리 값 0px」인 배치는 있다.** 그중 **풀이칸 모서리**만이 크기와 무관하게
> 구조적으로 0 이고, **정답란 오른쪽 끝**은 **8pt 까지는 어떤 설정에서도** 0 이다
> (`line-height` 를 지정하면 9pt 까지). 번호 줄 옆은 6pt 에서 0 이지만 그건 글꼴
> 반올림에 기댄 값이라, 「0px 이니 안전하다」고 못 박으면 글꼴이 바뀌는 날 조용히
> 9건·22건이 넘친다.

## 3. 나 — 순번을 키우면 얼마나 드나

원장님 말씀 3번(「순번을 키우고 별개 서식으로」)을 그대로 만들어 재었다.
창 25px, 잰 Δ 의 최대가 20px 이라 **전수 숫자는 정확하다.**

| 배치                          |   Δ(문항당) | 이어지는 장 484px | 첫 장 405px        |
| ----------------------------- | ----------: | ----------------- | ------------------ |
| (기준선) 18px                 |           — | 2,917             | 6,345              |
| **22px** (구분선 없이)        |  **+4.0px** | 3,054 (**+137**)  | 6,585 (**+240**)   |
| **26px** (구분선 없이)        |  **+8.0px** | 3,193 (**+276**)  | 6,807 (**+462**)   |
| **26px + 구분선 + 여백 10px** | **+18.0px** | 3,577 (**+660**)  | 7,469 (**+1,124**) |
| 26px + 구분선 + 식별자 7pt    |    +18~20px | 3,590 (+673)      | 7,490 (+1,145)     |
| 〔대조군〕 문항 아래 새 줄    |     +18.0px | 3,577 (+660)      | 7,468 (+1,123)     |

읽는 법 셋.

1. **글자만 키우는 값은 싸다.** 18 → 22px 이 4px, 26px 이 8px 이다. 번호 줄은
   `line-height:1` 이라 키운 만큼만 늘고 그 이상은 안 는다.
2. **비싼 것은 구분선이 아니라 「별개 서식」의 여백이다.** 26px 단독 +8px 인데
   구분선(1px)과 아래 여백(6→10px)·안여백(5px)을 더하면 **+18px** 이 된다.
   즉 늘어난 18px 중 **10px 이 선 자체가 아니라 선 둘레의 빈 자리**다.
3. **+18px 은 한 줄(20.3px)에 가까운 값이다.** 첫 장에서 **1,124건**이 새로 넘친다 —
   지금 넘치는 6,345건이 **7,469건(15.8%)** 이 된다.

> ⚠️ 이 값은 다른 세션이 지금 고치고 있는 것과 **정면으로 부딪힌다.** ⑷+⑸-c 는
> 「지면에 들어가는 문항만 고른다」인데, 문항마다 18px 을 더 먹으면 **고를 수 있는
> 문항이 줄어든다.** 26px+구분선을 고르시면 그 수리가 돌려받은 자리의 일부를 다시 쓴다.

### 3.1 값을 치르지 않고 키우는 길

「키우고 싶다」와 「자리를 더 쓰고 싶지 않다」를 같이 만족하는 조합이 있다.

| 조합                       |          Δ | 이어지는 장 | 첫 장  |
| -------------------------- | ---------: | ----------- | ------ |
| 26px + 구분선 + 여백 10px  |    +18.0px | +660        | +1,124 |
| **26px 단독**(구분선 없이) | **+8.0px** | +276        | +462   |
| **22px 단독**              | **+4.0px** | +137        | +240   |
| **22px + 아래 여백 6→2px** |  **0.0px** | **+0**      | **+0** |

마지막 줄이 답이다. **순번을 18 → 22px 로 키우면서 넘침이 한 건도 안 는다.**
키운 4px 을 번호 아래 여백에서 그대로 돌려받기 때문이다.

> 이 줄은 처음에 「+4 와 −4 를 더하면 0」이라는 **산술로** 적었다가, 따로 만들어 다시
> 쟀다. 두 변화가 같은 줄에 걸리므로 서로 간섭할 수 있고, 산술로 적어 두면 보고서에서
> **그 줄만 아무도 확인 안 한 값**이 된다. 실측 결과 Δ 0.0px · 증감 +0 으로 산술과 같았다.

## 4. 다 — 반대로 줄일 수 있나

세 가지를 재었다. 첫째는 **모든 문항에 똑같이** 걸리고, 뒤의 둘은 **문항에 따라 요동친다.**

### 4.1 여백만 조이는 안 — 확실하게 돌려받는다

| 배치                                      |          Δ | 이어지는 장      | 첫 장            |
| ----------------------------------------- | ---------: | ---------------- | ---------------- |
| 순번 18px 그대로, **아래 여백 6px → 2px** | **−4.0px** | 2,780 (**−137**) | 6,128 (**−217**) |

지금 지면에서 **아무것도 키우지 않고** 넘침을 137·217건 줄이는 길이다. 다만 번호와
본문이 그만큼 붙으므로 **형태 판단**이 필요하다(D-07).

### 4.2 번호를 흐름에서 빼내는 안 — 세로는 벌지만 가로를 잃는다

번호 줄(24px)을 통째로 없애면서 순번은 **26px 로 키우는** 두 배치다.

| 배치                                   |    Δ 중앙 | Δ 범위         | 이어지는 장 484px        | 첫 장 405px              |
| -------------------------------------- | --------: | -------------- | ------------------------ | ------------------------ |
| (기준선)                               |         — | —              | 2,917                    | 6,345                    |
| **번호를 본문 첫 줄에 태우기** (float) | **−24px** | −47 ~ **+23**  | **2,417 (−500)**         | **5,544 (−801)**         |
| 번호를 왼쪽 여백으로 빼기              |     −24px | −42 ~ **+230** | 2,428 (−489)<sup>*</sup> | 5,470 (−875)<sup>*</sup> |

<sup>*</sup> **이 두 값만 「정확」이 아니다.** 잰 Δ 가 창(120px)을 넘었다(최대 +230px).
창 밖에서도 뒤집힌 문항이 있을 수 있어 **증감의 하한**으로 읽어야 한다. 도구가 그렇게
말하도록 만들어 두었다(§1.3) — 창을 좁게 잡고 「정확」이라고 적는 것이 이 검토에서
가장 쉬운 자기기만이다.

**둘 다 넘침을 크게 줄인다.** 첫 장에서 800건 안팎이 해소된다 — 순번을 26px 로 **키우면서**
그렇다. 「키우면 무조건 비싸다」가 아니라는 뜻이다.

**그런데 꼬리가 있다.** 본문이 놓일 가로가 34px 좁아지면서 **일부 문항이 크게 늘어난다.**

|                          | 이어지는 장            |
| ------------------------ | ---------------------- |
| Δ > 0 (되레 늘어난 문항) | 8,646건 중 **370건**   |
| Δ > 40px                 | **18건**               |
| 최대                     | **+230.3px** (약 11줄) |

늘어난 문항을 눈으로 보니 이유가 분명했다.

```
+230.3px  그림 2장 · 「그림의 □ABCD가 다음 조건을 모두 만족시킨다고 할 때 …」
+153.3px  그림 2장 · 「그림과 같이 △ABC의 외접원의 중심 O에서 …」
+112.3px  그림 5장 · 「혜리는 걸어서 집에서 출발하여 …」
 +98.0px  그림 5장 · 「다음 중 −1≤x≤1에서 정의된 …의 그래프로 옳은 것은? ① ② ④ ⑤」
 +97.9px  그림 0장 · 「다음 <보기>는 집합과 명제에 대한 설명이다 …」
```

**가로로 나란히 놓이던 그림이 세로로 쌓인다.** 한 번 쌓일 때마다 그림 한 장 높이가
통째로 붙으니 100~230px 이 된다. 마지막 한 건은 그림이 없는데도 늘었다 —
`<보기>` 상자가 좁아져 줄이 늘어난 경우다.

### 4.3 §4 의 답

> **줄일 수 있다. 세 가지 값이 다 다르다.**
>
> - **여백만 조이기**(−4px)는 **확실**하다. 모든 문항이 똑같이 4px 을 돌려준다.
>   넘침 −137·−217건. 형태 변화가 가장 작다.
> - **번호를 본문 첫 줄에 태우기**(float)는 **가장 크게 벌면서**(−500·−801건)
>   순번을 26px 로 키운다. 늘어나는 문항이 있지만 최대 +23px 로 얌전하다.
> - **왼쪽 여백으로 빼기**는 비슷하게 벌지만 **꼬리가 사납다**(최대 +230px).
>   그림이 여러 장인 문항에서 배치가 무너진다. 같은 이득이라면 float 쪽이 안전하다.

## 5. 라 — 지금 식별자를 종이에 찍어도 되는가 → **안 된다**

`scripts/qa/audit-printable-id.ts` 로 전수 판정했다. 세 가지가 각각 독립적으로 막는다.

### 5.1 모양이 하나가 아니다 — 지면을 채울 수 없다

| 모양                            |   문항 수 | 예                                     |
| ------------------------------- | --------: | -------------------------------------- |
| `숫자-숫자` (기출: 시험지-문항) |    40,237 | `5123-7`                               |
| UUID 36자 (RPM 교재)            |     4,843 | `019fd1d5-5ad6-76dd-ac5f-d8f9051c428c` |
| **없음**                        | **2,072** | —                                      |

전체 47,152건 중 **4.4% 는 `externalId` 가 아예 없다**(자작 766건 전량 + RPM 19건).
「모든 문항에 번호를 넣고 싶다」는 요청을 지금 값으로는 **못 채운다.** 그리고 한 지면에
`5123-7` 과 36자 UUID 가 섞인다.

### 5.2 번호에서 **출처가 드러난다** — 아무 사전지식 없이도

`externalId` 는 `{exam_id}-{원본 문항번호}` 다. 그래서 종이에 찍힌 코드는, 보는 사람이
아무것도 몰라도 다음을 **그대로** 말한다.

1. **같은 앞자리 = 같은 원본 시험지.** 한 시험지에 `5123-7`·`5123-19` 가 나란히 있으면
   「이 둘은 **어느 한 학교의 시험지 한 장**에서 왔다」가 드러난다.
2. **뒷자리 = 원본에서의 문항번호**(실측 범위 1~31). `-22` 는 원본 뒤쪽 문항이다.
3. **앞자리 크기 = 출제 연도.** 실측 블록: 2023년 `1097~2638` · 2024년 `2640~4208` ·
   2025년 `4210~5924`.

### 5.3 번호가 **가나다순으로 매겨져 있다** — 불투명한 값이 아니다

이게 핵심이다. `exam_id` 는 무작위가 아니라 **학교 이름 가나다순으로 훑으며** 매겨졌다.

| 적재 배치   | 시험지 | 학교 | 번호 범위 | **가나다순 일치율** | 학교당 번호폭 중앙 |
| ----------- | -----: | ---: | --------- | ------------------: | -----------------: |
| 2023-2-중간 |    191 |  146 | 1097~2638 |           **97.8%** |                  0 |
| 2023-1-중간 |    143 |   99 | 1351~2636 |           **97.1%** |                  0 |
| 2024-1-중간 |    284 |  155 | 2640~4207 |           **98.5%** |                196 |
| 2024-2-중간 |    241 |  150 | 2915~4208 |           **98.5%** |                  1 |
| 2025-1-중간 |    415 |  170 | 4211~5924 |           **98.6%** |                465 |
| 2025-1-기말 |    384 |  173 | 4210~5923 |           **98.8%** |                287 |

번호가 무작위였다면 이 값은 **50% 안팎**이어야 한다. 98% 라는 것은 번호가 학교 이름의
**정렬 위치를 그대로 담고 있다**는 뜻이다. 「학교당 번호폭 중앙 0~1」 = 한 학교의
시험지가 번호축에서 **한 자리에 붙어 있다**.

> **처음엔 이걸 놓칠 뻔했다.** 학년도로 묶어서 보니 「학교당 번호폭 중앙 380」이 나와
> 「번호가 흩어져 있다 = 안전하다」로 읽혔다. 한 학년도 안에 학기·회차 배치가 **여러 개
> 끼어 있어서** 생긴 착시였다. 배치로 갈라 보면 0~1 이다. 분모를 잘못 잡으면 같은
> 숫자가 다른 것을 가리킨다.

**되짚기 공격을 실제로 돌려 봤다.** 코드 몇 개의 출처 학교를 아는 사람이(자기 학교
기출은 알아본다) 나머지를 얼마나 좁히는가 — 배치 `2025-1-중간`(시험지 415 · 학교 170):

| 아는 코드 수 | 가나다순 몇 칸 빗나가나 | 학교를 정확히 맞힘 | ±3개 학교 안 |
| -----------: | ----------------------: | -----------------: | -----------: |
|            3 |                  55.2칸 |               0.5% |         3.7% |
|            5 |                  51.5칸 |               0.7% |         5.0% |
|           10 |                  43.6칸 |               0.8% |         7.0% |
|           20 |                  29.5칸 |               1.3% |        14.4% |
|           50 |                  15.5칸 |           **4.2%** |    **30.3%** |

(아무 정보 없이 찍으면 0.6%)

**정직하게 읽자.** 학생이 코드 50개의 출처를 알아내 학교를 콕 집을 확률은 4.2% 다 —
**교실에서 당장 벌어질 일은 아니다.** 그러나 판단의 근거는 이 확률이 아니라 **성질**이다.

- 5.2 의 세 가지는 **아는 코드가 0개여도** 드러난다. 확률이 아니라 **정의상 그렇다.**
- 5.3 은 번호가 **순서를 보존하는 값**이라는 뜻이다. 불투명한 토큰이 아니다. 표를
  가진 사람(원본 아카이브를 얻은 누구든)에게는 **정확히** 역함수가 존재한다.

### 5.4 결론 — id-scheme 세션에 넘기는 근거

> **지금의 `externalId` 는 지면에 쓸 수 없는 체계다.** 크기·색을 아무리 낮춰도 바뀌지
> 않는다. 종이에 찍을 값이 필요하면 **출처와 무관하게 새로 매긴 불투명한 번호**여야
> 한다. 조건 셋:
>
> 1. **전 문항에 빠짐없이** 있을 것 (지금은 4.4% 가 없다)
> 2. **한 가지 모양**일 것 (지금은 두 가지)
> 3. **출처·연도·원본 문항번호·가나다순 위치를 담지 말 것** — 즉 정렬 가능한 값이
>    아니라 **매김표(mapping)** 로만 풀리는 값일 것

이 셋을 만족하면 §2 의 「번호 줄 빈자리」에 그대로 얹을 수 있다. 만족하지 못하는 값을
작게 찍는 것은 **작아진 유출**이지 안전이 아니다.

## 7. 곁다리로 확인한 것 — 「숨긴다」가 만드는 구멍

원장님 결정이 「메타데이터로 숨긴다」이므로, **숨긴 것을 나중에 어떻게 꺼내 쓰는지**를
확인했다. 결론부터: **지금은 못 꺼낸다.**

### 7.1 종이만 들고 문항을 되짚을 수 있나 — 코드로 확인

지면에 **실제로 찍히는 것**(`JaseupTemplate.tsx`·`PrintAnswerKeyPage.tsx` 전수):

|        | 문제지 첫 장                                                                    | 이어지는 장 | 정답지                  |
| ------ | ------------------------------------------------------------------------------- | ----------- | ----------------------- |
| 학원명 | 오늘의수학                                                                      | 오늘의수학  | 오늘의수학 · ANSWER KEY |
| 제목   | 일일테스트 · 〈단원명〉                                                         | 같음        | 같음                    |
| 날짜   | **학습일 2026.08.18**                                                           | 없음        | **없음**                |
| 반     | `이름 ____ · 반 ____` **빈칸**                                                  | 없음        | 없음                    |
| 순번   | 문 N                                                                            | 문 N        | 문 N                    |
| 그 밖  | 서술형 n 배지 · 핵심 개념 상자 · 내 정답/채점 · SCRATCH PAD · 오늘의 메모 · p.N | p.N ×2      | 빠른 정답 · 해설 · p.N  |

**시험지 id 도 문항 id 도 지면에 없다.** 반 이름은 `TestPrintDocument` 에는 있지만
`JaseupPrintMeta` 로 넘어가지 않아 **종이에는 안 나간다**(학생이 손으로 적는 빈칸이다).

되짚는 길을 코드에서 따라가면 이렇게 끊긴다.

1. 종이 → 시험지 찾기: 단서는 **날짜 + 제목** 뿐이다. `GET /api/tests` 의 필터는
   `classId`·`studentId`·`status` — **날짜 필터가 없다**(`testDate desc` 정렬만).
   같은 날 같은 단원으로 여러 반에 냈으면 종이만으로는 **어느 반 것인지 못 가른다.**
2. 시험지 → 문항: 시험지 화면이 순번대로 보여 준다. 여기는 이어진다.
3. 문항 → 문제은행: **끊긴다.** `problemFilterQuerySchema` 는 `strictObject` 이고
   `unitId`·`grade`·`chapter`·`difficulty`·`problemType`·`source`·`reviewStatus`·
   `pool`·`hasFigure` 뿐이다 — **id 검색도 본문 검색도 없다.** 문항 상세 화면
   (`/problems/[id]`)도 없다(API `GET /api/problems/{id}` 는 있다).

> 즉 **식별자를 종이에 찍든 안 찍든, 그 값을 넣고 문항을 찾을 화면이 지금 없다.**
> 「참고용으로 작게 찍는」 안을 고르시더라도, 찾는 화면이 같이 생기지 않으면 그 숫자는
> 아무 데도 못 쓴다. 이건 지면이 아니라 **문제은행 화면**의 일이다.

### 7.2 「숨긴 메타데이터」는 인쇄에서 살아남는가 — 실측

`scripts/qa/probe-print-metadata.tsx` — 실제로 지면을 그려 PDF 로 뽑고, PyMuPDF 로
글자층과 문서 속성을 뒤졌다.

| 통로                                   | PDF(기본)         | PDF(머리글·꼬리글 켬)  | **실물 종이**           |
| -------------------------------------- | ----------------- | ---------------------- | ----------------------- |
| HTML `data-*` 속성                     | **사라짐**        | 사라짐                 | 사라짐                  |
| `<meta>` author·description·keywords   | **사라짐**        | 사라짐                 | 사라짐                  |
| `display:none` 글자                    | 사라짐            | 사라짐                 | 사라짐                  |
| `<title>` → PDF **문서 속성 `/Title`** | **남음**          | 남음(+지면 머리글로도) | 머리글 켰을 때만        |
| 흰 글씨·투명 글씨                      | **글자층에 남음** | 남음                   | **사라짐**(잉크가 없다) |
| 문서 **URL**                           | 안 찍힘           | **찍힘**               | 찍힘                    |
| 보이는 6pt 회색 글씨(대조군)           | 남음              | 남음                   | 남을 것(§6 확인)        |

읽는 법 셋.

1. **`data-*` 속성은 죽는다.** 「DOM 에 있으니 괜찮다」는 인쇄물에는 해당이 없다.
2. **살아남는 디지털 통로는 두 개뿐이다** — PDF 문서 속성(`/Title`)과, 인쇄 대화상자에서
   「머리글 및 바닥글」을 켰을 때의 **URL**. 제품의 인쇄 URL 은 `/tests/{시험지 uuid}/print`
   라, 그 체크 하나로 **시험지 uuid 가 통째로 종이에 찍힌다.** 「숨긴다」는 결정과 반대
   방향이므로 §6 의 확인 항목 7 로 넣었다.
3. **그런데 지금 `/Title` 은 비어 있다.** 인쇄 화면에 `metadata` 를 안 내보내서 제목이
   루트 레이아웃의 **「오늘의수학」** 이다. 살아남는 통로에 **식별 정보가 안 실려 있다.**

> **실물 프린터로 뽑은 종이에는 위 디지털 통로가 하나도 없다.** 종이에는 메타데이터가
> 없고 잉크만 있다. 「숨겨 두고 나중에 찾는다」가 **종이에서** 성립하려면, 눈에 보이는
> 잉크가 있거나 — 아니면 §7.1 처럼 **날짜·반·순번으로 되짚는 화면**이 있어야 한다.

## 8. 바 — 배치안 Wire (골라 주십시오)

**아무것도 확정하지 않았습니다.** 지면 형태는 전부 D-07(원장님 확정)이라, 05 §0-3 대로
Wire 를 늘어놓고 값만 붙였습니다. 아래 `5123-7` 은 **자리를 보이려고 넣은 임시 문자열**
입니다 — §5 에서 이 값은 지면에 쓸 수 없다고 판정했으므로, 실제로는 새로 매긴 번호가
들어갑니다.

세 갈래로 묶었습니다. **A·B·C 는 순번을 지금 크기로 두고 식별자만 얹는 안**,
**D·E 는 원장님이 말씀하신 「순번을 키운 별개 서식」**, **G·F 는 키우면서 자리를
안 쓰거나 되레 되찾는 안**입니다. A·B·C 는 D~G 중 어느 것과도 **겹쳐 쓸 수 있습니다**
(자리가 서로 다릅니다).

---

### A안 — 지금 그대로 + 식별자를 **풀이칸 모서리**에 〔세로 **+0px** · 넘침 **+0 / +0**〕

```
┌────────────────────────────────┬──────────┐
│ 문 3                           │ SCRATCH  │
│                                │      PAD │
│ 그림과 같이 평행사변형 ABCD에서 │          │
│ ∠A의 이등분선이 변 BC와 만나는 │          │
│ 점을 E라 할 때 …                │          │
│                                │   5123-7 │ ← 7pt 회색
│ 내 정답 ______  채점 ☐          │          │
└────────────────────────────────┴──────────┘
```

- 「SCRATCH PAD」 라벨과 **같은 방식**(절대 위치)이라 문항 세로에 **관여하지 않는다.**
- **크기를 올려도 0px** 이다(14pt 까지 확인). 세 안 중 유일하게 «구조적으로» 0 이다.
- 학생이 답을 쓰는 칸 안이라 **눈에 띄는 자리**다. 「참고용 정도」로 볼지는 원장님 판단.

### B안 — 지금 그대로 + 식별자를 **정답란 오른쪽 끝**에 〔세로 **+0px** · 넘침 **+0 / +0**〕

```
│ 내 정답 ____________  채점 ☐   5123-7 │ ← 7pt 회색, 정답란 안
```

- 이미 있는 30.5px 줄 안에 얹는다. **9pt 까지 0px**, 10pt 부터 값이 붙는다(§2.2).
- 채점하며 보는 줄이라 원장님 눈에 **가장 자주 들어오는** 자리다.
- 학생도 답을 쓰며 본다.

### C안 — 식별자를 **장 꼬리글**에 모아서 〔세로 **+0px** · 칸 **+0px** · 넘침 **+0 / +0**〕

```
   ┌ 문 3 …                    ┐ ┌ 문 4 …                    ┐
   └───────────────────────────┘ └───────────────────────────┘
   오늘의 메모 ______________   문1 5123-7 · 문2 4210-3    p. 2
```

- **문항 칸을 한 픽셀도 안 건드린다.** 이미 있는 꼬리글 줄에 들어간다
  (실측: 문항 칸 484px 그대로).
- 장마다 **두 개**만 적으면 되니 지면이 가장 조용하다.
- 대신 「이 문항이 어느 코드인가」를 **순번으로 한 번 더 짚어야** 한다.

### D안 — 순번을 **키운 별개 서식** + 그 줄 오른쪽에 식별자 〔세로 **+18~20px** · 넘침 **+673 / +1,145**〕

```
┌────────────────────────────────┬──────────┐
│ 문 3                    5123-7 │ SCRATCH  │ ← 순번 26px 굵게 / 식별자 7pt
│ ────────────────────────────── │      PAD │ ← 금색 1px 구분선
│ 그림과 같이 평행사변형 ABCD에서 │          │
│ ∠A의 이등분선이 …               │          │
│                                │          │
│ 내 정답 ______  채점 ☐          │          │
└────────────────────────────────┴──────────┘
```

「상단에 문항번호, 하단에 문제시작」이 **선으로 갈린** 모양이다. 말씀하신 모양 그대로다.

**가장 비싼 안이다.** 첫 장에서 넘침이 6,345 → 7,490건(13.46% → **15.9%**)이 된다.
늘어난 18px 중 8px 만 «키운 글자»고 **10px 은 선 둘레의 빈 자리**다(§3). 선을 유지하면서
값을 낮추려면 아래 여백을 6px 로 되돌리는 쪽(+12px)이 있고, 선을 빼면 +8px 이다.

### E안 — 순번만 **조금** 키움 (구분선 없이) 〔세로 **+4px** · 넘침 **+137 / +240**〕

```
│ 문 3                           │ ← 22px (지금 18px)
│ 그림과 같이 평행사변형 ABCD에서 │
```

### G안 — 순번을 키우되 **여백에서 그대로 돌려받는** 안 〔세로 **0.0px** · 넘침 **+0 / +0**〕

```
│ 문 3                           │ ← 22px (지금 18px) · 아래 여백 6px → 2px
│ 그림과 같이 평행사변형 ABCD에서 │
```

순번을 키우면서 **넘침이 한 건도 안 느는** 유일한 안이다(전수 실측). 키운 4px 을
번호 아래 여백에서 되돌려 받는다 — 대신 번호와 본문이 지금보다 붙는다.

### F안 — 순번을 키우면서 **세로는 되찾는** 배치 〔세로 **−24px** · 넘침 **−500 / −801**〕

```
① 본문 첫 줄에 태우기            ② 왼쪽 여백으로 빼내기
┌──────────────────────────┐    ┌──────────────────────────┐
│ 문 3 그림과 같이 평행사변 │    │ 문 │ 그림과 같이 평행사변 │
│      형 ABCD에서 ∠A의 …   │    │  3 │ 형 ABCD에서 ∠A의 …   │
└──────────────────────────┘    └──────────────────────────┘
```

번호 줄이 통째로 사라지므로 **세로를 24px 돌려받는다.** 순번을 26px 로 **키우면서도**
넘침이 500·801건 **줄어드는** 유일한 안이다.

다만 본문이 놓일 가로가 줄어 **일부 문항은 되레 늘어난다**(이어지는 장 8,646건 중 370건).
①(본문 첫 줄에 태우기)은 최대 +23px 로 얌전하고, ②(왼쪽 여백)는 **최대 +230px** 까지
튄다 — 나란히 놓이던 **그림이 세로로 쌓이기** 때문이다(§4.2). 같은 이득이면 ①이 안전하다.

## 9. 원장님께 여쭐 것

지면 형태는 D-07 이라 여기서 정하지 않았습니다. 여쭐 것은 넷입니다.

1. **자리** — 두 갈래를 따로 골라 주시면 됩니다(자리가 달라 겹쳐 쓸 수 있습니다).
   - 식별자를 **어디에** 둘까요: A(풀이칸 모서리) · B(정답란 오른쪽 끝) · C(장 꼬리글)
     — 셋 다 넘침 **+0** 입니다. 아예 안 찍는 것도 선택지입니다.
   - 순번 서식은 **그대로 둘까요, 키울까요**: 지금(18px) · E(22px, +137/+240) ·
     **G(22px + 여백 조이기, +0)** · D(26px+구분선, +673/+1,145) ·
     F(번호를 본문 첫 줄로, **−500/−801**)
2. **누가 보는가** — 식별자를 **학생 시험지에도** 찍을까요, **정답지에만** 찍을까요?
   - 정답지에만 찍으면 학생 시험지는 완전히 깨끗하고, 넘침은 **당연히 +0** 입니다.
   - 다만 원장님이 이상한 문항을 보시는 건 대개 **문제지** 쪽입니다. 그리고 지금
     정답지에는 **날짜조차 안 찍힙니다**(§7.1) — 정답지만으로는 어느 날 시험지인지도
     모릅니다.
3. **크기·색** — 「아주 작게」의 실제 크기는 §6 을 **실물로** 확인하신 뒤에 정하시는 게
   맞습니다. 특히 **복사본에서 살아남는지**는 화면으로 알 수 없습니다.
4. **번호 체계** — §5 결론대로 지금 값(`5123-7`)은 못 씁니다. 새 번호를 매기는 일은
   id-scheme 세션 몫인데, **어느 조건까지 요구할지**는 원장님 결정입니다
   (출처가 안 드러날 것 / 전 문항에 있을 것 / 한 가지 모양일 것).

그리고 한 가지 **말씀드릴 것**이 있습니다 — 여쭐 것이 아니라 지금 상태의 보고입니다.

> **어느 안을 고르셔도, 지금은 그 번호로 문항을 찾을 화면이 없습니다.** 문제은행은
> id 로도 본문으로도 검색이 안 됩니다(§7.1). 종이에 번호를 찍는 일과, 그 번호를 넣어
> 문항을 찾는 화면을 만드는 일은 **다른 작업**입니다. 번호만 찍고 화면이 없으면
> 「쉽게 찾아볼 수 있게」라는 애초 목적이 채워지지 않습니다.
