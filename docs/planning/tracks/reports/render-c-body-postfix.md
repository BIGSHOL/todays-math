## 1. 지표부터 틀려 있었다 (이 트랙의 핵심)

착수 시점의 실태 보고는 이랬다.

| 항목 | 착수 보고 | 실제 |
|------|----------|------|
| 서술형 등 라벨이 본문에 박힘 | 502건 (1.06%) | **8,436건 (17.89%)** |
| 기타 유형 라벨 | 37건 | (위에 합산) |
| HWP 수식 잔재 | 125건 | 141건 (옮길 수 있음 90 + 보류 51) |
| `$` 홀수 | 12건 | 12건 (고칠 수 있음 11 + 보류 1) |

세 번 다 **같은 모양의 실수**였고, 세 번 다 **표본을 눈으로 보고서야** 드러났다.

### 1.1 라벨 502 → 8,436 (16배)

지표의 라벨 패턴이 `[[【]\s*서\s*술\s*형\s*\d*\s*[\]】]` 였다. 그런데 실측 최빈 모양은
**`[서술형 $2$]`** 다 — 번호가 수식으로 감싸여 있다. `서술형` 다음에 `$` 가 오므로
`\d*` 가 못 받고, 패턴이 통째로 빗나간다. 넓은 그물(대괄호 안에 유형 낱말이 있으면
후보)로 다시 세니 8,502건이었다.

```
    894  "[서술형 $1$ ]"     ← 최빈. 기존 패턴이 못 셈
    891  "[서술형 $2$ ]"
    …
    113  "[서술형 2]"        ← 기존 패턴이 세던 것은 이 부류뿐
```

`[서답형 $6$]`(서답**형**)도 낱말 자체가 목록에 없어 통째로 빠져 있었다.

### 1.2 `DIVIDE` — 규칙과 지표가 **같은 자리**에서 실패했다

착수 지시문이 이미 지적한 대로 `measure-hwp-latex-residue.py` 는 `DIV` 를
`(?![A-Za-z])` 로 닫아 두어 `DIVIDE` 를 구조적으로 못 셌다. 그런데 조사해 보니
**고치는 쪽인 `hwpeq_unglue.py` 의 치환 규칙도 정확히 같은 이유로 실패하고 있었다.**

```python
# 있던 것
(re.compile(r"(?<![\\A-Za-z])DIVIDE(?![A-Za-z])"), r"\\div "),
```

HWP 원본의 실제 모양은 `xDIVIDE(-6)` · `aDIVIDEbDIVIDEc` · `4DIVIDEunder` 처럼
**양옆이 영문자**다. 즉 이 규칙은 고쳐야 할 자리마다 정확히 비켜갔다.
영문자 lookaround 는 정상 LaTeX 명령을 지키는 장치가 아니다 — 그건 백슬래시
lookbehind 가 한다. 대문자 HWP 키워드가 영어 낱말일 리는 없다.

덤으로 **소문자 `divide` 30회는 목록에 아예 없어** 0으로 보이고 있었다.
`$(-4x+8)divide\left(-2^{2}\right)$` 같은 행이 18건, 지면에 `divide` 라는 날 글자로
나가고 있었다.

### 1.3 `veca` — 같은 실수를 세 번째로 (트랙 도중에 내가 만든 지표에서)

새로 만든 지표에서도 소문자 키워드를 `(?<![A-Za-z\\])vec(?![A-Za-z])` 로 셌다.
`veca` 는 `vec` 뒤에 `a` 가 오므로 안 잡힌다 — **실측 15행이 "1행"으로 보고**됐다.

> **교훈.** HWP 잔재는 **글자에 들러붙은 것이 본모습**이다. 뒤쪽 영문자 lookahead 를
> 붙이면 지표가 "정확히 결함만 골라서" 못 본다. 세 번 다 같은 자리였다.
> 지금은 소문자 구조 키워드의 뒤쪽 가드를 전부 걷어냈고, **세는 쪽과 고치는 쪽이
> 같은 규칙 모듈(`scripts/qa/renderPostfixRules.ts`)을 쓴다.** 규칙이 못 보는 것은
> 지표도 못 보지만, 적어도 둘이 갈라지지는 않는다.

### 5.2 HWP 잔재 보류 52행

**43행 — 통째 미변환.** 변환기를 아예 안 거친 행이다. 본문이 이런 모양이다.

```
$rm ANGLE OMA= ANGLE OMB= {BOX{~~ 1. ~~}},~$$rm {bar{OA}} = {BOX{~~ 2. ~~}}$
${1} over {1 TIMES 3} + {1} over {3 TIMES 5} + CDOTS
```

`over` 는 **분자·분모 경계를 잡아야** 하고, 선택지 자리표시자 `{BOX{ 1. }}` 는 문항
구조까지 무너져 있다(선택지 번호가 수식 한가운데 박혀 있다). 키워드 치환으로는
못 살린다 — **재추출이 답이다.** 원본 시험지 경로는 `sourceFile` 에 있다.

### 5.4 라벨 ↔ `questionType` 어긋남 374행 — **다른 트랙에 넘긴다**

라벨을 떼면 지면의 「서술형 n」 표시는 `questionType` 컬럼 하나에 달린다. 그런데
두 근거가 어긋나는 행이 374건 있다. **둘은 서로 독립인 출처다** — 라벨은 원본
시험지가 인쇄한 글자고, `questionType` 은 추출 코퍼스의 `qtype` 을 `externalId` 로
조인해 채운 값이다(`backfill-question-type.ts`).

**나는 `questionType` 을 건드리지 않았다.** 그 컬럼은 다른 트랙 소유이고, 어느 쪽이
