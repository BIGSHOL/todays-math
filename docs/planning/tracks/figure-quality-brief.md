## 1. 전수 검사 결과 (재현: `python scripts/qa/measure-figure-resolution.py`)

그림 **16,122장** (`public/figures/`).

「낮다」는 픽셀 수로 판정할 수 없다 — 같은 400px 도 20mm 로 나가면 508dpi,
70mm 로 나가면 145dpi 다. 지면 규칙에서 실효 DPI 를 유도한다:

- 인쇄 그림 폭 **상한 70mm** (`printGeometry.figureMaxWidth` = 264.567 CSS px)
- 상한보다 넓으면 줄여서 70mm, 좁으면 **원본 크기 그대로**(= 96dpi)

| 지면 실효 DPI | 장수 | 비율 |
| --- | ---: | ---: |
| 96 (작아서 확대도 안 됨) | 3,282 | 20.4% |
| 100~150 (거칠다) | 4,463 | 27.7% |
| 150~200 | 3,058 | 19.0% |
| 200~300 | 3,344 | 20.7% |
| 300 이상 | 1,975 | 12.3% |

**48.1% 가 150dpi 미만.** 원본 가로 중앙값 425px.
무리별 최악은 **RPM 1,721장 중 84.7%**.

## 2. 원인은 «우리가 200dpi 로 잘랐다» 다 — 원본은 더 좋다

| | 실측 | 근거 |
| --- | --- | --- |
| RPM 교재 PDF | **벡터** (쪽당 드로잉 100~1,560개) + 81dpi 배경 한 장 | `crop-rpm-from-pdf.py` 주석에도 「교재는 도형이 벡터」 |
| RPM 오려내기 | `DEFAULT_DPI = 200` | 같은 파일 60행 |
| 기출 원본 삽입 이미지 | 실효 dpi **중앙 209** (25% 152 · 75% 318 · 최대 641) | PDF 30편 · 이미지 161장 표본 |
| 기출 오려내기 | `CLIP_DPI = 200` (`extract-all-figures.py`) | 같은 파일 35행 |

⚠️ **기출 원본의 52.8% 가 우리 200dpi 보다 높다.** 우리가 원본보다 낮게 잘라 왔다.
⚠️ 기출 그림은 **73.7% 가 JPEG**(10,608 / 14,401). 선 그림에 JPEG 는 링잉을 만든다.
   다시 자를 때는 **PNG** 로.

### 다시 렌더가 «확대»가 아니라 «새로 그리기»임을 확인했다 (RPM)

가장자리 번짐(중간 회색 비율, 낮을수록 또렷):

| 영역 | 200dpi | **600dpi 재렌더** | 200→600 확대 |
| --- | ---: | ---: | ---: |
| 77×42pt | 3.9% | **1.1%** | 4.1% |
| 65×48pt | 3.3% | **1.2%** | 4.7% |
| 243×64pt | 4.2% | **1.8%** | 4.8% |

확대는 그대로인데 재렌더만 3배 또렷해진다 = **진짜 정보가 는다.**

### 다시 자르면 어디까지 가나 (픽셀 산술)

| | 지금 | 400dpi | 600dpi |
| --- | ---: | ---: | ---: |
| RPM 1,721장 · 150 미만 | 84.7% | 6.7% | **0.4%** |
| 기출 14,401장 · 150 미만 | 43.7% | 9.1% | 2.2% |

⚠️ **기출 줄의 숫자를 그대로 믿지 마라.** 이 표는 픽셀 수 산술이다. 기출 원본은
   래스터라 **원본 dpi 가 천장**이다 — 400dpi 로 자르면 원본의 75% 를 온전히 담고,
   그보다 높은 값은 업스케일일 뿐이다. RPM 줄은 벡터라 그대로 참이다.

## 3. 일의 순서 — **다시 자르기가 먼저다**

화질 개선 모델을 먼저 돌리면, **버린 정보를 지어내게** 된다. 원본에 그대로 있는 것을
되찾는 것이 먼저고 그게 공짜이며 정확하다.

1. **다시 자르기** — 모든 그림을 원본에서 다시. **300dpi 고정**(원장님 지시 「일반화질」).
   저장은 **PNG**. 여기서 48.1% → 한 자릿수로 떨어진다.
2. **벡터로 뽑을 수 있는 것은 벡터로** — §4.
3. **그래도 낮은 것만** 화질 개선 — §5. 원본 자체가 낮은 것(표본상 기출 원본의 25% 가
   152dpi 이하)이 여기 남는다.

## 4. 벡터 (SVG)

두 갈래가 있고 **다른 물건**이다.

- **㉠ 원본 PDF 의 벡터를 그대로 뽑기** — RPM 전량과 기출의 벡터 쪽(표본 97쪽 중 18쪽)이
  대상이다. 해상도 개념이 사라진다.
  ⚠️ 실측: `page.get_svg_image()` 는 **쪽 전체**를 뽑는다(615KB · path 529개 · 배경 이미지
  포함). cropbox 로는 안 잘린다. 쓰려면 `get_drawings()` 로 **그 영역의 path 만 골라
  SVG 를 새로 짜야** 한다. 이게 이 트랙에서 가장 값어치 있는 일이다.
- **㉡ 우리 도형 엔진이 본문에서 다시 그리기** (`FigureSpec` → `F:\시험지변환기`).
  ⚠️ **닿는 범위가 좁다** — D-55 ⑻ 실측: 표본 4건 전부 채택 불가(지어냄 1 · 엔진 거부 1 ·
  AI 가 null 2), 본문에 치수 단위가 있는 문항이 9,419 중 806(8.6%)뿐이다.
  **이 트랙의 주력이 아니다.** ㉠ 이 훨씬 넓다.

## 5. 화질 개선 (Grok 세션이 맡을 부분)

**다시 그리는 것이 아니다** — 원장님 지시대로 **잡음 감소·화질 상승**이다.

실측(기출 그림 표본 400장):

| | 25% | 중앙 | 75% | |
| --- | ---: | ---: | ---: | --- |
| 중간 회색 비율(번짐) | 1.8% | 3.3% | 5.0% | |
| 점잡음 세기 | 0.85 | 1.51 | 2.68 | **3.0 초과가 20.8%** |

### 🔴 반드시 지킬 것

**화질 개선은 내용을 바꾸면 안 된다.** 각도·길이·라벨이 하나만 달라져도 답이 바뀐다.
그래서 결과마다 아래를 통과해야 한다:

1. **되돌려 대조** — 개선본을 원본 크기로 줄여서 원본과 견준다. 차이가 크면 버린다.
2. **획이 사라지지 않았나** — 원본에서 검은 픽셀이 있던 자리가 개선본에서 비면 버린다.
   가는 선·작은 라벨이 먼저 지워진다.
3. **없던 것이 생기지 않았나** — 원본에 없던 검은 덩어리가 나오면 버린다.
4. 판정은 **버리는 쪽으로** 기운다. 잘못 «개선된» 그림은 지면에서 티가 안 난다.

## 7. 절대 지킬 것 (이 저장소의 규칙)

- **제자리 덮어쓰기 금지.** 새 디렉터리에 만들고, 견주고, 바꿔치기는 **되돌리기 원장**과
  함께. 원장은 `scripts/qa/reports/*` 가 디렉터리째 무시되므로 `.gitignore` 에 `!` 줄을
  넣고 `git check-ignore -q <파일>` 이 **exit 1** 인지 확인할 것.
- **경로를 바꾸지 마라.** DB `figure_urls` 가 `/figures/...` 를 가리킨다. 파일명을 바꿔야
  하면 DB 갱신과 되돌리기 원장이 함께 가야 한다(D-31 — 쓰기는 `ALLOW_SHARED_IMPORT=1`).
- **인쇄가 바뀐다 → 절대 규칙 6.** 완료 조건은 실물 프린터 출력 검수다.
  `src/app/dev/print-check/items.ts` 에 항목을 추가할 것.
- **`git add -A` 금지.** 이 저장소는 다중 세션이 같은 트리를 쓴다 — 경로로만 스테이징.
- 「몇 % 좋아졌다」를 적을 때 **분모를 함께** 적을 것. 표본이면 표본이라고 쓸 것.
- 판정기를 만들면 **반대쪽 표본에 대 보라** — 「멀쩡한 그림에 이 규칙을 대면 «개선 필요»가
  나오면 안 된다」처럼 반증 가능한 형태로.

## 9. 🔴 크기 일관성 — 이 트랙의 **합격 조건**

> 원장님 지시: 「모든 그림이나 도형 크기가 일관성이 있어야하니까 **철저한 프롬프트화**」
> 「**svg 엔진과 연계**시켜서 일관성 있는 그림이 생성할 수 있도록」

### 지금이 왜 제각각인가 (실측)

원본 가로 픽셀이 **41px ~ 7,343px** (중앙 425). 지면은 70mm 상한으로만 자르므로
**큰 그림은 70mm, 작은 그림은 작은 채로** 나간다 — 같은 삼각형이 문항마다 다른 크기다.
지금 규칙은 「넘치면 줄인다」뿐이고 **「얼마로 그린다」가 없다.**

### 규격 — 원본 지면의 물리 크기를 따른다

교재·시험지에서 그 그림이 차지하던 **물리 크기(pt)** 가 곧 출제자가 정한 크기다.
그걸 버리지 말고 그대로 쓴다.

```
목표 인쇄 폭(mm) = min(70, 원본 rect 폭(pt) / 72 * 25.4)
출력 픽셀 폭      = 목표 인쇄 폭(mm) / 25.4 * 목표DPI
```

- `원본 rect` 는 이미 있다 — RPM 은 `source_coords`, 기출은 `figure-manifest` 계열이
  쓰는 rect. **없으면 만들지 말고 그 그림은 건너뛰고 세어서 찍는다.**
- `목표DPI` 는 **하나로 고정**한다 — **300**. 원장님 지시 2026-08-19 「엄청나게 초
  고화질까진 필요없어, 알아보기에 무리없는 일반화질」. 300dpi 는 인쇄 선 그림의
  편안한 값이고, 600 은 디스크만 네 배로 늘린다. 하나로 고정해야 척도가 같아진다.
- 이 규칙이면 픽셀 폭이 곧 물리 크기이므로, 지면에서 **같은 것이 같은 크기**로 나온다.

⚠️ 지금처럼 「원본 픽셀 그대로 → 70mm 상한」이면 척도가 그림마다 다르다.
   **픽셀이 아니라 mm 를 기준으로 삼아야** 일관성이 생긴다.

### SVG 엔진과 잇는 자리

엔진이 이미 정본을 갖고 있다 — **다시 만들지 말고 그것을 쓴다**:

| 정본 | 어디 | 무엇 |
| --- | --- | --- |
| `type_scale(vb_w, vb_h, role)` | `F:\시험지변환기\core\figure_svg.py:1024` | 글자 크기를 **짧은 변에 비례**시켜 통일(13~22 고정). role = `label`/`tick`/`small` |
| 선 굵기 | 같은 파일 | 실선 `1.4` · 보조선 `1.0` · 화살·눈금 `1.2` |
| 글꼴 | 같은 파일 47행 | `Times New Roman, Batang, serif` · 변수는 italic |
| 라벨 halo | 같은 파일 | `paint-order="stroke" stroke="#fff"` — 선 위에 겹쳐도 읽힌다 |
| `verify_figure(...)` | 같은 파일 1046행 | **라벨에 적은 값과 실제 작도를 재측정해 대조**. 안 맞으면 예외 |

⚠️ 엔진 주석에 남은 실패가 그대로 경고다 — 「크기를 호출부마다 손으로 적으면 한 그림
안에서 점 이름 15 · 각도 11 · 치수 12.5 처럼 제각각이 된다」(2026-08-13 원장님 지적).
**호출부에서 숫자를 적지 말고 `type_scale` 을 불러라.**

⚠️ `verify_figure` 없이 통과시키지 마라 — 「라벨이 15:17 인데 그림이 1:3 이면 lint 는
통과하고 학생은 틀린 그림으로 문제를 푼다」(오성중 q2·q8·s2 실측). 보기 좋은지와
맞는지는 다른 검사다.

### 일관성을 **세는** 검사 (완료 조건에 포함)

「일관되다」는 그대로는 못 센다. 아래를 지표로 삼는다:

1. **인쇄 mm 당 픽셀(척도)** 의 분포 — 전량이 목표DPI ± 2% 안이어야 한다.
   지금은 41px~7,343px 라 척도가 수십 배 벌어져 있다.
2. **글자 크기 / 짧은 변** 비율 — SVG 로 그린 것은 `type_scale` 이 보장하지만,
   래스터는 못 잰다. 래스터는 ①만 본다.
3. 표본을 **한 장에 모아 눈으로** 본다(`scripts/qa/contact-sheet.py` 가 이미 있다).
   숫자가 통과해도 나란히 놓고 봐야 어긋난 것이 보인다.

## 10. Grok 세션에 줄 **프롬프트 규격**

원장님 지시 「철저한 프롬프트화」. 화질 개선을 맡기는 각 건마다 아래를 **그대로** 넣는다.
값이 비면 그 건은 **넘기지 말고 건너뛴다**(세어서 찍는다).

```
[대상]
  파일        : public/figures/<...>.png
  원본        : <PDF 경로> 쪽 <n> · rect(pt) x0,y0,x1,y1
  목표 인쇄 폭: <mm>            ← min(70, rect폭pt/72*25.4)
  목표 DPI    : 300 (고정)
  목표 픽셀 폭: <px>            ← 목표 인쇄 폭/25.4*300
  내용        : <단원> · 본문에 적힌 치수/각도/라벨 목록

[해야 하는 일]
  잡음 감소와 선명도 회복만 한다. **다시 그리지 않는다.**
  배경은 흰색, 선은 검정. 회색조로 낸다.

[하면 안 되는 일]  ← 하나라도 어기면 그 결과는 버린다
  · 없던 선·점·라벨을 만들지 않는다
  · 있던 가는 선·작은 라벨을 지우지 않는다
  · 각도·길이·비율을 바꾸지 않는다
  · 글자를 다시 쓰지 않는다(OCR 후 재조판 금지 — 숫자가 바뀐다)

[제출물]
  · 개선본 PNG (목표 픽셀 폭에 맞춤)
  · 자기 검사 결과 3줄: 되돌려 대조 오차 / 사라진 획 수 / 새로 생긴 덩어리 수
```

⚠️ **프롬프트가 곧 계약이다.** 「알아서 예쁘게」라고 하면 모델은 다시 그린다 —
그리고 다시 그린 그림은 지면에서 티가 안 난다(D-55 ⑺: AI 가 본문에 없는
`35°·45°·25°·15°` 를 만들어 내고 엔진 검사를 통과했다).

## 12. 🔴 무엇을 SVG 로 대체할 수 있나 — **측정으로 갈렸다**

> 원장님 지시 2026-08-19: 「얼마전에 우리가 가져온 그림이나 도형들 사진의 경우 선이
> 끊겨있다던지, 굵기가 일정하지 않다던지, 말 그대로 사진의 특징이 보였음.
> **svg 엔진으로 대체가능하면 전부 엔진으로 생성하는게 더 일관성있을터.**」

원장님이 보신 「끊긴 선·들쭉날쭉한 굵기」의 원인이 **둘**이라, 어느 쪽인지 갈라야
고치는 방법이 달라진다.

1. 우리가 200dpi 로 래스터화한 흔적 → **다시 자르면 사라진다** (§2 실측: 번짐 3.9%→1.1%)
2. 원본이 애초에 스캔 사진 → 다시 잘라도 남는다

### 실측 — 원본에서 그림이 «벡터인가 사진인가»

그림 크기(35~300pt) 덩어리를 세어 벡터 드로잉과 삽입 이미지로 갈랐다.

| 출처 | 표본 | **벡터** | 삽입 이미지(사진) |
| --- | --- | ---: | ---: |
| RPM 교재 | 4권 · 덩어리 351개 | **100.0%** | 0.0% |
| 기출 시험지 | PDF 20편 · 덩어리 188개 | **8.5%** | **91.5%** |

### 그래서 이렇게 갈린다

| 갈래 | 대상 | 방법 | 결과 |
| --- | --- | --- | --- |
| **㉠ 원본 벡터를 꺼낸다** | RPM 1,721장 **전량** + 기출의 8.5%(≈1,200장) | PDF `get_drawings()` → SVG 재구성 (§4 ㉠) | 해상도 개념이 없다. 선 굵기·글자 크기를 **엔진 정본**(`type_scale`)으로 통일 가능 |
| **㉡ 엔진이 본문에서 다시 그린다** | 매우 좁다 | `FigureSpec` → 엔진 | ⚠️ D-55 ⑻: 표본 4/4 채택 불가. 본문에 치수가 있는 문항이 9,419 중 806(8.6%) |
| **㉢ 래스터 복원** | 기출의 91.5% (≈13,200장) | 300dpi 재크롭 + 잡음 감소 | 원본이 사진이라 여기가 남는다 |

**㉠ 이 이 트랙의 주력이다.** 약 2,900장(18%)이 완전한 벡터가 되고, 그것만으로
「선이 끊긴다·굵기가 다르다」가 그 무리에서는 **구조적으로 사라진다.**

⚠️ **㉡ 을 주력으로 삼지 마라.** 「엔진으로 대체 가능하면 전부」가 옳은 방향이지만,
   본문 글자만 보고 다시 그리는 길은 실측으로 닿는 범위가 좁고 **지어낸 값이
   그럴듯하게 그려져 통과한다**(D-55 ⑺: AI 가 본문에 없는 35°·45°·25°·15° 를 만들어
   내고 엔진 검사를 통과했다). ㉠ 은 원본의 좌표를 그대로 옮기므로 그 위험이 **없다**.

### ㉠ 을 할 때 반드시 붙일 것

- 뽑아낸 SVG 의 선 굵기·글자 크기를 **엔진 정본으로 정규화**한다(`type_scale`,
  실선 1.4 / 보조선 1.0). 원본마다 다른 값을 그대로 두면 일관성이 안 생긴다.
- 크기는 §9 규격 그대로 — 목표 인쇄 폭 = min(70mm, 원본 rect 물리 크기).
- **원본과 겹쳐 대조**하라. 좌표를 옮기는 일이라 틀리면 도형이 통째로 어긋난다.
  200dpi 로 렌더한 원본 크롭과 새 SVG 를 같은 크기로 그려 픽셀 차이를 세라.

### 화질 기준 (원장님 2026-08-19)

「엄청나게 초 고화질까진 필요없어」 · 「**프린트했을때 인식가능한 무리없는 화질**」
→ 래스터는 **300dpi 고정**. 벡터(㉠)는 해상도가 없으므로 이 기준과 무관하다.

## 13. ⚠️ §9 정정 — 「원본 rect 는 이미 있다」가 **틀렸다**

Grok 세션이 디스크를 직접 뒤져 잡아냈고, 확인 결과 맞다. §9 의 그 문장을 믿지 마라.

| 내가 적은 것 | 실제 (확인함) |
| --- | --- |
| 「RPM 은 `source_coords`」 | `source_coords` 는 **발문 상자**다. 오려낸 **그림 칸**은 `figure_rect()` 가 런타임에 만들고 **어디에도 저장하지 않는다**. `rpm-crop-result.json`·`rpm-figure-attach-ledger.json` 에는 경로만 있다 |
| 「기출은 figure-manifest 계열의 rect」 | `figure-manifest.json` 에 `rect` 키가 **0건**. 대장은 `{"2658": {"13": ["/figures/2658/q13.png"]}}` 뿐이다. rect 는 `map-figures.map_exam()` 이 만들고 **버린다** |

**그래서 §9 의 물리 크기 규격을 쓰려면 원본 PDF 를 다시 매핑해야 한다.**
대장만 보고는 못 한다. 이것이 1단계의 진짜 비용이다 — 「그냥 dpi 만 올리면 된다」가 아니다.

## 14. 🔴 인쇄 쪽도 같이 바꿔야 한다 (Grok 이 짚은 결합)

`printOverflow.ts:157` 은 **픽셀 폭**으로 배율을 정한다:

```ts
const scale = figure ? Math.min(1, figureMaxWidth / figure.width) : 1;
```

즉 지금 규칙은 「픽셀이 264.567 을 넘으면 70mm 로 줄이고, 아니면 픽셀 그대로(96dpi)」다.

⚠️ **그래서 300dpi 로 다시 자르면 작은 그림이 오히려 커진다.** 지금 200px 인 그림은
   96dpi 로 작게 나가는데, 300dpi 로 다시 자르면 600px 이 되어 264 를 넘고 **70mm 로
   확대**된다. 자르기만 고치면 **지면의 그림 크기가 통째로 달라진다.**

→ 인쇄 쪽이 **픽셀이 아니라 물리 크기**를 보게 바꿔야 §9 의 일관성이 성립한다.
   그림마다 「인쇄 폭(mm)」을 들고 다녀야 한다 — 파일 이름·별도 대장·메타데이터 중
   어디에 둘지는 이 트랙에서 정하라. **인쇄가 바뀌므로 절대 규칙 6(실물 검수)이다.**

## 15. 침묵하는 계수기 (Grok 이 찾음)

`extract-all-figures.py` 는 `stat["클립 렌더"]` 와 `"xref 못찾음"` 을 **올리기만 하고
마지막 출력에서 찍지 않는다**(164–166행은 「그림없음:편」·「실패:편」만 찍는다).
그래서 **네이티브 추출 vs 200dpi 폴백 비율이 로그에 안 나온다** — §6 첫째가
안 재지는 이유가 이것이다. 재려면 같은 편 목록으로 `map_exam()` 만 돌려
그림마다 `xref` 있음/없음을 세라(쓰지 말고 세기만).

⚠️ **파일 확장자로 나누지 마라** — JPEG 는 대개 네이티브지만 PNG 는 네이티브와
   폴백이 섞인다.
