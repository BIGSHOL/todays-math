## 0.2 이 트랙이 시작하며 바로 본 배선 구멍

적재만 하고 출제·인쇄 배선을 안 고치면 **숫자가 0 으로 나온다.** 그건
「영향이 없다」가 아니라 **값이 안 흘러간다**는 뜻이다.

| 자리 | 이 실행 시작 때 | 이 실행에서 한 일 |
| --- | --- | --- |
| `assessSeat` / `parseFigureDimensions` | `figureSourceMm` 을 **받는다** | 그대로. ④는 이 함수를 직접 불렀다 |
| `risksTightSeat` → `selectProblems` | **안 넘겼다.** 필드도 없었다 | **넘기게 고쳤다.** 테스트가 잠근다. 배선 전 시뮬 0장 → 배선 후 **1,321장** 선정이 달라짐 |
| `findEligibleProblems` | `content`·`figureUrls`·`figureDims` 만 | **select 에 mm 을 안 넣었다.** 컬럼이 없어서 넣으면 출제 조회가 죽는다. 주석으로 순서를 박음 |
| 인쇄 `tests/[id]/print/page.tsx` | `figureDims` 만 매핑 | **매핑 안 넣음** (같은 이유). 주석으로 순서를 박음 |
| `schema.prisma` | `figureSourceMm` **없음** | **안 넣음.** 마이그레이션 SQL 만 있다 |

🔴 **적용 순서 (인쇄 트랙 §6.1 과 같음, 한 글자도 바꾸면 안 된다)**

1. 마이그레이션 SQL 을 DB 에 적용
2. `schema.prisma` 에 `figureSourceMm Float[] @default([]) @map("figure_source_mm")`
3. `npx prisma generate`
4. `findEligibleProblems` select 에 `figureSourceMm: true`
5. 인쇄 페이지 매핑 `figureSourceMm: item.problem.figureSourceMm`
6. 컬럼이 있는 상태로 적재 드라이런을 **다시** 돌려 `before` 를 실제로 읽는다
   (`beforeIsInferred: true` 인 원장으로 `--apply` 하지 말 것)
7. `ALLOW_SHARED_IMPORT=1 … --apply`

1~5 없이 6만 하면 값은 DB 에 있는데 출제·지면은 오늘과 같다.
2를 1보다 먼저 하면 인쇄가 통째로 죽는다.

### ① 원장이 얼마나 낡았나

원장을 만들 때 집계는 「디스크 16,119 · 원장에 안 담긴 파일 0」이었다.
**지금 이 워크트리 디스크는 16,146장**이다.

| | 장수 |
| --- | ---: |
| 원장에 있고 디스크에도 있음 | 16,119 |
| 원장에 있는데 디스크에 없음 | **0** |
| 디스크에 있는데 원장에 없음 | **27** |

27장은 전부 `pdf-qNN` (19) · `hwppdf-qNN` (8) 이고, 시험지 폴더 **21개**다.
지시서가 「다른 트랙이 기출 그림 21건을 회수해 넣었다」고 한 그 자리로 보인다.
파일 수가 21이 아니라 27인 이유는 같은 문항에 `pdf-` 와 `hwppdf-` 가 같이
생긴 폴더가 여섯이기 때문이다.

앞 20: `2085/hwppdf-q15.png`, `2085/pdf-q15.png`, `2384/pdf-q06.png`,
`3284/hwppdf-q15.png`, `3493/hwppdf-q15.png`, `3493/pdf-q15.png`, …

이 27장은 원장에 없으므로 **mm 를 모른다.** 출제 가능 「하나도 없음」의
`pdf-` 23장 · `hwppdf-` 14장 안에 섞여 있다. 이번엔 원장을 다시 만들지 않았다.

그림화질 워크트리 `public/figures` 는 **16,104장** — 이 WT 보다 42장 적다.
같은 27 + 그 사이 다른 회수분이 이 WT 에만 있는 것으로 보인다. 픽셀이
같은지는 **안 쟀다.**

## 3. 단계 2 — 래스터 바꿔치기 (설계만, 실행 안 함)

**무엇을:** `public/figures` 에서 가로 픽셀이 늘어난 **2,526장만** 300dpi 본으로
바꾼다. 그대로인 11,385장은 용량만 늘고 화질 이득 0.

**§1 ⑴:** 파일 교체와 `figure_dims` 갱신은 **한 몸**. 치수 갱신은 있는 스크립트
`backfill-figure-dimensions.ts` 를 그대로 쓴다. 다시 만들지 않는다.

제안하는 순서 (확정 뒤):

1. 단계 1 이 **끝난 뒤**. mm 이 있으면 인쇄 폭은 픽셀이 아니라 mm 이라
   파일이 촘촘해져도 **지면 크기는 안 바뀐다.** 그게 이 순서를 고른 이유.
2. `--from <그림화질/public/figures-300>` 옵션. 그 트리는 이 워크트리에 없다.
3. 되돌리기 원장을 **먼저** 쓴다. 행마다: 상대경로 · 옛 md5 · 새 md5 · 옛 치수 ·
   새 치수. `git check-ignore -q` exit 1 을 확인.
4. 옛 파일은 **지우지 말고 옮긴다** (`public/figures-pre300/` 같은 보관 위치).
   `fs.rmSync` 금지 (한글 경로에서 Node 가 죽는다).
5. 옮긴 직후 `backfill-figure-dimensions.ts --apply` 로 그 URL 들의 dims 를
   파일에서 다시 읽는다. 둘 사이에 출제가 끼면 자와 지면이 갈라진다.
6. 검산: 제품 `figurePrintWidthPx`(mm 있는 문항) 전후 폭이 **0건** 달라야 한다.
   mm 없는 문항은 픽셀 규칙이라 바뀌는 장이 생긴다 — 그 수를 **세서** 적고,
   2,526 안에 mm 없는 장이 있으면 단계 1 으로 못 막은 자리다.

위험:

- 확장자가 JPEG→PNG 로 바뀌면 `figureUrls` 경로가 달라져 DB 도 같이 고쳐야 한다.
  어제 스크립트는 어간으로 짝을 찾는다. URL 이 바뀌면 mm 배열 짝도 흔들린다.
- 이 WT 16,146 vs 그림화질 옛 16,104. 42장의 정체(①의 27 + α)를 바꿔치기
  명단에 넣지 말 것. 300dpi 본이 없다.
- 공유 DB 의 `figure_dims` 를 이 스크립트와 치수 적재가 **둘 다** 만진다.
  되돌릴 때는 **지금 값이 자기가 쓴 값일 때만.**

## 4. 단계 3 — SVG 전환 (설계만, 실행 안 함)

손에 있는 것: `public/figures-svg/` **2,467장** (기출 888 · RPM 1,579).
파일 스스로 `width="…mm" height="…mm"` 를 들고 있다 (표본 3장 모두 상한
70.000mm — 원본이 70mm 이상인 장).

`figureSvg` 컬럼은 **엔진이 그린 문자열 하나**라 원본 여러 장을 못 담는다.
바꾸려면 `figureUrls` 를 `.svg` 경로로 바꾸는 쪽이 맞다.

지시서가 물은 것:

| 질문 | 설계안 (미확정) |
| --- | --- |
| `.svg` 는 픽셀 치수가 없다. `figure_dims` 를 무엇으로 채우나? | **mm 를 아는 것만** 전환한다. 자는 mm 로 폭을 정하고, 비율은 **지금 래스터 dims** 를 유지한다 (출처가 다른 두 근거 — `figurePrintSize` 주석과 같음). SVG 파일에서 dims 를 다시 읽으면 70mm@96dpi=264px 로 뭉개져, mm 없는 경로가 전부 70mm 가 된다. |
| mm 를 모르는 SVG 는? | **전환하지 않는다.** SVG 의 내장 `width="70mm"` 가 인라인 style 없이 나가면 작은 원본이 70mm 로 커진다. |
| `<img src="*.svg">` 가 제품에서 나오나? | 앞 세션 80/80 은 **별도 하니스**다. 제품 `ProblemContent` 는 이미 `<img src={url}>` 이라 확장자만 바꾸면 같은 태그다. **확정 뒤 제품 컴포넌트로 다시 확인**한다. |
| 한 문항 여러 장 중 일부만 SVG? | mm 일부만 있는 것과 같다 — **통째로 안 바꾼다.** 문항 단위 전량 건수는 이번 실행에서 **못 셌다.** |
| 116MB 를 `public/` 에 더 얹히나? | 얹힌 상태다 (이미 이 워크트리에 2,467장). 옛 래스터는 **남긴다.** 지우면 되돌릴 파일이 없다. |
| 되돌리기 | `figureUrls` 의 옛 경로를 원장에 적는다. 단계 1 과 같은 게이트·「우리가 쓴 값일 때만」. |

위험:

- SVG 내장 mm 과 DB `figure_source_mm` 과 인라인 style 이 **세 곳**이 된다.
  제품 폭은 인라인 style (`figureWidthStyle`) 한 곳이어야 한다. SVG 내장 값은
  폴백일 뿐 — mm 없는 전환을 막아야 폴백이 거짓 70mm 를 안 만든다.
- 기출 벡터 888장은 대부분 **표·상자**이지 도형이 아니다 (벡터 트랙 §9).
  전환의 이득은 「선이 끊긴다」가 아니라 **글자가 또렷해진다.**
- `/figures-svg/…` 를 미들웨어가 `/figures/**` 처럼 막을 수 있다. 인쇄 측정이
  `/figures/**` 307 을 우회했던 자리. 확인 전에 전환하면 지면이 빈 그림이 된다.

→ **실행하지 않는다.** 원장님이 「SVG 로 바꿔라」를 정하신 뒤에, 문항 단위
전량 건수부터 센다.

「mm 가 있으니 파일을 바꿔도 지면 크기가 안 바뀐다」고 했는데, 그건 **mm 를 아는
문항에만** 참이다. mm 를 모르면 폭이 `min(70mm, 픽셀/96·25.4)` 라 **픽셀이 늘면
지면에서 커진다**(191→349px, 50.5mm → 70mm). 화질 작업이 조판을 바꾸면 안 되므로
그 한 장을 뺐다. — 이 부류가 1,345자리 중 **9자리**뿐이라 나머지 8은 우연히
폭이 같았다. 표본이 조금만 달랐으면 못 봤을 자리다.

### 9.3 바꾼 뒤 네 가지를 세어 확인했다

| | 결과 |
| --- | --- |
| ① 디스크가 정말 새 파일인가 (md5) | **1,344 / 1,344** · 옛 파일 보관 1,344 |
| ② DB 치수 == 디스크 파일 | **1,249 / 1,249** 어긋남 0 |
| 🔴 ③ **지면 폭이 달라진 자리** | 1,641자리 중 **0** ← 합격 조건 |
| ④ 이 무리의 150dpi 미만 | 879 → **418** |

③ 이 이 트랙의 뜻이다. **단계 1 을 먼저 한 것이 이걸 만든다** — 순서를 반대로
했으면 파일을 바꾸는 순간 지면이 한 번 요동쳤다.

### 9.4 되돌리기를 **시험해 봤다**

드라이런 1,344/1,344 복구 가능. 그리고 원장의 `newMd5` 와 치수 `after` 를 한
행씩 망가뜨려 「그 뒤 다른 트랙이 또 바꿨다」를 흉내 내니 **그 한 건씩만 정확히
건너뛴다.** 시험 안 해 본 되돌리기는 되돌리기가 아니다.

옛 파일은 지우지 않고 `public/figures-backup-300swap/` 로 **옮겼다**
(`fs.rmSync` 는 한글 경로에서 노드를 죽인다). 그 디렉터리는 커밋하지 않는다 —
git 이 `public/figures` 를 추적하므로 같은 그림이 두 벌 쌓인다.

### 9.5 변이 시험

가드 다섯을 하나씩 끄니 **다섯 다 빨강**(`scripts/qa/mutate-swap.sh`):
가로가 늘었나 · 확장자가 달라지나 · 바이트가 같나 · 고아인가 · 지면 폭이 달라지나.

### 9.6 남은 것

- **실물 검수** — `/dev/print-check` 에 `figure-raster-300dpi` 를 「대기」로 넣었다.
  볼 것: 또렷해졌는가 · **크기가 종전과 같은가**(0건이어야 한다) · 다시 오리며
  가장자리가 잘리지 않았는가 · 안 바꾼 그림과 섞였을 때 거슬리지 않는가.
- 확장자가 달라지는 **11장** — `figureUrls` 를 바꾸는 일이라 따로 해야 한다.
- **고아 1,172장** — 나중에 그림 회수 트랙이 이 파일들을 문항에 붙이면
  **낡은 파일이 붙는다.** 그때 `survey-figure-swap.py` → `swap-figure-files.ts` 를
  다시 돌리면 된다(계획은 커밋되어 있다).
- 사진처럼 흐릿한 그림은 이 작업으로 **안 나아진다** — 원본이 스캔이라
  다시 오려도 같은 화소다. 벡터(단계 3)가 다음 수다.
