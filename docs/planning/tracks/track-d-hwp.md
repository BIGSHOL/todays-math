# 트랙 D — HWP 원본 재추출 (뒤늦게 열린 정본 경로)

`docs/planning/tracks/README.md` 의 공통 규칙을 먼저 읽어라. 그 규칙이 이 문서보다 우선한다.

## 발견 — 본문을 PDF 에서 뽑을 이유가 처음부터 없었다

`scripts/qa/extract-final-batch.py` 를 보면

- **180행** `doc = textlayer.extract(pathlib.Path(p["pdf"]))` — 본문은 **PDF 텍스트 레이어**
- **186행** `answers = hwp_answers(p["hwp"], work)` — HWP 는 **정답만**

그런데 `scripts/vendor/testchanger/hwp_extract.py` 를 직접 돌려 보면 문항마다
`stem` · `choices` · `answer` · `topic`(소단원) · `score`(배점) · `type` · `solution`(해설)
이 **전부** 나온다. 한컴오피스 COM 도 이 컴퓨터에서 동작한다(2026-08-16 확인).

```
python scripts/vendor/testchanger/hwp_extract.py "<hwp 경로>" -o out.json
```

완료본 짝 2,950편 중 **2,944편에 HWP 가 있다**(`scripts/qa/reports/final-pairs.json`).

## 이게 왜 중요한가 — 원장님이 직접 짚은 세 건

| 문항 | 폐기 목록의 판정 | 실제 |
|------|------------------|------|
| 국제고 2697 | "본문 결손" 2건 | 원본은 8문항. DB 2건이 **둘 다 해설 지면 텍스트** |
| 강북고 2928-19 | "해설만 들어 있음" | 문제는 PDF 4쪽에 멀쩡. **1~12번 본문은 통째로 "정답" 두 글자** |
| 현풍고 2900-18 | "원본 모순 — OCR 훼손" | **훼손 아님.** HWP 원문 그대로. 판정이 틀렸다 |

원인은 하나다. PDF 뒤쪽 해설 지면에도 `1.` `2.` 줄머리가 있는데 추출기가 **뒤에 나온 것을
남겨서** 해설이 앞쪽 문제를 덮었다. (같은 성질의 버그를 `extract-official-answers.py`
에서 이미 한 번 잡았다 — 그 주석을 읽어라.)

## 규모는 부풀리지 마라 — 실측

표본 25편에서 **문항 개수는 HWP 520 vs PDF 513 으로 거의 같다.** 24/25 편은 개수가 정확히
일치했다. **대부분의 시험지는 PDF 경로로도 제대로 나왔다.** 강북고·국제고 같은 붕괴는 소수다.

HWP 의 값어치는 개수가 아니라 **수식의 온전함**이다. PDF 경로가 만들어 낸 실제 훼손:

```
f(x)=∈∉⊂^{∩}_{∩}(ax-an)/(x-2) ...      ← 경우 나눔 중괄호가 PUA 쓰레기로
\frac{2227777}{45_{2}(6×6×6)(5+5+5+5)}  ← 쌓인 식이 분수로 뭉개짐
```

폐기 후보 515건 중 **215건이 HWP 원본을 갖고 있다**: 수식 훼손 80 중 52,
증명·작도형 74 중 72(HWP `solution` 이 "해설참조" 를 대체할 수 있다), 해설지 적재 8 전부,
본문 결손 54 중 25, 그림 없음 285 중 46.

## 할 일

### D-1. 전량 HWP 추출 — 토큰 0, 오래 걸린다. 먼저 걸어 둬라

2,944편을 `hwp_extract.py` 로 뽑아 `scripts/qa/reports/hwp/<examId>.json` 에 쌓아라.
HWP COM 은 단일 인스턴스라 병렬이 잘 안 될 수 있다 — 먼저 10편으로 소요를 재고,
병렬이 되는지 확인한 뒤 규모를 정해라. 재개 가능해야 한다(이미 있는 파일은 건너뛴다).
**진행 상황을 주기적으로 보고해라.** 사람이 지켜볼 수 있어야 한다.

### D-2. 어느 문항이 PDF 때문에 망가졌는지 판정하라 — **여기가 핵심**

전부 갈아엎지 마라. **HWP 가 확실히 나은 것만** 교체한다. 판정 근거를 규칙으로 세워라.
확실한 신호부터:

- DB 본문이 30자 미만 (실측 24건 — 강북고 12건 포함)
- DB 본문에 해설 냄새(`따라서` `이므로` `대입하면` `위의 식`)가 짙은데 문제 냄새가 없다
- DB 본문에 PUA 잔재(`∈∉⊂` 연쇄, `\ue0` 계열)나 뭉개진 분수
- HWP 문항 수 > DB 행 수 (국제고 8 vs 2)
- HWP `stem` 과 DB 본문의 유사도가 바닥

**반대 방향도 반드시 보라**: HWP 쪽이 더 나쁜 경우가 있는지. 예컨대 워터마크가 본문
가운데 끼어드는 걸 실측했다(현풍고 18번 stem 안에 `대구광역시 내신 수학 연구회`).
교체가 개선인지 개악인지 **표본 30건을 눈으로 확인**하고 숫자를 내라.

### D-3. 수식 표기를 맞춰라

HWP 는 한글 수식 스크립트로 준다 (`int _{} ^{} {...}`, `LEFT (`, `over`, `pi`).
DB 는 KaTeX 가 읽는 `$...$` LaTeX 다. **변환기 없이 그대로 넣으면 지면이 깨진다.**
testchanger 에 이미 변환 로직이 있는지 먼저 찾아라(`scripts/vendor/testchanger/`,
`F:\시험지변환기`). 없으면 만들되, `renderKatexSafe` 기준으로 **렌더 성공률을 측정**해라.
CLAUDE.md 의 KaTeX 교훈(unknown command 가 `.katex-error` 가 아니라 `#cc0000` 으로 난다)을
반드시 읽어라.

### D-4. 덤으로 열리는 것들 — 확인만 하고 해당 트랙에 넘겨라

- **소단원(`topic`)**: 표본 25편 중 HWP 에 topic 이 있는 건 520 중 162. 폴더마다 갈린다
  (10-handoff.md B단계 기록과 일치). 지금 매핑이 빈 문항을 채울 수 있는지 세어만 봐라.
- **배점(`score`) · 유형(`type`)**: `problemType='서술형'` 라벨이 못 미더웠던 문제
  (실측 95% 가 `[서술형 N]` 배점 머리표였다)를 여기서 정본으로 바로잡을 수 있다.
- **해설(`solution`)**: 증명·작도형 72건의 "해설참조" 를 대체할 수 있다 → 트랙 B 에 넘겨라.
- **그림**: HWPX 는 zip 이고 `BinData` 에 원본 이미지가 들어 있다. PDF 오려내기보다
  정확할 수 있다 → **트랙 A 에 넘겨라.** 직접 손대지 마라.

## 완료 기준

- HWP 추출 N / 2,944 편, 실패 사유별 집계.
- 「교체 대상 M 건 / 그대로 둘 것 K 건」이 규칙과 표본 검증으로 갈렸는지.
- 교체 후 KaTeX 렌더 성공률이 **떨어지지 않았음**을 숫자로.
- 폐기 후보 515건 중 몇 건이 되살아났는지.
- 쓰는 컬럼은 `content` `choices` `problemType` 뿐. `answer` 는 트랙 B, `figureUrls` 는
  트랙 A, `externalId` 는 트랙 C 소관이다 — **넘겨라, 직접 쓰지 마라.**
- dry-run 기본 + `ALLOW_SHARED_IMPORT=1` 게이트. 되돌릴 수 있게 교체 전 본문을 백업해라
  (`scripts/qa/backup-transformed-content.ts` 가 선례다).
