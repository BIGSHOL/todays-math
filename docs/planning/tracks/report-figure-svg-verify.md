## 0. 한 줄

수치로 거른 채택 후보(그림 자리 **1,576** · 문항 1,526)에서 **20자리를 눈으로 봤고
결함 3 + 미관 저하 1** 이 나왔다. 그중 하나는 **래스터와 전혀 다른 그림**이다.
비율 가드(2%)는 필요하지만 **충분하지 않다** — 다른 그림이라도 비율은 우연히 맞는다.

## 2. 🔴 채택 후보에서 나온 결함

그림 두 장을 나란히 놓고 봐야만 나온다.

## 3. 깨끗했던 것

무작위 6장(내접 정사각형 · 삼각형 두 개 · 도수분포표 · 보기 상자 · 좌표그래프 ·
각 20°/58° 삼각형)과 의심도 상위 중 10장은 **꼭짓점 이름·치수·눈금·직각 표시·
채움이 다 남아 있었다.** 오히려 래스터에 있던 워터마크 얼룩이 SVG 에는 없다.

**일관된 차이 하나**: SVG 의 선이 래스터보다 **가늘고 연하다.** 내용 누락이 아니라
원본 교재의 진짜 선 굵기로 보이지만, **종이에서 흐릴 수 있다** — 실물 검수 항목이다.

## 4. 막힌 171자리 — SVG 가 틀린 건가 래스터가 틀린 건가

**둘 다 있다.** 4장을 봤다:

| 시트 | 판정 |
| --- | --- |
| `0001` 포물선 | **SVG 가 틀림** — 래스터 `y=-x²+15` 인데 SVG 는 `y=-x²`. **`+15` 가 잘렸다** |
| `0141` 벤 다이어그램 | **SVG 가 틀림** — 래스터는 벤 다이어그램, SVG 는 «명제 참/거짓 표». 비율 차이가 **6.73%** 뿐이었다 |
| `0120` 선분·각 | **SVG 가 틀림** — 선분 A—B 하나가 통째로 빠졌다 |
| `0060` 원과 접선 | **래스터가 틀림** — 래스터에 문항 번호(0597)와 발문이 통째로 들어가 있고 그림은 구석에 눌렸다. **SVG 가 더 낫다** |

→ 막아 두는 것이 맞다(3/4 가 SVG 결함). 다만 **`0060` 같은 「래스터가 나쁜 크롭」이
섞여 있다** — 그건 SVG 채택이 아니라 **그림 회수** 쪽에서 다룰 일이다.

🔴 **`0141` 이 문턱을 정당화한다.** 6.73% 에서 이미 «전혀 다른 그림»이 나온다.
문턱을 10% 로 뒀으면 그게 시험지에 나갔다.

## 5. 선별기 — 그리고 내가 빠진 함정

`scripts/qa/screen-svg-diff.mjs` 는 **훑는 순서만** 정한다(판정하지 않는다).
이 저장소가 겹쳐 보기 지표에 세 번 속았기 때문이다.

🔴 **처음 만든 의심도가 한 방향이었다** — `max(0, 1 - 잉크비)` 로 **잉크가 줄어든
쪽만** 봤다. 그랬더니 `0141`(전혀 다른 그림, 잉크비 **1.87**)이 하위 40%(105/171위)에
묻혔다. **손상이 임계값을 «정상» 쪽으로 민다**는 그 함정에 그대로 빠진 것이다
(CLAUDE.md 2026-08-16·17). `|ln(잉크비)|` 로 고치니 56위로 올라왔다.

고친 뒤에도 상위는 **선 굵기 차이**에 지배된다(가장 의심스럽던 두 장이 둘 다
깨끗했다 — 래스터의 두꺼운 테두리가 잉크량을 지배). 그래도 **진짜 결함 둘을
칸차 1·2위로 올렸으니** 순서 정하는 용도로는 쓸모가 있다.

## 6. 🔴 권고

**전량 적용하지 마라.** 근거는 `1410` 하나로 충분하다 — 학생이 못 푸는 정도가
아니라 **다른 문제의 그림**이 지면에 나간다.

선택지:

1. **전량 눈으로 본다** — 1,576자리. Grok 에 두 번 맡겼는데 두 번 다 35분 넘게
   아무것도 안 냈다(CLI 자체는 멀쩡하다 — 따로 찔러 보면 즉답한다).
   다른 방법이 필요하다.
2. **본 것만 채택한다** — 확인된 자리만 화이트리스트로. 지금은 16자리뿐이라 의미가 없다.
3. **채택을 접는다** — 래스터 300dpi 바꿔치기(단계 2)로 이미 화질은 올렸다.
   벡터의 추가 이득은 «글자가 더 또렷하다» 정도다.

원장님 결정이 필요하다. 어느 쪽이든 **적용 스크립트는 준비되어 있고
`--blocklist` 없이는 적용을 거부한다**(`scripts/qa/adopt-figure-svg.ts`).
