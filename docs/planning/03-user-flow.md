# User Flow (사용자 흐름도) — 오늘의수학

> Mermaid 플로우차트로 핵심 기능의 주요 여정을 표현합니다.
> 성공/실패 분기를 포함하고, 온보딩→핵심작업→리텐션 루프를 표현합니다.

---

## MVP 캡슐

| # | 항목 | 내용 |
|---|------|------|
| 1 | 목표 | 진도만 입력하면 수학 일일/확인테스트가 5분 안에 완성되어, 매일 30분~1시간을 되찾는다 |
| 2 | 페르소나 | 반별·학생별 진도가 다른 동네 수학학원 원장/강사 |
| 3 | 핵심 기능 | FEAT-1: 진도 기반 자동 출제 |
| 4 | 성공 지표 (노스스타) | 주 5일 이상 실제 사용 |
| 5 | 입력 지표 | ① 진도 입력→인쇄까지 5분 이내 ② 무수정 사용률 80% |
| 6 | 비기능 요구 | 수식이 깨지지 않는 A4 인쇄 품질 |
| 7 | Out-of-scope | 학생용 앱, 자동 채점, 모바일 앱, 결제 |
| 8 | Top 리스크 | AI 생성 문제 품질로 인한 검수 부담 |
| 9 | 완화/실험 | 검수 화면 1클릭 교체 + 무수정 사용률 측정 |
| 10 | 다음 단계 | /tasks-generator로 TASKS.md 생성 → Phase 0 시작 |

## 1. 전체 사용자 여정 (Overview)

핵심 루프: **진도 입력 → 자동 출제 → 검수 → 인쇄 → (수업) → 진도 갱신 → 다시 자동 출제**

```mermaid
graph TD
    A[접속] --> B{로그인 상태?}
    B -->|No| C[FEAT-0: 로그인/가입]
    B -->|Yes| D[메인: 오늘의 테스트 목록]
    C --> D

    D --> E{준비된 테스트 있음?}
    E -->|Yes| F[FEAT-1: 테스트 검수]
    E -->|No| G[FEAT-4: 반/진도 확인]
    G --> H[FEAT-1: 자동 출제 실행]
    H --> F

    F --> I{문제 OK?}
    I -->|일부 교체| J[문제 1클릭 교체]
    J --> F
    I -->|Yes| K[FEAT-3: 인쇄]

    K --> L[수업 진행 - 오프라인]
    L --> M[FEAT-4: 진도 갱신]
    M --> N[다음 테스트 자동 준비]
    N --> D
```

## 2. FEAT-0: 온보딩/로그인 플로우

최초 가입 시 반·학생 등록까지가 온보딩입니다. 진도 데이터가 있어야 자동 출제가 가능하기 때문입니다.

```mermaid
graph TD
    A[시작 화면] --> B{신규/기존?}

    %% 신규 사용자 — 가입 수단은 이메일 하나뿐(소셜 로그인 제거 2026-08-14)
    B -->|신규| D[이메일 가입]
    D --> F[이메일/비밀번호/이름 입력]
    F --> G[가입 완료]

    G --> H[온보딩: 반 만들기]
    H --> I[온보딩: 학생 등록 - 이름만]
    I --> J[온보딩: 현재 진도 지정]
    J --> K[메인 화면]

    %% 기존 사용자
    B -->|기존| L[로그인]
    L --> M{성공?}
    M -->|Yes| K
    M -->|No| N[에러 표시: 간결한 안내]
    N --> L
```

## 3. FEAT-1: 진도 기반 자동 출제 플로우 (핵심)

```mermaid
graph TD
    A[출제 시작] --> B{대상 선택}
    B -->|반 전체| C[반 선택]
    B -->|개별 학생| D[학생 선택]

    C --> E[진도 확인 - 자동 표시]
    D --> E

    E --> F{테스트 유형}
    F -->|일일테스트| G[오늘 진도 범위]
    F -->|확인테스트| H[누적 범위 - 시작/끝 단원 지정]

    G --> I[출제 조건 확인<br/>문항 수 / 난이도 배분 - 기본값 제공]
    H --> I

    I --> J[자동 출제 실행]
    J --> K{문제은행에 충분?}

    K -->|Yes| L[출제 완료: 검수 화면]
    K -->|No| M[부족 안내]
    M --> N{AI 생성 실행?}
    N -->|Yes| O[AI 문제 생성 - 진행 표시]
    O --> L
    N -->|No| P[문항 수 축소 제안]
    P --> L

    L --> Q{문제 검수}
    Q -->|교체| R[해당 문제 1클릭 교체<br/>중복 제외 자동 적용]
    R --> Q
    Q -->|승인| S[테스트 확정]
    S --> T[FEAT-3: 인쇄로 이동]
```

**중복 방지 규칙**: 최근 N일(기본 14일) 내 같은 반/학생에게 출제된 문제는 자동 제외.

## 4. FEAT-3: 시험지 인쇄 플로우

```mermaid
graph TD
    A[테스트 확정] --> B[인쇄 미리보기<br/>A4 레이아웃 + KaTeX 수식]
    B --> C{미리보기 OK?}

    C -->|레이아웃 문제| D[문항 배치 조정<br/>페이지 나눔 확인]
    D --> B

    C -->|Yes| E{출력 대상}
    E -->|문제지만| F[문제지 인쇄]
    E -->|문제지+답안지| G[문제지 인쇄 후 답안지 인쇄]

    F --> H[브라우저 인쇄 대화상자]
    G --> H
    H --> I[출력 완료 - 사용 기록 저장<br/>노스스타 측정용]
```

## 5. FEAT-4: 진도 갱신 플로우 (리텐션 루프의 시작점)

수업 직후 10초 안에 끝나는 것이 목표입니다. 이 흐름이 매일 반복되어야 서비스가 삽니다.

```mermaid
graph TD
    A[수업 종료] --> B[메인에서 반 선택]
    B --> C[현재 진도 표시]
    C --> D{오늘 진도는?}

    D -->|예정대로| E[다음 소단원으로 1클릭 진행]
    D -->|다르게 나감| F[단원 트리에서 직접 선택]

    E --> G[진도 저장]
    F --> G

    G --> H[내일 테스트 자동 준비 예약]
    H --> I[완료 - 간결한 확인 표시]

    %% 리텐션 루프
    I --> J[다음날 접속]
    J --> K[준비된 테스트 발견]
    K --> L[검수 → 인쇄 → 수업]
    L --> A
```

## 6. 에러 처리 플로우

```mermaid
graph TD
    A[에러 발생] --> B{에러 유형?}

    B -->|문제 부족| C[가용/필요 문항 수 표시<br/>AI 생성 또는 문항 축소 제안]
    B -->|AI 생성 실패| D[재시도 안내<br/>문제은행 문제로 대체 제안]
    B -->|네트워크| E[연결 재시도 안내]
    B -->|입력 오류| F[필드별 에러 표시]
    B -->|인쇄 수식 깨짐| G[새로고침 후 재시도 안내<br/>지속 시 이슈 기록]

    C --> H{선택}
    H -->|AI 생성| I[생성 실행]
    H -->|축소| J[줄어든 문항으로 진행]

    D --> K[문제은행 우선 출제로 폴백]
    E --> L[재시도]
    F --> M[수정 후 재제출]
```

**에러 문구 원칙 (D-08 톤 적용)**: 간결하고 사무적으로. 원인 + 다음 행동 1개.
예: `"이 단원의 문제가 부족합니다. AI 생성을 실행하거나 문항 수를 줄여주세요."`
