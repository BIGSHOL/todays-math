### 0.1 제품에서 부르는 길 (D-55, 2026-08-19)

AI 문제 변형이 도형을 **새로 그린다**. 사람이 파이썬을 직접 부르지 않는다.

```
AI(figureSpec v2 JSON)
  → src/lib/figure/renderFigureSpec.ts   (Node: 프로세스 하나 띄워 stdin/stdout)
  → scripts/figure/render_spec.py        (render_figure_spec + sanitize_svg)
  → Problem.figureSvg
```

**SVG 의 유일한 생산자는 서버다.** 미리보기에서 본 도형도 채택할 때는 **스펙으로**
되돌아와 서버가 다시 그린다 — 브라우저가 준 마크업을 저장하면 지면·화면에 남는
주입 통로가 된다. 스펙 검증은 **엔진이 정본**이고(허용 키 밖은 `FigureSpecError`)
TypeScript 쪽에서 다시 좁히지 않는다. 두 벌이 되면 갈라진다.

```python
import sys; sys.path.insert(0, r"F:\시험지변환기")
from core.figure_scene import compile_figure_spec   # 구조화 스펙 → 검증된 SVG
from core.figure_svg   import line, txt, circ, curve_path, arc, rangle, ...
from core.figure_solid import View                  # 3D 사방투영
```

| 모듈 | 역할 |
|---|---|
| `core/figure_scene.py` | **FigureSpec v2**(구조화 스펙) → 검증·렌더. LLM이 JSON만 내면 되는 안전 경로 |
| `core/figure_svg.py` | 2D 프리미티브(선·호·각도표시·치수선·곡선·라벨). 강력하지만 코드 작성 필요 |
| `core/figure_solid.py` | 공간도형(사방투영 `View`, 정투영 `Camera`, 평면·정사영) |
| `core/figure_quality.py` | 픽셀 린트 + `sanitize_svg`(보안 경계) |

## 1. 2계층 구조 — 어느 쪽을 쓸지 먼저 정한다

**계층 A — FigureSpec v2 (권장, LLM이 생성)**
평면도형·원 계열은 전부 여기서 해결된다. 스키마가 엄격해 잘못된 스펙은 **조용히 통과하지 않고 예외**가 난다.

허용 최상위 키: `version`(=2) · `theme` · `canvas` · `background` · `style` ·
`points` · `circles` · `segments` · `angles` · `dimensions` · `labels`

```python
spec = {
  "version": 2,
  "points": {"O": [0,0],
             "A": {"type":"on_circle","circle":"c","angle":60},
             "P": {"type":"intersection","segments":["AC","BD"]}},
  "circles": {"c": {"center":"O","radius":85}},
  "segments": {"AB": ["A","B"]},
  "angles": {"angA": {"vertex":"A","points":["B","D"],"label":"∠A"}},
  "dimensions": {"dimAB": {"points":["A","B"],"label":"10 cm","side":"auto"}},
  "labels": {"A":"A","B":"B"},
}
svg = compile_figure_spec(spec).render_svg()
```

**계층 B — 프리미티브 직접 조립**
FigureSpec v2에 **없는 것**: 곡선(함수 그래프)·입체도형·통계 그래프.
이때만 `figure_svg`/`figure_solid`로 f-string SVG를 조립한다.

```python
def wrap(w, h, body):
    return (f'<svg viewBox="0 0 {w} {h}" xmlns="http://www.w3.org/2000/svg">'
            f'<rect width="{w}" height="{h}" fill="#fff"/>{body}</svg>')
```

## 2.1 초등 그림 — `elem-1` (D-61, 2026-08-20~21 원장님 육안)

### 불변식 (원장님 육안 2026-08-20~21 — 테스트가 지킴)

- **`table`**: viewBox 폭 ≤240 (`TABLE_VIEWBOX_MAX`). 열이 많으면 칸만 줄인다. 폭을 키우면 `[&>svg]:w-full` 때문에 숫자가 본문보다 작아진다.
- **`namedShapes`**: 라벨 y = 도형 아래 고정. 같은 행은 같은 높이. FigureSpec `labels` 는 점 옆에 붙어 높이가 제각각이다 — 쓰지 않는다.
- **`trapFour`**: 아랫변 3칸·윗변 1칸, 칸 한 변 = 높이. 조각 0 왼쪽 · 1 가운데 위 · 2 가운데 아래 · 3 오른쪽. 정점 6개(윗 2·아랫 4). **두 대각선 분할 금지**(위·아래 넓이 다름 → 분수 불가). **산 모양 이등변 넷을 나란히 놓지도 않는다**(원본은 한 도형).
- **`tape`**: `_length_mark` → `core.figure_svg.measured`. 손 곡선 금지.
- **`pointGrid`**: 격자 `#c8d7e4` 0.7px. `#7aa0c4` 1.05px 는 발문을 이긴다.
- **`fracPie`**: 교재 피자를 **오리지 않는다**(쪽 배경이 남는다).
- **`netCylinder`**: 밑면 원 둘은 옆면 직사각형의 **긴 변(둘레)** 에 접한다. 떠 있는 원 금지. 짧은 변(높이)에 붙이면 접을 수 없다. `layout` 은 `opp`·`oppFlip`·`oppMid`·`sameTop`·`sameBot`·`ends`.
- **둥근 입체 타원**: `ROUND_RATIO` **0.15** — 원기둥·원뿔·**구** 셋이 한 숫자를 쓴다.
  「절대 타원이 그려지지 않도록」(원장님 2026-08-22). 시안은 `shot-round-ratio.py`.
- **`cone`**: 꼭대기에서 투영 밑면(타원)에 그은 두 접선이 모선. 보이는 호를 따라 옆면을 채운다. 숨은 호는 점선. 밑면 타원 채우기 + 세 점 삼각형 금지.
- **화면 폭**: 위젯 140px(viewBox ≤160), 중간 240px(≤320), 큰 도형 360px — `figureSvgFrame.ts`.

### 불변식 (원장님 육안 2026-08-22 — `docs/planning/tracks/elem-engine-review-20260822.md`)

- **겨냥도(`prism`·`pyramid`·`cuboid`)**: **안 보이는 모서리는 점선, 보이는 모서리는 실선.**
  숨김은 「뒤쪽 꼭짓점」이 아니라 **면 두 장으로** 판정한다(양쪽이 다 뒤를 보면 숨은 모서리).
  점선은 면을 **다 그린 뒤에** 그린다 — 밑에 깔면 칠에 덮여 막힌 덩어리가 된다.
- **밑면 회전**: 서로 다른 꼭짓점의 **화면 x** 가 0.18(반지름 1 기준) 이상 벌어져야 한다.
  각뿔은 x 대신 **꼭대기에서 본 극각**이 갈라야 한다(모선은 부챗살이라 x 로는 안 갈린다).
  교과서 배치를 두고 **겹칠 때만 필요한 만큼만** 돌린다 — `_spread_rotation`.
- **`cylinder`·`cone`·`sphere`**: 타원은 **축에 나란**하고 ry/rx = **0.15** (§4-20-d).
  ⚠️ 종전 0.30 은 원장님이 「타원처럼 생겨진다」고 물리셨다 — 이 줄을 되돌리지 마라.
  사방(45°) 투영은 타원이 7° 기울어 「타원기둥」처럼 보인다 → 깊이축을 화면 위(90°)로 세운다.
  원기둥 옆면은 위·아래 **앞쪽 호를 이은 도형**이다(네 점 사각형 금지). 밑면 뒤쪽 호는 점선.
- **치수 라벨**: `cm` 이 붙은 글자는 **전부** `measured()` 가 낸다(점선 `6 4` + halo).
  도형 위에 얹은 날 `<text>` 금지. 벌어짐은 `DIM_OFF`(12) 하나를 쓴다.
  마름모 대각선은 `off=0` 으로 두어 **대각선 자체가 치수선**이 되게 한다(점선 두 겹 금지).
- **viewBox**: `_svg` 가 몸통의 경계 상자를 재서 **그린 것을 다 담는다**. kind 가 여백을
  손으로 셈하지 않는다. 음수 쪽이면 내용을 밀고, 모자라면 넓힌다. `table` 의 ≤240 은 그대로.
- **`namedShapes`**: 등변 tick·직각 기호는 `items[].marks` 로 **켜야** 나온다.
  「세 변이 같은 삼각형을 고르시오」에 tick 이 찍혀 있으면 문제가 성립하지 않는다.
  그리고 표시가 없어도 **서로 다른 kind 는 윤곽으로 갈려야 한다**(쌍마다 ≥ 6px,
  `SHAPE_MIN_DISTANCE`). 좌표를 고치면 **전 쌍을 다시 재라** — 한 짝을 벌리다
  다른 짝이 좁아진다(09 §4-19).

- **`barChart`·`lineChart` 세로축**: 축 맨 위는 **걸음을 아는 쪽(파이썬)이 정한다.**
  `yMax` 는 「진실」이 아니라 **「최소 높이 요청」** — `_axis_top` 이
  `max(yMax, 올림(값 최댓값/걸음)×걸음)` 을 내고, **눈금도 막대·꺾은선도 그 값을 쓴다.**
  걸음은 `1·2·5×10ⁿ` 사다리에서 눈금이 `MAX_Y_TICKS`(9)줄을 넘을 때만 올라간다 —
  **넘칠 때만 키운다**(안 그러면 결함 없는 장까지 바뀐다). 축을 올리면 걸음이 또 커지므로
  **더 안 움직일 때까지 되풀이**한다 (§4-23).

상수는 `elementary.py` 한 곳: `INK` `#111111` · `PAPER` `#ffffff` · `GRID` `#c8d7e4` ·
`GRID_SW` 0.7 · `TABLE_VIEWBOX_MAX` 240 · `DIM_OFF` 12 · `FIT_PAD` 2.
`elem_advanced.py`: `HIDDEN_DASH` `5 4` · `ROUND_RATIO` **0.15**(셋이 공유) · `NGON_MIN_GAP` 0.18
· `NICE_STEPS` `1·2·5×10ⁿ` · `MAX_Y_TICKS` **9**.

## 4. 실제로 낸 오류 (재발 금지 목록)

### 4-1. `line()` 에 좌표를 4개로 펼쳐 넘김 ❌
```
TypeError: line() got multiple values for argument 'w'
```
`line(x1, y1, x2, y2, w=1.4)` 로 불렀다. **`line()`은 점 튜플 2개를 받는다.**
→ `line((x1, y1), (x2, y2), w=1.4)`

### 4-2. FigureSpec 이름 충돌 ❌
```
FigureSpecError: duplicate geometry name 'B': new angle conflicts with point
FigureSpecError: duplicate geometry name 'AB': new dimension conflicts with segment
FigureSpecError: duplicate geometry name 'A': new angle conflicts with point
```
`angles`/`dimensions`의 **키**를 점 이름(`A`,`B`)이나 변 이름(`AB`)과 똑같이 지었다.
**모든 기하 객체의 이름은 한 네임스페이스를 공유한다.**
→ 각은 `angA`, 치수는 `dimAB` 처럼 **접두사**를 붙인다. (엔진이 막아 준 것이지 결함이 아니다)

### 4-3. 입체도형을 손으로 오프셋 계산 ❌
직접 `cab(x,y,z)` 오프셋을 만들어 겨냥도를 그렸더니 **직육면체·삼각기둥이 뭉개졌다.**
→ 반드시 `figure_solid.View`(사방투영)에 **3D 좌표**를 넘긴다. `View`는 호출 가능 객체다.

### 4-4. 숨은 모서리를 점선 처리하지 않음 ❌
모든 모서리를 실선으로 그리면 선이 교차해 **입체로 보이지 않는다**(삼각기둥 실패).
→ 관찰자 반대편 꼭짓점에 닿는 모서리를 골라 `dash="5,4"` 로 먼저 그린다.
```python
tri_edges  = [(0,1),(1,2),(2,0),(4,5),(1,4),(2,5)]   # 실선
tri_hidden = [(3,4),(5,3),(0,3)]                      # 뒤쪽 꼭짓점 D(3)에 닿는 모서리
```

### 4-5. Python `%` 포맷과 CSS `%` 충돌 ❌ (엔진과 무관하나 반복해서 당함)
```
ValueError: unsupported format character ';' (0x3b)
```
HTML 템플릿에 CSS(`max-width:100%`)가 있는데 `"..." % (a, b)` 로 포맷했다.
→ `.format()`/`.replace()` 를 쓰거나, 애초에 **셸 heredoc 대신 파일로 작성**한다.
   (한글 경로 + 셸 이스케이프가 겹치면 디버깅 비용이 크다)

### 4-6. 사다리꼴을 두 대각선으로 나눠 분수에 씀 ❌ (2026-08-21)

### 4-12. 원기둥 전개도에서 원이 직사각형 위에 떠 있음 ❌ (2026-08-22)
밑면 원 둘을 옆면 위에 간격을 두고 그렸다. 전개도는 원이 직사각형 **긴 변에 접해야** 접힌다.

### 4-13. 원뿔을 밑면 타원 + 세 점 삼각형으로 그림 ❌ (2026-08-22)
투영 밑면의 왼쪽·오른쪽 끝은 꼭대기에서 본 접점이 아니다. 타원을 채우고 그 위에 삼각형을 얹으면 피자 조각처럼 보인다.
→ 꼭대기에서 타원에 접하는 두 모선. 가까운 호를 따라 옆면을 채우고, 먼 호는 점선.

### 4-14. 겨냥도 숨은 모서리를 **면 아래에** 깔거나 밑면만 셈 ❌ (2026-08-22 원장님)
각기둥이 「막힌 덩어리」로 보여 면·모서리를 셀 수 없었다. 원인이 둘이다.
⑴ 점선을 면보다 **먼저** 그려 칠에 덮였다. ⑵ 각뿔은 밑면 모서리만 숨김 판정을 해
**모선**(꼭대기→뒤 꼭짓점)이 실선으로 남았다.
→ 점선은 면을 다 그린 **뒤에**. 숨김은 §4-4 의 「뒤쪽 꼭짓점에 닿는 모서리」가 아니라
   **면 두 장**으로 판정한다(양쪽이 다 뒤를 보면 숨음). §4-4 는 직육면체에만 맞는 규칙이었다 —
   오각기둥·육각뿔은 뒤 꼭짓점이 둘 이상이라 손으로 고른 목록이 샌다. `_hidden_edges`.

⚠️ **각기둥 규칙을 각뿔에 그대로 대면 안 된다.** 각기둥 옆면 법선은 수평이라
「밑면 고리의 뒤쪽 사슬」과 숨은 면이 정확히 같지만, 각뿔은 꼭대기가 법선을 위로 눕혀
**보이는 옆면이 더 많다**. 칠각뿔에서 실제로 갈렸다(사슬 4 vs 실제 3). 시험은
개수 대신 **구조**(숨은 모선 = 숨은 밑면 모서리 − 1)를 잰다.

### 4-15. 원기둥·원뿔 밑면이 **기울어** 타원기둥처럼 보임 ❌ (2026-08-22 원장님)
사방(45°) 투영은 수평 원을 **7° 기운** 타원으로 그린다. 납작한 정도(0.31)는 교과서
범위인데 기울어 있어서 「원기둥이 아니라 타원기둥」으로 읽힌다. 옆면을 네 점 사각형으로
덮은 것도 겹쳐, 밑면을 가로지르는 실선이 남아 「잘린 배」처럼 보였다.
→ 둥근 입체만 깊이축을 **화면 위(90°)** 로 세운다. 그러면 축에 나란한 타원이 되고
   `depth_ratio` 가 곧 ry/rx 다. **값은 §4-20-d 에서 0.15 로 다시 정해졌다.**
   옆면은 위·아래 **앞쪽 호를 이어** 만들고,
   밑면 뒤쪽 호는 점선. `ROUND_RATIO` · `_split_ring`.

### 4-16. 같은 kind 안에서 치수 표기가 갈림 ❌ (2026-08-22 원장님)
`areaPoly` 의 삼각형은 점선 치수선인데 **마름모만** `4 cm`·`8 cm` 를 도형 위에 얹었다.
원기둥 `2 cm` 는 곡선 지시선이 밑면 호 위에 떠 「어디를 가리키는지 모르겠다」였다.
→ **`cm` 이 붙은 글자는 전부 `measured()` 가 낸다.** 벌어짐은 `DIM_OFF` 하나.
   대각선처럼 도형 안을 지나는 선은 `off=0` 으로 두어 **그 선 자체가 치수선**이 되게 한다 —
   따로 긋고 옆에 치수 곡선을 두면 점선이 두 겹이라 더 어수선하다(실측).
   반지름은 **중심에 점을 찍는다**. 점이 없으면 무엇에서 잰 길이인지 안 보인다.

### 4-17. viewBox 여백을 kind 가 손으로 셈함 ❌ (2026-08-22 원장님)
오각기둥 전개도의 위·아래 꼭짓점이 잘렸다. 밑면 각형이 옆면 위로 얼마나 솟는지를
**내접원 반지름**으로 셈했는데 정오각형은 그보다 높다. 변 수가 바뀌면 또 어긋난다.
→ `_svg` 가 몸통을 훑어 경계 상자를 재고 맞춘다. 곡선은 제어점이 아니라 **실제 극값**을
   푼다(제어점을 담으면 measured() 곡선이 두 배로 부푼다). `transform` 은 `sanitize_svg`
   가 막으므로 좌표 숫자를 직접 옮긴다 — 모르는 태그·상대 경로 명령은 **예외**로 드러낸다.

### 4-18. 꼭짓점이 화면에서 겹쳐 숨은 점선이 실선에 달라붙음 ❌ (2026-08-22)
숨은 모서리를 살리자마자 드러났다. 오각기둥의 앞왼쪽·뒤왼쪽 세로 모서리가 화면 x
0.03 차이라 점선이 실선 위에 겹쳐 그려졌다. 칠각뿔은 **모선** 둘의 극각이 1.1° 차이였다.
→ 도형마다 각도를 맞추지 말고(D-61) 교과서 배치에서 **필요한 만큼만** 돌린다.
   가르는 축이 다르다 — 각기둥은 **화면 x**(세로 모서리는 나란하다), 각뿔은
   **꼭대기에서 본 극각**(모선은 부챗살이다). `_spread_rotation`.

⚠️ 극각 문턱은 **닿을 수 있는 값**이어야 한다. 부챗살은 실루엣 쪽에서 반드시 몰리므로
각형 수가 커지면 아무리 돌려도 못 넘는다(팔각뿔 최선 3.3°). 처음에 6° 로 잡았더니
n≥6 이 전부 **조용히 0°(=안 돌림)** 로 되돌아갔다 — 「닿을 수 없는 목표」의 그 자리다
(CLAUDE.md 2026-08-18). 못 넘으면 **최선**을 쓰게 고쳤다.

### 4-19. 표시를 끄자 **도형 자체가 안 갈렸다** ❌ (2026-08-22)
§4 의 「묻는 것을 그림이 답하지 않는다」(등변 tick 옵트인)를 넣은 **직후**, 세 세션이
같은 자리에서 막혔다 — g3 은 `rightTri` 를 피해 점격자로 우회, g4 는 「가·나를 눈으로
가를 수 있나」를 물었고, g5 는 합동 풀에서 `eqTri` 를 뺐다. 원인 하나다:
**`eqTri`(밑변 s·높이 0.866s)와 `isoTri`(밑변 s·높이 s)의 윤곽 거리가 3.93px** 뿐이었다.
tick 이 그 차이를 가려 주고 있었을 뿐이다.

→ **표시를 지웠으면 도형이 그 몫을 해야 한다.** `isoTri` 밑변을 0.58s 로 좁혀
   3.93 → **9.45px**. 변 길이 비 1.12 → 1.80.

⚠️ 문턱은 **분포를 보고** 정했다. 전 kind 쌍을 재니 3.93 하나가 외톨이고 나머지는
전부 7.92px(`para↔rect`) 이상이라 **두 무리 사이가 훤히 비어 있다.** 6px 은 그 틈이다 —
「적당히」 고른 값이 아니다. 밑변을 0.50s 까지 좁히면 이번엔 `isoTri↔tallDiamond` 가
7.33px 로 내려온다. **한 짝을 벌리다 다른 짝을 좁히지 않았는지 전 쌍을 다시 재라.**

시험은 도형을 **한 번에 다 그려** 쌍마다 하우스도르프 거리를 잰다. 그리고 「가장 닮은
짝이 6~10px」을 먼저 단언한다 — 재는 자가 죽으면 「0건」이 아무것도 증명하지 않고,
음성 대조군(`para↔rect` 7.92px, 눈으로는 갈리는 짝)이 문턱에 안 죽는 것도 같이 잠긴다.

⚠️ **거리만으로는 부족하다 — 축이 둘이다** (elem-g5 가 짚었다).
하우스도르프는 **그려진 자세**에서 재므로 「멀리 떨어져 보이지만 **돌리면 포개지는**」
짝을 구조적으로 못 본다. 합동 문항(초5 `2-3-1`)이 묻는 것은 「**포개었을 때** 겹치는가」라
학생은 종이를 돌리고 뒤집어도 된다 — 그런 짝은 **정답이 둘**이 되는데 거리 가드는 초록이다.

실제로 `diamond` 는 이미 **45° 돌린 정사각형**이고 `square` 와 갈리는 이유는 모양이 아니라
**크기뿐**이다(변 31.1 vs 44.0). 그래서 **회전 불변 지문**(꼭짓점 수 · 정렬한 변 길이 ·
정렬한 내각)을 따로 잰다. 변이 ⑭(마름모를 키워 정사각형과 합동으로)에서
**하우스도르프는 9.1px 로 초록이고 이 지문만 빨강**이다 — 서로를 갈음하지 못한다는 증거다.

음성 대조군은 `eqTri`(44·44·44) ↔ `square`(44·44·44·44) — **변 길이 값이 같다.**
이 둘이 안 걸려야 「꼭짓점 수까지 본다」가 같이 잠긴다.

다음 병목은 `isoTri`(25.5·45.8·45.8) ↔ `wideTri`(33.7·33.7·44.0) 다 —
**`isoTri` 밑변을 더 건드리면 이쪽이 먼저 위험해진다.**

### 4-20. **받은 치수를 다 안 적었다** — 설명 없는 점선이 남는다 ❌ (2026-08-22)
`areaPoly` 사다리꼴만 높이 점선에 **값이 없었다.** 삼각형·평행사변형은 밑변·높이를 둘 다
적는데 사다리꼴은 `10 cm`·`4 cm`(아랫변·윗변)뿐이라 지면에 이유 없는 점선 하나가 남았다.
§4-16(「라벨이 `measured()` 인가」)은 **이것을 구조적으로 못 본다** — 적힌 라벨만 보기
때문이다. 축이 다르다: **「스펙이 준 치수를 하나도 안 빠뜨렸는가」.**

그리고 값을 적자마자 **점선 자체가 틀린 자리에 있던 것**이 드러났다. 윗변·아랫변 왼쪽 끝의
**가운데 x** 에 그어 윗절반이 빗변 바깥으로 삐져나와 있었다. 값이 없어 아무도 안 봤을 뿐이다.
→ 삼각형·평행사변형과 같이 **꼭짓점에서 수직으로** 내린다.

**값을 적는 것은 표기 규칙이 아니라 «조명»이다.** 지면에서 **설명 없는 선은 검사 대상이
되지 못한다** — 눈이 그냥 지나간다. 실제로 높이 값을 넣자마자 elem-g5 가 자기 호출 쪽에서
둘을 더 찾았다: **두 대각선이 같아 정사각형이 된 마름모**(200개 중 4개)와 **직사각형처럼
보이던 사다리꼴**(윗변 7·아랫변 9·높이 12는 기울기가 12분의 1). 값이 찍히니 도형이
값과 안 맞는 것이 보였다. 치수를 빠뜨리면 그 도형의 **다른 결함까지 같이 숨는다.**

### 4-20-a. 지면이 너저분하면 **조명을 끄지 말고 옮긴다** (원장님 확정 2026-08-22)

마름모는 위 규칙의 **예외**가 됐다. 원장님:

> 「마름모는 충분히 도형 크기가 크지 않으면 그냥 문제에 적어두고 **내부에는 라벨 표기
> 안 하는 걸로** 하자. … **표기하니까 오히려 너저분해지는듯**」

네 안(대각선 자체가 치수선 / 삼각형처럼 아래로 / 둘 다 바깥 / 둘 다 안쪽)을 **삼각형과
나란히** 그려 본 뒤 나온 결정이다. **넷을 다 보고서야** 「어느 것도 안 넣는 게 낫다」가
나왔다 — 한 안만 냈으면 그 안을 고르셨을 것이다. **대각선 점선은 남긴다**(넓이 규칙
`d1×d2÷2` 가 그 선에서 보인다). 뺀 것은 **라벨뿐**이고 길이는 발문이 말한다.

⚠️ 그러면 §4-20 의 조명이 마름모에서 꺼진다 — 그리고 **§4-21 을 지면에서 잡아 줄 근거가
바로 그 라벨이었다.** 원장님 결정은 **지면**에 대한 것이지 **검사**에 대한 것이 아니다.
그래서 **끈 것이 아니라 옮겼다**: 「그린 가로:세로가 스펙의 `d1:d2` 와 맞는가」를 시험이
SVG 에서 직접 잰다. **`height != d2` 인 입력**(`12×8×height 4`)이 그 시험의 핵심이다 —
같은 값만 넣으면 무엇으로 그리든 비가 같아 §4-21 자리가 구조적으로 안 갈린다.

그리고 「안내선은 치수 곡선과 짝이어야 한다」 검사에서 마름모를 **예외라고 적었다.**
규칙을 조용히 약하게 만들면 다음 사람이 「원래 느슨한 검사」로 읽는다 — 예외는
**예외라고 보이게** 둔다.

> **지면에서 빼기로 한 것이 있으면, 그것이 무엇을 지키고 있었는지 먼저 세라.**
> 지키던 게 있으면 그 몫을 시험으로 옮기고, 없으면 그냥 빼면 된다.

### 4-20-b. 가르는 축은 「좁아서」가 아니라 **「발문이 이미 말했는가」** (원장님 확정 2026-08-22)

> 커밋 **`221ac22b`**. ⚠️ 그 커밋 제목은 「마름모 라벨을 뺀다」인데 **원기둥·구의 라벨 제거가
> 같이 들어 있다**(작업 트리에 있던 것이 함께 쓸려 들어갔다). 「원기둥 반지름 라벨이 언제
> 없어졌나」를 **로그에서 제목으로 찾으면 안 나온다** — 그래서 여기 해시를 적어 둔다.

원기둥에도 같은 지시가 왔고, 이 문장이 **진짜 축**을 알려 준다:

> 「원기둥의 반지름도 마찬가지. **문제에 굳이 있는데 라벨로 이중표기**해서
> 너저분해질 필요가 없을듯.」

마름모 때는 「충분히 크지 않으면」이라 하셔서 **크기** 문제로 읽었는데, 축은 **이중표기**다.
그래서 「전부 빼라」가 **아니다** — 갈래마다 다르다. 발문을 전수로 뽑아 정했다:

| kind | 값을 쓰는 발문 | 그림에서 | 근거 |
|---|---|---|---|
| `cylinder` | 「밑면의 반지름이 $2$ cm 인 … 지름은?」 | **반지름 뺌 · 높이 남김** | 반지름은 발문에 있고 **높이는 없다** |
| `sphere` | 「반지름이 $3$ cm 인 구의 지름은?」 | **뺌**(날 텍스트였다) | 발문이 말한다. §4-16 위반도 같이 사라짐 |
| `cone` | 「밑면의 **지름**이 $4$ cm 인 … **반지름**은?」 | **원래 없음 — 그대로** | 반지름을 적으면 **답을 그림이 말한다**(원장님 ⑤ 부류) |

나머지 갈래(원기둥 4/5 · 원뿔 4/5 · 구 3/4)는 아예 수를 안 쓰는 개념 문항이라
(「원뿔의 밑면은 어떤 도형인가?」) 라벨이 할 일이 없다.

⚠️ **`netCylinder` 는 `cylinder` 와 별개다.** 「밑면의 반지름이 $r$ **이고 높이가 $h$** 인
원기둥의 전개도에서 …」(`g6.ts` 전개도 갈래)는 발문이 **높이까지 말한다** — `cylinder` 쪽
발문은 높이를 말하지 않는다. 그래서 「높이는 남긴다」는 **`cylinder` 에만** 해당한다.
`netCylinder` 는 지금도 치수를 하나도 안 적고, 그게 이 규칙에 맞다.
겉모습이 같다고 둘의 규칙을 합치지 마라.

⚠️ **전개도의 밑면은 `<circle>` — 정원이다. 눌러서 타원으로 만들지 마라.**
「원기둥 밑면은 타원으로 그리기로 했는데 여긴 왜 정원이지」 하고 맞추려 들면
**접을 수 없는 그림**이 된다. 겨냥도의 타원은 **원을 비스듬히 본 것**이고,
전개도는 펼친 실물이라 **진짜 원**이다. 둘은 같은 밑면의 다른 그림이다.

> 타원이 나오는 자리는 **셋뿐**이다(HEAD 기준 전수 확인, team-lead):
> `_cylinder` 밑면 · `_cone` 밑면 · `_sphere` 적도. 나머지 `<circle>` 은 전개도 밑면과
> 점 표시이고, `elementary.py` 의 `<ellipse>` 하나는 연산 기호를 담는 **말풍선 배지**다.
> ⚠️ 이런 전수 확인은 **`git show HEAD:` 로** 하라 — 변이 하네스가 도는 동안의
> 작업 트리는 일부러 망가뜨린 상태다.

**높이를 같이 빼면 안 된다** — 설명 없는 점선만 남아 §4-20 사다리꼴과 같은 자리가 된다.
반지름 라벨을 빼면서 **중심 점도 같이 뺐다**: 라벨이 없으면 그 점 역시 설명 없는 표시다.

조명은 여기서도 옮겼다 — 「그린 `r:h` 가 스펙과 맞는가」를 시험이 SVG 에서 직접 잰다.
절대 크기는 원래 안 지킨다(`scale = 70/max(2r,h)` 라 `2r ≥ h` 면 반지름이 늘 35px).

⚠️ **구는 옮길 조명이 없다.** `pr = 36.0` 리터럴이라 `r=1` 과 `r=20` 이 **같은 원**이다 —
그림이 `r` 을 한 톨도 안 담는다. 지금 구 문항은 길이를 그림에서 읽지 않아 성립하지만,
「그림을 보고 반지름을 구하시오」가 생기면 그 순간 못 쓴다. **그 사실 자체를 시험에
적어 뒀다**(「구는 반지름을 그림 크기에 반영하지 않는다 (알려진 상태)」) — 어디에도
안 적혀 있으면 다음 사람이 **의도인지 결함인지** 알 수 없다.

### 4-20-d. 「**절대** 타원이 그려지지 않도록」 — `ROUND_RATIO = 0.15` (원장님 확정 2026-08-22)

> 「자꾸 **타원처럼 생겨지네**」(원기둥) · 「**원뿔도 마찬가지**」
> → 「**강력하게 조여. 절대 초등과정에서 원기둥 원뿔 구에서 타원이 그려지지 않도록**」

§4-15 에서 **기울기**를 고치고 「납작한 정도(0.31)는 원래 범위였다」고 판단해 비율은
그대로 뒀는데, **비율도 문제였다.** 기울기 수정은 옳았지만 축이 둘이었다.

0.30·0.20·0.15·0.12 를 **셋 다 · 납작한 것(h<2r) 포함**으로 렌더해 견주고 **0.15** 로
확정하셨다. **하한은 0.12** 다 — 거기서는 납작한 원기둥이 직사각형처럼 보이고
**구 적도가 거의 직선**이 되어 공이 원판으로 읽힌다. 시안은
`scripts/qa/shot-round-ratio.py` 로 **언제든 다시 낼 수 있다**(비율을 인자로 받는다).

**셋이 한 숫자를 쓴다.** 예전에는 구만 날 리터럴 `0.32` 라 상수를 조여도 구는 안
따라왔고, 하필 **셋 중 가장 뚱뚱한 것**이 안 고쳐지고 남았다
(2026-08-18 「배선이 한쪽만 되면 그쪽 지표만 좋아진다」).

#### 자는 **눈금을 맞춰야** 한다 — 「수가 나오나」도 「값이 변하나」도 부족하다

엉뚱한 요소를 재도 **값이 같이 움직인다.** 실측: 비율을 0.30 → 0.15 로 바꾸면
원기둥 **몸통**이 0.900 → 0.825 로 따라 움직이고 원뿔 **실루엣**도 그렇다. 그걸 재면
비율을 잠가 놓고 몸통을 지키는 **동어반복**이 된다.

→ **「그 수가 비율과 같은가」**로 잠근다. 그리고 **`r·h` 가 다른 두 점**을 쓴다 —
   밑면 타원의 비는 `r·h` 와 무관하게 일정하지만(0.150·0.150) 몸통·실루엣은
   **0.900 / 0.550** 으로 갈린다. 엉뚱한 요소는 두 점에서 같은 값을 낼 수 없다.

눈금 실측 **12/12**: `p ∈ {0.30, 0.20, 0.15, 0.12}` × `r2h3`·`r5h4` × 셋에서 잰 값 = `p`.

⚠️ **재는 자리가 kind 마다 다르다.** 원기둥·원뿔은 **폴리곤**이고 구만 `<ellipse>` 다 —
`<ellipse>` 만 찾는 자는 앞의 둘에서 **구조적으로 0**이 된다(못 재는 것이 깨끗한 것으로
보인다). 원뿔은 **밑면 다각형이 따로 없다**: 실루엣에서 꼭대기 한 점을 빼고 뒤쪽 점선
호를 이으면 타원 한 바퀴가 된다. **어느 한 요소에도 그 값은 없다.**

⚠️ 기대값은 **시험에 적은 리터럴**이다. 제품 상수를 읽으면 상수를 바꿀 때 기대값이
따라가서 영원히 초록이다. 값을 바꾸면 시험도 **일부러** 같이 고쳐야 한다.

#### 변이는 **kind 별로** 쪼갠다

`ROUND_RATIO` 하나를 되돌리면 원기둥·원뿔이 같이 움직여서, **원뿔 자가 죽어 있어도
원기둥이 빨개져 🔴 로 찍힌다.** 파일 단위 판정은 「어느 단언이 죽었나」를 말해 주지
않는다. 상수를 늘리지 말고 **부르는 자리**(`ratio=ROUND_RATIO`)를 kind 마다 따로 겨눈다.
하네스도 실패한 **시험 이름**을 같이 찍게 했다.

### 4-20-c. 그리고 이 검사의 손 목록이 **바로 그 sphere 를 놓치고 있었다**

「cm 라벨은 전부 halo 다」 검사가 `WITH_DIMS` 라는 손 목록만 훑어서, 거기 없는 `sphere` 의
날 텍스트를 **구조적으로 못 봤다.** §4-22 에 「손 목록은 샌다」를 적어 놓고 **그 시험이
바로 그 모양**이었다.

→ ⑴ 검사를 **전 kind 훑기**로 바꾸고, 「라벨이 있어야 한다」를 요구하지 않는다 —
   **있으면 halo 여야 한다**만 본다. 그래야 라벨을 뺀 kind 도 같이 훑는다.
   ⑵ 「적기로 한 kind 는 실제로 적는가」를 **따로** 둔다(검사가 빈 껍데기가 되지 않게).
   ⑶ 변이 표본(`probe-elem-figure.py`)은 **엔진의 `KIND_FIELDS` 와 대조**해 빠진 kind 가
   있으면 멈춘다. 넣자마자 **31개**가 빠져 있었고 그 안에 `sphere` 가 있었다 —
   그게 없었으면 이번 수리의 변이를 판정할 수 없었다.

### 4-21. 그림을 `height` 로 그리고 라벨은 `d2` 로 적었다 ❌ (2026-08-22, 잠재)
마름모는 세로 대각선 값이 `d2` 인데 **그리는 상자는 `height`** 로 잡았다. 지금 부르는 쪽이
늘 `height == d2` 라 안 드러날 뿐, 둘을 다르게 주면 **길이 4 로 그려 놓고 「8 cm」로 적는다.**
에러도 안 나고 KaTeX 도 멀쩡하다 — 스스로 신고하지 않는 부류다.
→ 마름모의 세로는 **적히는 값**(`d2`)으로 그린다. `d2` 는 `height` 를 기본값으로 두므로
   지금 부르는 쪽은 아무 변화가 없다.

⚠️ 시험을 **두 값이 다른 입력**(`height: 4, d2: 8`)으로 써야 이 자리가 갈린다.
같은 값만 넣으면 고치기 전에도 초록이다.

  전까지 안 보이고, **적어 줄 사람이 없으면 그 자리는 구조적으로 0**이 된다.
  뿌리에 두면 적을 목록이 아예 없어진다.
- **하네스 이름 접미사**: 둘이 동시에 돌면 서로 덮어쓴다. `ls MUTATION-IN-PROGRESS.*`
  한 줄로 도는 것 전부가 보인다.
- **PID 를 넣는다**: 하네스가 비정상 종료하면 표지만 남아 다들 영영 기다린다.
  프로세스를 **이름으로 세지 마라** — `ps -ef | grep '…\.sh$'` 의 `$` 앵커 때문에 0을
  얻고 「죽었다」로 읽어 **도는 하네스 밑에서 파일을 고칠 뻔한** 일이 있었다.
- **「한 번 걷혔다」는 「안전하다」가 아니다**: 연달아 돌리면 두 회차 **사이의 틈**에
  뛰어들어 다음 회차가 망가뜨린 상태를 「최종 결과」로 재게 된다.
  `scripts/qa/wait-mutations-quiet.sh` 가 「조용할 초」(연속 N초)를 본다.

⚠️ **「뿌리 glob 이 새 이름을 잡는가」는 표지를 실제로 만들지 않고도 잰다** —
`markers()` 만 떼어 부르거나 한 번만 훑어 센다. 대기를 실제로 **막아 보는** 것은
확인이 아니라 **재현**이고, 재현은 되살릴 길을 먼저 깔고 하는 것이다.
타임아웃으로 죽는 것은 바깥에서 오는 신호라 `trap` 이 잡는 경로가 **아니다** —
이 항목이 경고한 「표지만 남아 다들 영영 기다린다」에 **이 항목을 확인하다가** 걸릴
뻔했다(2026-08-22, 표지가 남을 뻔한 것을 손으로 지웠다). 규약을 시험하는 코드가
그 규약의 함정에 가장 먼저 빠진다.

⚠️ **그리고 내가 여기서 원인을 지어냈다.** 「표지가 걷혔다 곧바로 다시 떴다」는 보고를 보고
「저쪽 대기가 내 표지를 못 보고 있다」고 **단정해 두 세션에 그렇게 알렸다.** 실제로는
그 대기가 내 옛 경로를 27행에 **박아 두고 잘 보고 있었고**, 그 보고는 두 회차를 **정확히
본 것**이었다. 나는 그 스크립트를 **한 번도 안 읽고** 증상에서 원인을 추론했다 —
「없다」를 적을 때는 무엇을 보고 없다고 했는지 함께 적으라는 그 자리다(CLAUDE.md 2026-08-18).
뿌리 규약은 그대로 옳지만 **이유가 다르다**: 「지금 대기가 못 봐서」가 아니라
**「손 목록은 샌다」**이다. 이유를 틀리게 적으면 다음 사람이 **멀쩡한 대기를 고치러 간다.**

### 4-23. 그래프 세로축 — **`yMax` 는 TS 가, 걸음은 파이썬이** 정한다 ❌ (2026-08-22 원장님)

원장님이 화면에서 두 가지를 잡으셨다. 겉보기엔 딴 결함인데 **한 뿌리**다.

| 증상 | 실측 |

뿌리: **`yMax` 를 정하는 쪽(TS `g4.ts`)과 걸음을 정하는 쪽(파이썬 `_y_step`)이 서로
상대가 무엇을 할지 모른다.** TS 는 `최댓값 + 3` 같은 값을 주는데 파이썬이 5로 자르면
맨 위 눈금은 `내림(yMax/5)×5` 가 된다 — `최댓값 % 5 == 1` 이면 **항상** 뜬다.
반대로 `yMax` 가 크면 걸음 5가 눈금을 수백 줄 만든다. 「**축 맨 위는 걸음을 아는 쪽이
정해야 한다**」가 규칙이고, 걸음을 아는 쪽은 파이썬이다.

→ ⑴ `_y_step` 은 옛 규칙(`≤8→1 · ≤12→2 · 그 위 5`)을 **바닥**으로 깔고 눈금이

   세로 배율도 **반드시 이 값**을 쓴다 — 눈금만 새 축이면 눈금과 데이터가 딴 자로 그려진다.

**⚠️ 「5~8줄이 읽기 좋다」로 걸음을 다시 고르면 안 된다.** `yMax` 15·16·17 은 지금 4줄인데
그 규칙이면 8~9줄이 된다 — **결함이 아닌 장을 바꾸는 것**이고, 형태를 바꾸는 결정은
원장님 확정 없이 못 한다(D-07). 상한을 8로 낮추면 **결함 없는 장 829장**이, 7이면

**「지금 규칙이 내는 최대」**(`y_max=8` 은 걸음 1로 0~8 아홉 줄)이다.

**⚠️ 축을 올리면 걸음이 또 커진다 — 맞물린다.** `yMax 44 · 값 44` 는 걸음 5로 45가

되풀이해야 한다. 한 번만 돌면 45(걸음 10, 맨 위 눈금 40)에서 멈춰 **값 44가 다시 뜬다.**

  그중 「결함이 없는데 바뀐 장 **0**」·「결함이 있는데 그대로 **0**」 —

#### 4-23-a. 셋 다는 안 된다 — 「넓은 규모」·「모든 점이 눈금 위」·「눈금 아홉 줄 이하」

→ **소재를 새로 넣거나 규모를 넓힐 때 `최댓값 ≤ 8 × 값의 걸음` 을 먼저 검산하라.**
