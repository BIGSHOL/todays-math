### 1.1 ⭐ 적재는 **소단원이 붙은 편만** 골라 갔다 (2026-08-16 실측)

⚠️ **"적재가 결함으로 멈췄다" 고 읽지 말 것.** 소단원 없는 편은 넣을 자리가 없어서
안 들어간 것이다. 되살리려면 문항을 다시 뽑는 게 아니라 **단원을 붙여야** 한다.

트랙 D 가 센 3,247 은 *이미 DB 에 있는 편* 안의 구멍이다. 편 단위 결손과 더하지 말 것.

| | |

**대상 수가 5,816 → 6,042 로 움직인 이유**: 적재 준비 중에 트랙 D 가 HWP 추출본의

숫자가 아니라 **규칙**(후보 − 결함 − 편 중복)이 승인의 근거였으므로 규칙은 지켜졌다.

> **교훈**: 남이 원본으로 쓰는 산출물은 **얼릴 시점**이 필요하다. 적재기는 입력
> corpus 지문을 기록하고, 지문이 달라지면 멈춘다. 2차 적재 때는 그 시점 지문으로
> 다시 승인받아야 한다.

### 1.5 ⚠️ 「중복 88그룹」은 중복이 아니었다 — 그림 결손이 만든 착시

RPM 중복으로 묶여 폐기 후보였던 88그룹(145행)을 완비도 기준으로 갈라 보니
**145행 중 143행이 서로 다른 문항**이었고, **86/88 그룹은 원본 정답부터 달랐다.**

본문 글자만 보고 묶었기 때문이다. 그림이 빠진 문항끼리는 글자가 같아진다.
트랙 A 가 그림을 1,088/1,088 로 붙이자 정체가 드러났다.

지시대로 전부 강등했다면 **멀쩡한 문항 134행을 근거 없이 내렸을 것이고, 그중
65행은 완비도 만점**이었다. 실제로는 점수가 진짜로 가른 **11행만** 강등했다.

**되풀이 금지**: 중복 판정은 본문만으로 하지 마라. **그림·정답을 같은 축에 넣어라.**
그리고 폐기처럼 되돌리기 어려운 일은 "기준을 세웠으니 일괄 적용" 하기 전에
**그 기준이 무엇을 내리는지 표본으로 먼저 보라.**

## 2. 중복 방지 원장 — **재이관 전 반드시 대조**

### 2.1 본문 해시 원장
`scripts/qa/imported-content.txt` — 이미 DB에 있는 문항의 **본문 해시**(sha1 앞 16자리,
공백 정규화 후). 재이관 시 이 해시에 있으면 **건너뛴다**.

재생성: `node scripts/qa/build-import-ledger.mjs`

### 2.2 externalId — 재이관 멱등 키 (2026-08-14 신설, 최우선)
`selectMissingLoadRows`는 `externalId`가 있으면 **내용 대조보다 먼저** 그것으로 중복을 거른다.
내용 대조 키(`loadRowKey`)는 `answer`를 포함하는데 정답 백필로 기존 행의 answer가
바뀌었기 때문에, 내용만 보면 같은 문항을 '새 것'으로 오인해 중복 삽입한다.

### 2.3 ⚠️ 기존 `problemFingerprint`를 중복 판별에 쓰지 말 것
`src/lib/import/problemFingerprint.ts`의 지문은 `answer`/`solution`을 포함한다.
**2026-08-14 정답 백필로 2,400여 건의 지문이 바뀌었다.** 같은 원본을 재이관하면
지문이 안 맞아 **중복 삽입된다**. 중복 판별은 §2.1 본문 해시로 한다.

### 2.4 OCR 품질 감사 원장
`scripts/qa/ocr-audit-clean.txt` — 결함 검사를 통과한 문항 해시.
`node scripts/qa/ocr-audit.mjs` 는 이 원장에 있는 문항을 **재검사하지 않는다**.
검사 세트를 바꾸면 스크립트의 `CHECKSET_VERSION`을 올린다(원장 자동 무효화).

## 4. 토큰 절약 원칙 (대량 데이터 작업 공통)

에이전트가 데이터를 컨텍스트로 읽으면 토큰이 폭증한다. 아래를 지킨다.

1. **스캔·집계는 스크립트가 한다.** 화면(대화)에는 요약 수십 줄만 출력하고,
   문항별 상세는 파일로 떨군다. (예: `ocr-audit.mjs` → 9,197건 스캔, 출력 10줄)
2. **파일 in / 파일 out.** 서브에이전트에게 JSON 파일 경로를 주고 결과도 파일로 쓰게 한 뒤,
   최종 응답은 `done total=60 high=57 …` 한 줄만 받는다. 문항 본문이 오케스트레이터
   컨텍스트에 절대 올라오지 않는다.
3. **원장으로 재작업을 막는다.** 통과분·처리분 해시를 남겨 다음 실행에서 건너뛴다.
4. **대용량 산출물은 커밋하지 않는다.** 상세 리포트 JSON은 `.gitignore`
   (`scripts/qa/reports/*.json`), 원장(수십 KB)만 커밋한다.
5. **배치 출력은 분할한다.** 서브에이전트 1회 응답이 64k 출력 토큰을 넘으면 실패한다
   (2026-08-14 실제 발생). 60건 배치는 20건씩 3파일로 나눠 쓰게 한다.

## 5. 앞으로 기출을 추가 이관할 때 (권장 절차)

### 5.1 ⭐ 추출 대상은 **완료본뿐** (D-37, 2026-08-14 원장님 확정)

> **기출 추출은 워드본을 PDF로 변환한 `(완료)` 표기 파일에서만 한다.**
> 비완료·스캔 원본은 **그 시험지의 완료본이 아예 없을 때만** 예외로 쓰고 사유를 남긴다.

**근거 — exam_index.db 9,173문항 전수 실측 (2026-08-14):**

| 버킷 | 시험지 | 문항 | 정답 없음 | 그림 참조 | OCR 훼손 |
|---|---|---|---|---|---|
| **A `HWP 2 PDF`의 (완료).PDF** | 124 | 2,996 | **9.4%** | 8.5% | **0.3%** |
| B 기타 (완료).PDF | 234 | 4,970 | 20.0% | 6.5% | 1.6% |

A버킷은 워드→PDF 변환이라 **텍스트 레이어가 살아 있어** OCR 훼손이 B의 1/5,
정답 결손이 절반이다. 스캔본은 √·표·첨자가 뭉개진다.

## 7. 실행 중 겪은 함정 (같은 실수 반복 금지)

- **N드라이브는 작업 도중 끊긴다.** 네이버 MYBOX 특성. 2026-08-15 추출 배치가 30편 전부
  `FileNotFoundError` 로 탔다. `extract-final-batch.py` 는 매 편 앞에서 마운트를 확인하고
  최대 10분 기다린다. 산출물이 있으면 건너뛰므로 **재실행이 곧 이어달리기**다.
- **`pg_advisory_xact_lock` 을 `$queryRaw` 로 부르면 죽는다.** 반환형이 void 라
  Prisma 6 가 열을 역직렬화하다 실패한다("Failed to deserialize column of type 'void'").
  `$executeRaw` 를 쓴다. 테스트가 `$queryRaw` 를 모킹하고 있어 침묵하고 있었다 —
  이제 `importLoad.test.ts` 가 `$queryRaw` 호출 시 던져서 회귀를 잡는다.
- **PowerShell/셸에서 백슬래시 경로를 파이썬 `-c` 로 넘기지 말 것.** `'N:\'` 가
  문자열 종료를 먹어 SyntaxError 가 난다. 스크립트 파일로 쓰거나 heredoc 을 쓴다.
- **파일명에 하이픈이 있으면 파이썬 import 가 안 된다.** 공용 유틸은 `final_meta.py`
  처럼 밑줄 이름으로 둔다.
- **큐브 추출 ID 는 지면 번호가 아니다.** 두 단이 섞여 `p069-q49` 가 10번이다. 번호로
  원본을 열지 말고 쪽+본문으로 찾는다.
- **초등 소문항을 `①②③` 로 적으면 보기로 잘린다.** `(1)(2)(3)` 을 쓴다. 문장 속 빈칸은
  `$\square$`.
- **초등 그림을 FigureSpec 좌표로 한 장씩 맞추지 말 것.** 라벨이 뜨고 분수 넓이가 갈린다.
  kind 로 규칙화한다(09 §4-6~4-11, D-61).
