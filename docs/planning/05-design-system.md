## 0. 디자인 작업 방식 (확정)

이 프로젝트의 디자인 협업 규칙 — **이 섹션만은 확정 사항입니다:**

1. **AI 공장식 스타일 전면 배제.** 다음은 금지 목록입니다:
   - 보라/파랑 그라데이션 히어로, 유리morphism 카드
   - shadcn/ui 등 기성 컴포넌트 킷의 기본 모양 그대로 사용
   - 목적 없는 이모지·아이콘 남발
   - 화면마다 반복되는 동일한 카드 그리드 레이아웃
   - "AI가 만든 것 같은" 뻔한 인상을 주는 모든 관성적 선택
2. **컴포넌트는 Tailwind CSS로 직접 제작** (D-15). 기성 킷 미사용.
3. **결정 프로세스**: 화면별로 ①제안 시안/선택지 제시 → ②원장님 피드백 → ③확정 후 구현.
   확정 전 구현 착수 금지.
4. **이 문서는 살아있는 문서**: 협의 결과가 나올 때마다 `[협의 필요]` → `[확정]`으로 갱신.

## 1. 디자인 철학

### 1.1 핵심 가치 (방향 합의됨, 세부는 협의)

| 가치 | 설명 | 구현 방법 |
|------|------|----------|
| 도구다움 | 감상하는 화면이 아니라 매일 쓰는 작업대 | 장식 최소화, 핵심 동선(검수→인쇄) 최단 클릭 |
| 차분한 신뢰감 | 토스처럼 정돈된, 요란하지 않은 인상 | 절제된 색 사용, 넉넉한 여백, 명확한 위계 |
| 손맛 있는 완성도 | 공장식 틀이 아닌, 이 서비스만의 디테일 | 직접 만든 컴포넌트, 원장님과 다듬은 세부 |

### 1.2 참고 서비스 (무드보드) `[협의 필요]`

| 서비스 | 참고할 점 (제안) | 참고하지 않을 점 |
|--------|----------|-----------------|
| 토스 | 정돈된 위계, 절제된 컬러, 명확한 다음 행동 | 모바일 중심 패턴 (우리는 PC 웹) |
| (원장님 추가 예정) | — | — |

> 원장님이 평소 "이건 보기 좋다"고 느낀 서비스/인쇄물을 공유해 주시면 무드보드에 반영합니다.

## 2. 컬러 팔레트 `[협의 필요 — 아래는 출발점 제안]`

### 2.1 역할 기반 컬러 (제안 초안)

> 제안 근거: 차분한 신뢰감(1.1) + 흰 종이(시험지)와 잘 어울리는 잉크 계열.
> **Hex 값은 전부 협의 대상입니다.** 시안 화면에서 실제로 보고 결정합니다.

| 역할 | 제안 방향 | 사용처 | 상태 |
|------|------|--------|------|
| **Primary** | 차분한 잉크 블루 계열 (채도 낮게) | 주요 버튼, 강조 | [협의 필요] |
| **Surface** | 종이에 가까운 웜 화이트 | 카드, 패널 | [협의 필요] |
| **Background** | 아주 옅은 회색 | 전체 배경 | [협의 필요] |
| **Text Primary** | 순검정이 아닌 잉크 블랙 | 주요 텍스트 | [협의 필요] |
| **Text Secondary** | 중간 회색 | 보조 텍스트 | [협의 필요] |

### 2.2 피드백 컬러 (관례적 기본값 제안)

| 상태 | 방향 | 사용처 | 상태 |
|------|------|-----|--------|
| **Success** | 초록 계열 | 출제 완료, 저장 확인 | [협의 필요] |
| **Warning** | 앰버 계열 | 문제 부족 안내 | [협의 필요] |
| **Error** | 빨강 계열 | 오류 | [협의 필요] |

### 2.3 다크 모드

- MVP에서는 라이트 모드만 지원 (인쇄 중심 도구 특성상 라이트 우선)
- 다크 모드는 v2에서 검토

## 3. 타이포그래피 `[협의 필요 — 아래는 출발점 제안]`

### 3.1 폰트 패밀리 (제안)

| 용도 | 제안 | 대안 | 상태 |
|------|------|------|------|
| 화면 본문 | Pretendard | system-ui, sans-serif | [협의 필요] |
| **시험지 인쇄** | 별도 결정 — 학생이 읽는 지면이므로 인쇄 가독성 기준으로 선택 | 명조 계열 vs 고딕 계열 실물 출력 비교 | [협의 필요·중요] |
| 수식 | KaTeX 기본 (Computer Modern 계열) | — | 사실상 확정 (수식 표준) |

> **시험지 폰트는 화면 폰트보다 중요한 결정입니다.** 실제 인쇄물을 놓고 비교해서 정합니다.

### 3.2 타입 스케일 (제안 초안)

| 이름 | 크기 | 굵기 | 용도 | 상태 |
|------|------|------|------|------|
| H1 | 24px | Bold | 페이지 제목 | [협의 필요] |
| H2 | 18px | SemiBold | 섹션 제목 | [협의 필요] |
| Body | 15px | Regular | 기본 본문 | [협의 필요] |
| Caption | 13px | Regular | 부가 정보 | [협의 필요] |

> 도구형 서비스라 과장된 Display 크기는 제안하지 않습니다. PC 웹 기준 밀도는 협의로 조정.

## 5. 기본 컴포넌트 `[협의 필요 — 시안 단계에서 확정]`

### 5.1 버튼 (Button)

| 상태 | Primary | Secondary | Ghost |
|------|---------|-----------|-------|
| 기본 | 채움 + 밝은 텍스트 | 테두리 + 컬러 텍스트 | 텍스트만 |
| 호버 | 약간 어둡게 | 배경 옅게 채움 | 밑줄 |
| 포커스 | 포커스 링 | 포커스 링 | 포커스 링 |
| 비활성 | 낮은 투명도 | 낮은 투명도 | 낮은 투명도 |
| 로딩 | 스피너 + 문구 유지 | 동일 | 동일 |

**문구 톤 (D-08 확정)**: 간결하고 사무적. "출제 완료", "인쇄하기", "진도 저장" — 느낌표·이모지 없음.

### 5.2 입력 필드 (Input)

| 상태 | 스타일 |
|------|--------|
| 기본 | 테두리 + 배경 |
| 포커스 | Primary 테두리 + 포커스 링 |
| 에러 | Error 테두리 + 간결한 에러 문구 |
| 비활성 | 회색 배경, 입력 불가 |

### 5.3 핵심 화면별 특수 컴포넌트 (이 서비스만의 것 — 함께 설계)

| 컴포넌트 | 화면 | 설계 포인트 | 상태 |
|----------|------|------------|------|
| 진도 트리 선택기 | S-07 | 학년>대단원>소단원 트리에서 1클릭 진행 (10초 입력 목표) | [협의 필요] |
| 문제 카드 (검수용) | S-05 | 수식 렌더링 + 난이도/유형 표시 + [교체] 버튼 위치 | [협의 필요] |
| 시험지 미리보기 | S-06 | A4 지면 그대로 보여주기 — 화면과 인쇄의 일치가 생명 | [협의 필요] |
| 시험지 지면 디자인 | 인쇄물 | 학원명/날짜/이름칸/문항 배치 — **가장 중요한 디자인 작업** | [협의 필요·최우선] |

> **시험지 지면이 이 서비스의 진짜 얼굴입니다.** 학생과 학부모가 매일 보는 결과물이므로,
> 화면 UI보다 먼저 원장님과 지면 디자인을 확정하는 것을 권장합니다.

## 6. 접근성 체크리스트

### 6.1 필수 (MVP)

- [ ] **색상 대비**: 텍스트와 배경의 대비율 4.5:1 이상
- [ ] **포커스 링**: 키보드 탐색 시 포커스 표시 명확
- [ ] **클릭 영역**: 버튼/링크 최소 44x44px
- [ ] **에러 표시**: 색상만으로 구분하지 않음 (텍스트 병행)
- [ ] **폰트 크기**: 화면 본문 최소 14px, 시험지는 인쇄 가독성 별도 검증

### 6.2 권장 (v2)

- [ ] 키보드 전체 탐색 가능
- [ ] 스크린 리더 호환 (ARIA 라벨)
