## 1. 한 줄 — 이 저장소가 여덟 번 겪은 결함

> **손상이 심할수록 그 손상을 「정상」으로 읽는 가드가 생긴다.**

손상 지표(짧다·안 닮았다·글자가 적다·값이 비었다)는 임계값을 **정상 쪽이 아니라
판정 불가 쪽**으로 민다. 그래서 한 방향 문턱을 놓으면 **가장 망가진 것이 가장 먼저
통과하거나, 가장 먼저 버려진다.**

같은 뿌리에서 나온 얼굴들:

| 얼굴 | 실제 사건 |
| --- | --- |
| 손상된 값을 「충실하다」는 증거로 읽음 | DB 본문이 길어서 통과 → 길었던 이유가 옆 문항 해설 오염 |
| 오염이 부풀린 길이를 가드에 씀 | 오염이 심할수록 교체가 막힘 (H7_그림단서손실) |
| 판정의 「참」을 제품 상수에서 가져옴 | 채점기가 제품 상수를 정답으로 삼아, **제품이 틀릴수록 점수가 올라감** |
| 세는 쪽과 쓰는 쪽이 다른 값을 봄 | 가드는 반올림 **전**, 지면은 반올림 **후** (2026-08-20) |
| 지표가 실패를 셀 수 없는 형태 | KaTeX 실패율 0.1% 인데 지면엔 `1over5x` 가 나감 |
| 목록을 손으로 써서 양쪽이 눈이 멈 | `le`·`ge` 가 세는 쪽·고치는 쪽 **양쪽 다** 없었음 |
| 빈 값을 결함으로 단정 | `originProblemId` NULL 이 결함이 아니라 **판별자**였음 |
| 없는 클래스가 조용히 무시됨 | `text-red-text` 가 아예 없어 경고 색이 **한 번도 안 나옴** (2026-08-20) |

**공통 처방은 하나다 — 문턱을 옮기지 말고 «본문과 독립인 근거»를 하나 더 요구하라.**

## 2. 판정 코드를 쓰기 전 점검표

한 항목이라도 「모르겠다」면 **코드를 쓰기 전에** 그것부터 확인한다.

1. **이 지표는 실패를 셀 수 있는 형태인가?**
   실패가 침묵하는 경로에서는 성공률이 0을 향해도 아무것도 증명하지 못한다.
   → 「무엇이 잔재인지 미리 정하지 않는 발견기」를 하나 더 둔다(`census-*`).

2. **판정의 「참」이 어디서 오는가?**
   고치려는 그 데이터에서 오면 안 된다. 제품 **상수**에서 와도 안 된다
   (제품 **함수**를 부르는 것은 좋다 — 규칙을 옮겨 적는 것을 막는다).
   실측값에서 오게 하고, 상수가 그와 다르면 **멈춘다.**

3. **세는 쪽과 쓰는 쪽이 같은 값을 보는가?**
   반올림·정규화·전처리가 한쪽에만 있으면 보장이 거짓이 된다.
   같은 규칙을 쓰는 자리가 둘이면 **한 숫자를 두 곳이 쓰게** 하고,
   「한쪽만 옮기면 빨개지는」 테스트를 같이 둔다.

4. **어휘·목록을 손으로 썼는가?**
   손으로 쓴 목록은 세는 쪽과 고치는 쪽을 **같이** 눈멀게 한다.
   정본에서 프로그램으로 뽑고(`build-hwp-vocab.py` 꼴), 파일 하나를 양쪽이 읽는다.

5. **임계값을 물려받았다면 분모가 같은가?**
   같은 숫자가 다른 것을 가리킨다. 1차에서 「편의 대부분」이던 후보가
   2차에서 「편의 일부」가 되자 겹침률 0.3 이 전부 거짓이 됐다.

6. **반대쪽 모집단에 대 봤는가?**
   「그림이 **붙어 있는** 행에 같은 규칙을 대면 «불필요»가 나오면 안 된다」처럼
   **반증 가능한 형태**로 물어야 한다. 표본이 아니라 **전량**이어야 상한이 묶인다.

7. **가드를 망가뜨려 봤는가?**
   상수를 하나씩 변이시켜 테스트가 **빨개지는지** 확인한다.
   실제로 29개 중 9개가 초록이었다(=장식). `mutate-*.sh` 규약을 따른다.

8. **가드가 헛짚지는 않는가?**
   오탐은 탐지 실패보다 나쁠 수 있다 — 사람이 규칙을 꺼 버리면 진짜 결함이 나간다.
   **진짜 위반과 멀쩡한 것을 «같은 파일»에 놓고 하나만 잡히는지** 본다.
   실제로 어포던스 검사기가 상수 이름 `base` 를 클래스 `text-base` 안에서 찾아
   애먼 `<h1>` 을 잡고 있었다(2026-08-20).

9. **파괴적 작업이면 «무엇을 잃는가»를 셌는가?** (D-20)
   건수만 보면 그럴듯하다. 43건이 433건이 된 것은 **손실 분포**로만 드러났다.
   분모를 먼저 찍고, 「처리 + 건너뜀」이 안 맞으면 **멈춘다.**

## 6. 사람이 눈으로 볼 때 — 요령

육안 검수는 **비싸므로 설계해야 한다.** 이 주에 실제로 통한 것:

1. **묶어서 본다.** 한 짝씩 1,576번 보면 뒤로 갈수록 대충 본다.
   한 장에 **6짝**이 한계였다(12짝에서는 축 이름 잘림 같은 미묘한 것이 안 보였다).
2. **묶기 전에 시험한다.** 이미 결함으로 확정한 것을 깨끗한 것들 사이에 섞어
   그 크기에서도 보이는지 먼저 확인한다. 안 보이면 묶음을 줄인다.
3. **의심도 내림차순으로 늘어놓는다.** 중간에 멈춰도 **남은 쪽이 가장 안전한 쪽**이 된다.
   선별기는 **순서만** 정하고 **판정하지 않는다**(수치에 세 번 속았다).
   의심도는 반드시 **양방향**으로 — `|ln(비율)|` 처럼. 한 방향이면 손상이 하위로 묻힌다.
4. **둘을 같은 크기로 맞춰 놓는다.** 크기가 다르면 「내용이 같은가」를 못 견준다.
5. **규칙을 고쳤으면 고치기 전에 본 표본부터 다시 본다.** 새 표본만 보면 회귀가 안 보인다.
6. **그림이 실제로 실렸는지 코드로 확인한다.** `about:blank` 에서는 크롬이 `file://`
   하위 자원을 막아 **빈 그림이 나오는데 스크린숏은 멀쩡히 찍힌다.**
   실제로 여섯 장이 전부 같은 6,311바이트로 나왔다 — 그대로 뒀으면
   「1,461장 전부 깨끗」이라는 보고가 나갔다. data: URI 로 박고 `naturalWidth>0` 을 센다.

- **같은 모델을 두 번 돌려도 재현율은 안 오른다.** 놓치는 것은 우연이 아니라 그 모델의
  성질이다. 재현율을 올리려면 **다른 모델**을 대야 한다.
- **「A 가 지목한 것을 B 에게 다시 묻기」도 눈금이 필요하다.** 확대한 그림을 붙여
  codex 에게 「이 주장이 참인가」를 물었더니 **참인 주장 2건까지 전부 «거짓»** 이라
  답했다. 답이 진실에 따라 안 변하니 아무것도 재지 못한다.
  **검증기에는 «참인 주장»을 반드시 섞어 넣어라** — 안 섞으면 「전부 거짓 → 깨끗하다」로
  읽고 지나간다.
- 시트 한 장에 codex 는 약 10,000 토큰을 쓴다. 5,000 언저리면 대충 본 것이니
  **토큰 수를 로그에 남기고 견주어라**(원문에 `tokens used` 로 찍힌다).

## 7. 배치·적용 규약

- **공유 DB(D-31)**: 기본 차단. `ALLOW_SHARED_IMPORT=1` + `--apply` 둘 다 있어야 연다.
  **`--revert --apply` 도 같은 관문을 통과해야 한다**(관문이 revert 분기보다 앞에).
- **되돌리기 원장을 DB 보다 먼저 쓴다.** 그리고 **커밋되는지 반드시 확인한다** —
  `scripts/qa/reports/` 는 디렉터리째 무시되므로 `.gitignore` 에 `!` 줄을 넣고
  `git check-ignore -v <파일>` 로 확인한다(종료 1 이면 커밋된다).
- **되돌릴 때는 지금 값이 «자기가 쓴 값일 때만» 되돌린다.** 같은 컬럼을 두 스크립트가
  잠그면 한쪽 되돌리기가 다른 쪽을 푼다.
- **재개 가능한 배치**: 실패 표시에 **시도 횟수**를 적고 3회 실패해야 포기한다.
  성공하면 표시를 지운다. 최종 집계에 「N회 실패로 포기 M」을 **따로 찍는다** —
  4초 창에 1,065편이 실패 표시를 받고 재시도에서 **전부 성공**한 일이 있다.
- **게이트는 통과 수가 아니라 분모를 지킨다.** 워커가 죽으면 그 파일은 결과에서
  그냥 빠지고 「118 passed」만 남는다. `scripts/qa/run-tests.mjs` 가
  「돌 예정 == 결과 있음」을 이름으로 견준다.
- **다중 세션(오르카)**: 커밋하지 않은 실험은 안전하지 않다. 남의 `git add -A` 에
  쓸려 들어간다. **만들자마자 커밋**하고, 경로로만 스테이징한다.
  되돌릴 때는 `git checkout HEAD -- <파일>` 처럼 **기준을 명시**한다.
- **배치 전에 원장님 화면을 뺏지 않는지 확인한다**(절대 규칙 9). 한컴 COM 은
  백그라운드가 아니다.

## 8. 「환경 문제」·「플래키」라고 적기 전에

그건 원인이 아니라 **원인을 못 찾았다는 말의 다른 표현**이다.
두 환경의 차이를 하나씩 지워 최소 재현 조건을 찾는다(`probe-*`).

실제 사례: 「이 워크트리에서만 테스트가 죽는다」로 덮었는데, 원인은
**Node v24 의 `fs.rmSync` 가 경로에 비ASCII(한글)가 있으면 프로세스를 죽이는 것**이었다.
워크트리 이름이 한글이었다. 재현기 하나면 끝날 일이었다.
→ 그래서 이 저장소는 **`fs.rmSync` 를 전면 금지**한다(`noRmSync.test.ts`).
