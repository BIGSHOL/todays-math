## A. 배점 추출 결손 — "~56편"의 실체가 바뀌었다

### A.0 새 실측 — 문제의 절반은 PDF 없이 고칠 수 있다

§15.4 는 "본문에 `[합 N점]` 표기가 남은 편은 4편뿐"이라 적었는데, **그 조사는 배점이
빈 문항만 봤다.** 배점이 *잘못 읽힌*(하위 소문항 배점을 집은) 문항까지 넓혀 다시 재니:

```
전 문항 42,856 중 본문에 [합/총 N점] 표기가 남은 문항: 87 (63편)
  그중 기록 배점 < 표기 배점(하위 배점 오집): 53문항
```

이유는 추출기 코드에 있다. `textlayer.py:39` 의 배점 정규식이

```python
_SCORE = re.compile(r"\[\s*(?:총\s*)?(\d+(?:\.\d+)?)\s*점[^\]]*\]")
```

`총` 은 알지만 **`합` 을 모른다.** 그래서 `[합 10점]` 은 (1) 배점으로 안 잡히고
(2) `_drop_marks` 도 같은 정규식을 쓰므로 **본문에서 지워지지도 않는다** — 표기가
JSON 에 통째로 살아남는다. 대신 첫 소문항의 `[2점]` 이 배점으로 잡힌다.
범물중 "추출 78점 / 원본 100점"이 정확히 이 경로다.

### A.1 층위 1 — JSON 보수 (즉시 가능, 원본 무수정)

`loadCorpus` 정정 규칙: 문항 본문에 `[합/총 N점]` 이 있고 **기록 배점 < N** 이면 N 으로
정정한다. "읽힌 값을 덮지 않는다"(fillScore 원칙)의 예외지만, 표기가 같은 문항 안에
있으면 기록 배점이 하위 소문항 것이라는 **증거**가 있으므로 정당하다.

- 대상 63편(가드 제외 190편과의 겹침은 구현 시 재측정)
- 🔴 채택 전 **대조군 검증 필수**: 가드 통과편에 같은 규칙을 걸어 과대추정 0 확인
  (adv4 가 PDF 추정기에 쓴 검증법 그대로)
- 위치는 `fillScore.ts` 확장이 맞다 — backtest·tune·실전이 같은 함수를 타야 한다

### A.2 층위 2 — 추출기 수정 (앞으로의 추출 ~750편+)

고칠 것은 사실상 **정규식 한 글자**다: `(?:총\s*)?` → `(?:[총합]\s*)?`.
`_SCORE.search` 가 첫 표기를 집으므로, `합` 을 알면 머리표(`[합 10점]`)가 소문항
(`[2점]`)보다 앞서 잡혀 오집도 함께 사라진다.

## B. 예측 문제지 구분 — FK 하나가 결함 셋을 닫는다

| 안 | 내용 | 검토 |
|---|---|---|
| ① enum 추가 | `TestType` 에 `predicted` | 의미상 정직하나 **파급이 넓다** — testType 을 분기하는 모든 자리(인쇄 라벨, 대시보드 D-33, 계약 `testTypeSchema`, E2E)가 세 값을 알아야 한다 |
| ② FK 컬럼 | `Test.predictionRunId String? @db.Uuid` | **추가 전용.** non-null = 예측 문제지. 게다가 시험지가 자기 회차를 안다 |
| ③ 현행 유지 | 배점 유무 신호 | 작동은 하나 간접적. 이론상 구분 실패 경로가 남는다 |

**권고: ② 를 먼저.** 이 한 컬럼이 열리는 것:

1. **구분** — `배점_대상아님` 가드가 배점 유무 대신 FK 로 정직하게 판정

## C. backtest 지표 정합 — 표는 이미 틀렸다고 판명됐다

adv4 확인: §12.4 의 "단원·난이도는 cohort-only 가 낫다"는 **표본 불일치 아티팩트**다.
cohort-only 가 못 푸는 44편(거리 1.0 급)이 engine 평균에만 얹혀 있었다. 같은 편으로
짝지으면 단원도 engine 이 유의하게 낫고(95% CI 전체 음수), 난이도는 두 모델이
1299/1299편 **같은 값**이다(엔진이 난이도를 코호트에서 그대로 가져오므로).

할 일 (전부 소규모, 한 커밋 묶음):

1. `backtest.ts` — 모델 비교 표를 **공통 표본**으로 낸다. engine 절대 성능은
   전체 표본 줄을 따로 유지(둘 다 보여야 한다 — 비교용과 실전 성능용은 다른 질문이다)
2. 난이도 열 — engine ≡ cohort-only 임을 출력에 명시(또는 열 병합).
   §12.5 가 `engine-sameRound` 를 걷어낸 것과 같은 논리를 자기 표에도 적용하는 것
3. `tune.ts` — 단원 지표에 `hasObservedUnits` 필터 부재(backtest 와 0.579 vs 0.762 로
   다른 숫자를 냄). 같은 summarize 규칙으로 정렬
4. `11 §12.4` 본문 정정 — 지금 문서가 틀린 주장을 담고 있다

### D.1 먼저 (첫 실측 전에) — 전부 소규모

| 결함 | 해법 권고 |
|---|---|
| 🔴 한 학교 20건이 전역 오프셋 독점 → 표본 0건인 학교 예측이 8점 이동 | `MIN_CALIBRATION_SCHOOLS = 3` 하한 신설 — 학교가 3곳 미만이면 전역 오프셋을 "판단 불가"로. 학교 1곳의 편향은 엔진 편향과 **구분 불가능**하다는 것이 근거 |
| 🔴 engineVersion 수동 문자열 — 파라미터를 바꿔도 안 올라감 | **스냅샷 테스트**: `DEFAULT_PARAMS` 값 전체와 `PREDICTOR_ENGINE_VERSION` 을 한 스냅샷에 잠근다. 파라미터가 바뀌면 테스트가 깨지며 "버전을 올려라"라고 말한다. 해시 접미(`0.6.0+p3f2a`)보다 단순하고, 사람이 의미 있는 버전을 유지한다. 요청별 `params` 오버라이드는 보정 표본에서 **기본값과 다른 run 을 제외**하는 필터로 처리 |
| 🟡 schoolMean 만 재전송하면 stdev 가 조용히 삭제 | 계약이 이미 optional/nullable 을 가른다 — 서비스가 `undefined`(미전송) → **미변경**, `null`(명시) → 삭제로 처리하게 수정 |
